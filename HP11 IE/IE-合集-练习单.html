翻译: 看这段文字 (「Oettingenstraße 67 是一栋大学楼, 图书馆则在 Schellingstraße 3、Ludwigstraße 25 (Philologicum) 和 Veterinärstraße 13.」). 怎样从中抽出所有地址? 补全函数 extract_addresses.

思路: 这是 IE 04 Slide 43 的「正则表达式」方法: 找出这几个地址共同的形式结构. 四个都是「一个大写字母开头、以 straße 结尾的词 + 空格 + 门牌号」. 写成正则, 用 re.findall 返回所有匹配. 注意德语字母 ä ö ü ß 不在 [a-z] 里.

答案 (先自己做再看) 
import re

def extract_addresses(text):
    return re.findall(r"\b[A-ZÄÖÜ][a-zäöüß]*straße \d+\b", text)

实际运行输出:

['Oettingenstraße 67', 'Schellingstraße 3', 'Ludwigstraße 25', 'Veterinärstraße 13']

模式拆开读: \b 词边界; [A-ZÄÖÜ] 一个大写字母; [a-zäöüß]* 任意个小写字母 (含变音字母); straße 固定后缀; 一个空格; \d+ 门牌号. 「Veterinär」里的 ä 就是为什么字符集要加上变音字母: 只写 [a-z]* 会漏掉 Veterinärstraße 13.

思路: 不看文字内容, 看排版结构: 维基百科里, 词条名和别名用 <b> 加粗, 指向其他词条的概念和实体用 <a> 链接. 所以「在 b 或 a 标签里的文字」就是实体候选. 这是 IE 03 讲的利用半结构化数据源的思路.

答案 (先自己做再看) 
def extract_text_from_html(html_text):
    return re.findall(r"<(?:b|a)\b[^>]*>(.*?)</(?:b|a)>", html_text)

实际运行输出:

['Ludwig-Maximilians-Universität München', 'LMU Munich', 'University of Munich', 'public', 'research university', 'Munich', 'University of Ingolstadt', 'Ludwig IX of Bavaria-Landshut', 'sixth-oldest university']

[^>]* 跳过标签里的属性 (href), (.*?) 非贪婪地取到最近的结束标签. 结果里真正的命名实体有 6 个 (三个大学名、Munich、University of Ingolstadt、Ludwig IX), 但 public、research university、sixth-oldest university 也被链接了, 它们是普通概念, 不是命名实体; 而没有链接的 Bavaria、Germany 却被漏掉了. 结构信号很有用, 但既不完全精确也不完全召回.

易错: 用正则解析 HTML 只适合这种简单、规整的片段; 真实网页 (标签嵌套、换行、属性里有 >) 应该用 HTML 解析器 (如 BeautifulSoup).

思路: 这就是 IE 04 Slide 48–50 里「整体实体识别」到「边界 / 逐词标注」的转换. 关键: 每个实体 Span 都有 .start 和 .end, 是它在 doc 里的词元下标 (end 不包含), 不用自己数词. 打印用 zip(doc, labels) 配对.

答案 (先自己做再看) 
labels = ["OTHER" for _ in range(len(doc))]
for ent in doc.ents:
    for i in range(ent.start, ent.end):
        labels[i] = ent.label_

print(list(doc))
print(labels)

for token, label in list(zip(doc, labels))[:25]:
    print(token.text, label)

    orgs = [e.text for e in nlp(ev).ents if e.label_ == "ORG"]
    print((year, ev), orgs)
    if orgs:

用 Transformer 做命名实体识别
Named Entity Recognition with Transformers

Exercise 1 · Task 9

A transformer (think GPT, BERT, Qwen, etc.) creates a contextual embedding for each input token. We can use these to predict named entities.

We are not getting into the details of the transformer architecture, but remember:

  • This only works with encoder-only transformers (BERT, not GPT)
  • You should specifically train (= fine-tune) a transformer on named entity recognition

A nice way of using pre-trained transformers without getting too technical, is the pipeline interface. Here, we will load "dslim/bert-base-NER" (https://huggingface.co/dslim/bert-base-NER).

from transformers import pipeline

pipe = pipeline(
    "ner", # set the task to Named Entity Recognition
    model="dslim/bert-base-NER", # loads a NER model from huggingface
    aggregation_strategy="none" # return a prediction for each token
)

print(pipe("The Statue of Liberty is a monument in New York."))

How do we get a list of named entities from that?

named_entities = []

for ent in pipe("The Statue of Liberty is a monument in New York."):
    pass # TODO

翻译: Transformer (如 GPT、BERT、Qwen) 为每个输入词元生成一个上下文向量, 可以用它来预测命名实体. 不讲架构细节, 只记住: 这只适用于只有编码器的 Transformer (BERT 可以, GPT 不行); Transformer 要专门在 NER 上训练 (微调). 不涉及太多技术细节的用法是 pipeline 接口, 这里加载在 NER 上微调过的模型 dslim/bert-base-NER. 运行后它对每个子词给出一个预测. 问题: 怎样从这个输出得到实体列表?

思路: 先看输出: 每一项有 entity (BIO 标签, 如 B-LOC、I-LOC)、word (WordPiece 子词, 以 ## 开头的表示接在前一个子词后面)、start / end (字符位置). 合并规则: ## 开头的接到上一个词上 (不加空格); I- 开头、而且紧接着上一个词的, 加空格接上; 其他 (B-) 开始一个新实体.

Statue 被切成了三个子词 St、##at、##ue. 合并代码:

named_entities = []
for ent in pipe("The Statue of Liberty is a monument in New York."):
    word, tag = ent["word"], ent["entity"]
    if word.startswith("##") and named_entities:
        named_entities[-1][0] += word[2:]                 # 子词: 直接接上
    elif tag.startswith("I-") and named_entities and named_entities[-1][2] == ent["start"] - 1:
        named_entities[-1][0] += " " + word               # 同一实体的下一个词
    else:
        named_entities.append([word, tag[2:], ent["start"]])   # 新实体
    named_entities[-1][2] = ent["end"]                    # 记住当前实体的结尾位置
named_entities = [(w, t) for w, t, _ in named_entities]

print(named_entities)

第三个元素记录实体当前的结束位置, 用来判断下一个词是不是紧挨着 (中间只隔一个空格). Liberty 被标成 I-ORG (分数只有 0.54, 模型拿不准), 但它是 I- 而且紧接在 of 后面, 所以并进了 Statue of Liberty, 类型沿用实体开头的 LOC.

「只适用于编码器模型」说得太绝对: GPT 类的解码器模型同样能做 NER, 一种是加上逐词分类层微调 (效果一般不如双向的 BERT, 因为它看不到右边的上下文), 另一种是直接用提示词让大模型输出实体列表 (IE 04 Slide 82 的混合系统). 题目的意思是: 用 pipeline("ner") 这种逐词分类的方式, 通常选 BERT 这样的双向编码器.

翻译: 从这些评论里抽出评分和产品 (产品当作 organizations, 即 ORG 实体), 输出每个产品的平均评分.

思路: 又是规则 + 模型的组合: 评分的位置和格式完全固定 (句首「数字 Stars:」), 用正则; 产品名用 spaCy 找 ORG. defaultdict(list) 让每个新产品自动从空列表开始, 直接 append.

答案 (先自己做再看) 
for text in reviews:
    stars = int(re.match(r"(\d) Stars", text).group(1))
    for e in nlp(text).ents:
        if e.label_ == "ORG":
            product_to_stars[e.text].append(stars)

实际运行输出:

Sony 4.5

每条评论的实体 (调试时打印出来看): 第一条 [('5', 'CARDINAL'), ('iPhone', 'ORG')], 其余同理, 句首的数字被标成 CARDINAL (基数词), 不是 ORG, 所以不会混进产品. iPhone: (5 + 2) / 2 = 3.5; Sony: (4 + 5) / 2 = 4.5.

易错: 用 re.match 而不是 re.search: 评分一定在句首, match 只在开头匹配, 不会误抓句子中间的数字. 把 iPhone 当 ORG 只是这个小模型碰巧这样标 (iPhone 其实是产品, OntoNotes 里有 PRODUCT 类); 换模型可能标成 PRODUCT, 那就要同时收 ORG 和 PRODUCT.

原题说法不准确:「products (= organizations)」把产品等同于机构. iPhone 是产品, Sony 是公司 (这里指 Sony 的相机); spaCy 的标签集里本来就有 PRODUCT. 这道题能做, 只因为 en_core_web_sm 恰好把这两个都标成了 ORG.
