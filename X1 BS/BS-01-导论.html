什么是操作系统: 两项任务
Was ist ein Betriebssystem?

Folie 2

Betriebssystem (engl.: Operating System, OS)
Eine Sammlung von Software, die die Hardwareressourcen eines Rechensystems verwaltet und auf geeignete Weise für die Anwendungen verfügbar macht

Betriebssystem 操作系统 (英语 Operating System, OS): 一组软件, 它管理计算机系统的硬件资源, 并以合适的方式把这些资源提供给应用程序使用.

图里的分层就是这句定义的画面: 用户只和应用程序打交道, 应用程序不直接碰硬件, 而是通过下面的操作系统. 定义里的两个关键词正好对应后面两页的两项任务: 「合适的方式」= 抽象, 「管理」= 资源管理.

Folie 3

1. Aufgabe: Abstraktion

  • Standardisiertes Interface für Ressourcen
    • CPU, Speicher, Festplatte, etc.
  • Vorteile
    • Wiederverwendung gleichartiger Funktionalität
    • Gleiches Interface für unterschiedliche Hardware
    • Zusätzliche Funktionen, höhere Abstraktion
  • Herausforderungen
    • Was sind die richtigen Abstraktionen?
    • Wie viele Hardwaredetails müssen sichtbar sein?

(插图: 处理器 → Prozesse / Threads, 内存条 → Adressraum, 硬盘 → Dateien, 各用一个绿色箭头连接.)

第一项任务是 Abstraktion 抽象: 给资源 (CPU、内存、硬盘等) 提供标准化的接口. 好处: 同类功能可以复用 (每个程序不必自己写磁盘驱动); 不同的硬件用同一个接口; 还能提供额外的功能和更高层的抽象. 难点: 什么才是正确的抽象? 硬件的细节要暴露多少?

插图里的三个箭头就是本课最重要的三个抽象: CPU 被抽象成 Prozess 进程 / Thread 线程, 内存被抽象成 Adressraum 地址空间, 硬盘被抽象成 Datei 文件. 例如程序打开一个文件时, 完全不用知道数据存在 SSD 还是 U 盘的哪个扇区.

Folie 4

2. Aufgabe: Ressourcenverwaltung

  • Das Betriebssystem verwaltet die Ressourcen und entscheidet über ihre Verwendung
  • Vorteile
    • Schutz von Anwendungen vor gegenseitigem Zugriff
    • Effiziente Nutzung von Ressourcen (Kosten, Zeit, Energie)
    • Faire Verteilung von Ressourcen
  • Herausforderungen
    • Welche Mechanismen sind geeignet?
    • Welche Richtlinien (engl.: Policies) sind die richtigen?

第二项任务是 Ressourcenverwaltung 资源管理: 操作系统管理资源, 并决定资源怎么用. 好处: 保护应用程序不被彼此访问 (一个程序不能读另一个程序的内存); 高效使用资源 (成本、时间、能耗); 公平分配资源. 难点: 什么机制合适? 什么策略 (Richtlinie, 英语 policy) 是对的?

机制和策略: 这对概念贯穿整门课. 机制回答「怎么做」(例如怎样从一个进程切换到另一个), 策略回答「做什么」(例如下一个该让哪个进程运行). 第 2 讲会正式讲这种分离.

Folie 12

Systemprogrammierung in C

  • Für die Entwicklung von UNIX entworfen
    • Systemnahe, imperative Programmiersprache
    • 1969 bis 1973 bei AT&T Bell Labs, von Dennis Ritchie
  • Vorteile gegenüber höheren Sprachen
    • Bessere und vorhersagbarere Performance
    • Zugriff auf systemnahe APIs, Hardware und CPU Features
  • Nachteile
    • Manuelle Speicherverwaltung (Abstürze, Schwachstellen)
    • Geringere Portabilität

(照片: Dennis Ritchie & Ken Thompson)

C 是为开发 UNIX 而设计的: 一门贴近系统的imperativ 命令式语言, 1969 至 1973 年由 Dennis Ritchie 在 AT&T 贝尔实验室开发. 相比高级语言的优点: 性能更好、更可预测; 能直接使用底层 API、硬件和 CPU 特性. 缺点: 要手动管理内存 (容易导致崩溃和安全漏洞); 可移植性较差.

Folie 13

Buildprozess

Buildprozess 构建过程: Quelltext 源代码 由编译器 (clang 或 gcc) 编译成 Assembly 汇编 (人能读的机器指令, 这里是 x86-64), 再由 Assembler 汇编器 翻译成 Binary 二进制, 也就是 CPU 真正执行的字节.

读图: 汇编和二进制是一一对应的. 第一条 push %rbp 是字节 55, mov %rsp,%rbp 是 48 89 e5, sub $0x10,%rsp 是 48 83 ec 10, 依此类推. lea 0xeae(%rip),%rdi 把字符串 "Hello World\n" 的地址放进第一个参数寄存器 %rdi, mov $0x0,%al 告诉可变参数函数 printf 没有浮点参数, 然后 call printf; xor %eax,%eax 把返回值置 0, 也就是 main 的 return 0.

幻灯片前后不一致: 汇编里的 mov %edi,-0x4(%rbp) 和 mov %rsi,-0x10(%rbp) 是把 main 的两个参数 argc (在 %edi) 和 argv (在 %rsi) 存到栈上, 说明这段汇编是从 int main(int argc, char **argv) 编译出来的, 不是左边写的 int main(). 我用 clang -target x86_64-linux-gnu -O0 分别编译两种写法核对过: int main() 没有 sub $0x10,%rsp 和这两条存储指令, 只有 8 条指令; 带 argc/argv 的版本和幻灯片完全一致.

Programmieren in C (Crashkurs)

  • Kompilieren mit clang (aus der LLVM Compiler Suite)

    • Ohne die Option -o binaerdatei heißt das Binary a.out
  • Programm starten

helloworld.c

C 速成: 在编辑器 (例如 VS Code) 里写好源码并保存; 用 clang (LLVM 编译器套件的一部分) 编译, 命令是 clang -o 可执行文件名 源文件, 不写 -o 时生成的文件叫 a.out; 在同一个目录里用 ./可执行文件名 运行.

为什么要写 ./: shell 只在 PATH 列出的目录里找命令, 当前目录通常不在其中, 所以要明确写出路径「当前目录下的 hello」.

Folie 15

Hello World

  • Verwendet Header Datei stdio.h
    • Standard I/O-Funktionen
    • Wie import in Java oder Haskell
  • Die Funktion main
    • Startpunkt des Programms, erforderlich für Executables
  • Die Funktion printf
    • Formatierte Ausgabe von verschiedenen Datentypen (ebenfalls in Python und Java)
    • Die einfachste Form verwendet nur eine Stringkonstante, allgemein ist der erste Parameter ein Format-String gefolgt von den auszugebenden Werten / Variablen
    • Definiert in stdio.h

Hello World 程序的三个部分: 头文件 stdio.h 提供标准输入输出函数, 作用类似 Java 或 Haskell 的 import; main 函数是程序的入口, 可执行程序必须有; printf 做格式化输出 (Python 和 Java 里也有同名的东西), 最简单的形式只传一个字符串常量, 一般形式是第一个参数为格式字符串, 后面跟要输出的值或变量. printf 声明在 stdio.h 里.

易错: 「像 import」只是类比. #include 是预处理器把头文件的文本原样复制进来, 头文件里通常只有函数的声明; 函数的实现在 C 标准库里, 链接时才接上.

Folie 16

Strukturierter Kontrollfluss

if, for, while, do-while, break, continue

for (int i = 0; i < 10; i++) {
   if (i % 2 == 0)
      continue;
   if (i == 7)
      break;
   printf("%d", i);
}

Was gibt dieses Programm aus?

结构化控制流: if、for、while、do-while、break、continue, 写法和 Java 相同. 问题是这个程序输出什么. 实际运行:

> ./loop
135

偶数 (0, 2, 4, 6) 碰到 continue, 直接进入下一轮, 不打印. 1、3、5 打印. 到 7 时 break 跳出整个循环, 7、9 都不打印. "%d" 后面没有换行, 所以三个数字连在一起: 135.

C 的基本类型: 整数有 char、short、int、long、long long, 每种都分 signed (有符号) 和 unsigned (无符号), 标准只规定大小关系 char ≤ short ≤ int ≤ long ≤ long long; 字符用 char; 浮点数有 float、double、long double; void 是表示「什么都没有」的类型 (例如没有返回值的函数).

表格是关键: C 标准只规定每种类型至少多少位 (第二列), 实际大小由平台决定. 最大的差别在 long: 64 位的 macOS/Linux 上是 64 位, 64 位 Windows 上只有 32 位. 所以要精确位数时, 应该用 <stdint.h> 里的 int32_t、uint64_t 等.

有符号整数写 signed int 或直接 int; 无符号整数写 unsigned int, 能表示更大的正数, 但没有负数 (32 位时范围是 0 到 4 294 967 295, 有符号是 −2 147 483 648 到 2 147 483 647).

Folie 18

Boolesche Ausdrücke

  • C kannte ursprünglich keinen eigenen Boolean Typ
  • Boolesche Ausdrücke (&&, ||, <, …) haben den Typ int
    • 0 für false
    • 1 für true
  • Bedingungen erwarten Ausdrücke eines Integer-Typs
    • Dabei wird 0 als false interpretiert
    • Alles andere als true (nicht nur 1)
int x;
if (x) entspricht if (x != 0)
if (!x) entspricht if (x == 0)
Achtung: if (x == 1) entspricht nicht if (x)!

C 原本没有专门的布尔类型. 布尔表达式 (&&、||、< 等) 的类型是 int: 假是 0, 真是 1. 条件判断接受任何整数表达式: 0 当作假, 其他任何值都当作真 (不只是 1). 所以 if (x) 等于 if (x != 0), if (!x) 等于 if (x == 0); 但 if (x == 1) 不等于 if (x): x = 5 时前者为假, 后者为真.

「原本」指的是: C99 加入了 _Bool, 包含 <stdbool.h> 后可以写 bool、true、false; C23 起它们直接成为关键字. 但比较运算的结果仍然是 int.

Folie 19

Boolean Beispiel

#include <stdio.h>
#include <stdlib.h>

int main(void) {
  int num;
  printf("Enter an integer (can be zero):\n");
  if (scanf("%d", &num) != 1) {
    printf("Could not parse a number!\n");
    exit(1);
  }

    if (num) {
      printf("That\'s not zero.\n");
    } else {
      printf("That\'s zero.\n");
    }
}

例子: 读入一个整数, 判断它是不是 0. scanf("%d", &num) 从标准输入读一个十进制整数存进 num (要传 num 的地址 &num, 见后面的指针), 返回成功读到的项数; 不等于 1 说明输入不是数字, 用 exit(1) 以错误码 1 结束 (exit 来自 stdlib.h). 然后 if (num) 正是上一页的规则: 非 0 即真. 字符串里的 \' 是转义的单引号, 在双引号字符串里直接写 ' 也可以.

实际运行, 分别输入 0、−3 和 abc:

> echo 0 | ./boolx
Enter an integer (can be zero):
That's zero.
> echo -3 | ./boolx
Enter an integer (can be zero):
That's not zero.
> echo abc | ./boolx; echo $?
Enter an integer (can be zero):
Could not parse a number!
1

−3 也是「真」. 最后一次 echo $? 显示退出码 1. 后半段代码缩进多了两格, 只是排版, 不影响结果.

Folie 20–21

Initialisierung von Variablen

  • Java erzwingt Initialisierung von lokalen Variablen, Felder von Objekten werden mit 0 initialisiert
public class Test {
    public static void main(String[] args) {
        int x;
        x = x + 1;
        System.out.println(x);
    }
}
> javac Test.java
Test.java:4: error: variable x might not
have been initialized
        x = x + 1;
            ^
1 error
  • In C können nicht initialisierte Variablen trotzdem gelesen werden, das Verhalten ist dann undefiniert!
  • Häufige Fehlerquelle, Verhalten wird systemabhängig
  • Daher: Variablen immer explizit initialisieren
#include <stdio.h>

int main() {
    int x;
    x = x + 1;
    printf("%d\n", x);
}
> clang -o test test.c
> ./test
2

变量初始化: Java 强制局部变量在使用前初始化 (对象的字段自动初始化为 0), 上面的 Java 程序根本编译不过. C 允许读取未初始化的变量, 但这时的行为是undefiniert 未定义的: 是常见的错误来源, 结果取决于系统. 结论: 变量一律显式初始化.

幻灯片上的运行结果是 2; 我在 M1 Mac 上用 clang 21 运行也恰好得到 2. 这个 2 没有任何保证: x 读到的是那块栈内存里碰巧残留的值 (这里是 1), 换编译器、换优化级别、换机器都可能不同. 默认编译时 clang 一声不吭; 加 -Wall 才会警告:

> clang -Wall -o test test.c
test.c:4:9: warning: variable 'x' is uninitialized when used here [-Wuninitialized]
    4 |     x = x + 1;
      |         ^

所以写 C 时养成习惯: 总是加 -Wall (最好再加 -Wextra).

function-declaration]
    otherFun();
    ^

void otherFun(void) {

函数声明: C 编译器从上往下读文件, 调用一个函数之前必须已经知道它的类型. otherFun 定义在 main 下面, 所以要在文件开头写一行Vorwärtsdeklaration 前向声明 void otherFun(void); (只有函数头, 以分号结尾), 告诉编译器「后面会有这样一个函数」. 参数列表写 (void) 表示「没有参数」.

右边的错误信息是去掉第一行声明时得到的: 第 8 行调用了一个还没声明的函数, C99 起不再允许「隐式声明」(旧 C 会默认它返回 int); 第 13 行的真正定义返回 void, 和隐式假定的 int 冲突, 所以又报一个「类型冲突」. 我把声明删掉后实际编译, 得到的正是这两个错误. 带着声明编译则没有任何错误, 程序以退出码 12 结束 (return 12).

易错: main 的返回值就是程序的退出码, 在 shell 里用 echo $? 能看到 12. 习惯上 0 表示成功, 这里返回 12 只是示例.

幻灯片前后不一致: 左边的代码有前向声明, 这样编译不会报错 (实测退出码 12, 无任何警告); 右边的两个错误是没有第一行声明时的结果. 错误信息里的行号也说明了这一点: 幻灯片的代码里, 调用在第 9 行、定义在第 14 行; 删掉第 1 行的声明后, 正好变成报错里的第 8 行和第 13 行. 幻灯片应该把「没有声明 → 报错」和「加上声明 → 正常」分开写.

指针与数组
Pointer · Arrays

Folie 23

Pointer

  • Ein Pointer ist eine Variable, die eine Referenz zu einer anderen Variablen oder Datenstruktur enthält
  • Die Entsprechung von Pointer in Java sind Referenzen
    • Auf Java Objekte wird immer über Referenzen/Pointer zugegriffen
  • In C sind Pointer explizit und entsprechen der Adresse im Speicher

Pointer 指针是一个变量, 里面存的是对另一个变量或数据结构的引用. Java 里对应的是引用: Java 对象总是通过引用 (也就是指针) 访问. 区别在于 C 的指针是显式的, 它的值就是内存地址, 可以打印、比较、做加减.

Folie 24

Pointer in C

  • Definition (Hier am Beispiel von Pointern auf int) 
    int *pointer1, *pointer2;
  • Zuweisung 
    int var;
pointer1 = &var; // Pointer auf var
  • Dereferenzierung 
    *pointer1 = 5; // weist var den Wert 5 zu

三个基本操作. 定义: int *p 声明一个指向 int 的指针. 赋值: &var 取 var 的地址, 存进指针. Dereferenzierung 解引用: *pointer1 = 5 通过指针写到它指向的地方, 也就是把 var 改成 5.

易错: * 在声明里和表达式里含义不同. 声明 int *p 里它表示「p 是指针」; 表达式 *p 里它是「取 p 指向的值」. 另外 int *pointer1, *pointer2; 每个变量前都要写 *: 写成 int *p1, p2; 的话, p2 只是普通的 int.

Folie 25

Beispiele

// Nur die lokale Kopie von x ändert sich
void inc(int x) {
    x = x + 1;
}

int main() {
    int n = 0;
    inc(n);
    printf("%d\n", n);
}
// Prints 0
// Der Pointer wird auf n dereferenziert
void inc(int *x) {
    *x = *x + 1;
}

int main() {
    int n = 0;
    inc(&n);
    printf("%d\n", n);
}
// Prints 1

C 的参数传递一律是按值传递. 左边: inc(n) 把 n 的值 0 复制给形参 x, 函数里改的只是这份局部副本, main 里的 n 仍是 0. 右边: inc(&n) 传的是 n 的地址 (地址本身也是按值复制的), 函数通过 *x 解引用, 改的就是 main 里的 n, 所以打印 1. 两个版本我都实际运行过, 输出分别是 0 和 1.

这也解释了前面 scanf("%d", &num) 为什么要写 &: scanf 需要把读到的值写回调用者的变量, 只能通过地址.

Folie 26

Arrays

  • Leichter Unterschied zu Java
int numbers[10];
// Elementtyp  Bezeichner  Länge
  • Deklariert und allokiert ein neues (lokales) Array mit unbestimmtem Inhalt
  • Für Arrays beliebiger Länge, die auch die aktuelle Funktion überdauern, muss mit malloc explizit Speicher allokiert werden (entspricht etwa Javas new)

数组和 Java 稍有不同: int numbers[10]; 依次是元素类型、名字、长度. 这一句同时声明并分配了一个新的局部数组, 内容是不确定的 (没有初始化成 0). 长度任意、并且要在当前函数结束后继续存在的数组, 必须用 malloc 显式分配内存 (大致相当于 Java 的 new); 用完还要自己 free, C 没有垃圾回收.

Folie 27

Arraylänge

  • Arraylänge ist in C zur Laufzeit unbekannt
    • Es wird außer den tatsächlichen Daten des Arrays keine weitere Information gespeichert
  • Länge eines Arrays wird nicht überprüft
    • In Java führt Zugriff außerhalb des Arrays zu ArrayIndexOutOfBoundsException
    • In C stürzt das Programm ab oder überschreibt oder liest andere Daten
    • Häufige Ursache von ausnutzbaren Pufferüberläufen (buffer overflows)!
    • Immer wieder Grund für schwerwiegende Schwachstellen: z.B. führte ein Buffer Overflow in libwebp zu Remote Code Execution in Google Chrome (CVE-2023-4863)

(插图: 一杯咖啡倒满后溢出杯子.)

C 的数组在运行时不知道自己的长度: 内存里只存数据本身, 没有别的信息. 访问时也不检查下标: Java 越界会抛 ArrayIndexOutOfBoundsException; C 里程序要么崩溃, 要么悄悄读写了别的数据. 这是可被利用的Pufferüberlauf 缓冲区溢出 (buffer overflow) 的常见原因, 一再导致严重漏洞: 例如图片库 libwebp 里的一个缓冲区溢出, 让攻击者能在 Google Chrome 里远程执行代码 (CVE-2023-4863, 2023 年 9 月).

易错: 正因为数组不带长度, C 函数接收数组时通常要另外传一个长度参数, 例如 void f(int *a, size_t n).

字符与字符串
Buchstaben und Zeichenketten · String Pointer

Folie 28

Buchstaben und Zeichenketten

  • Buchstaben haben den Typ char (kurz für Character)
    • char c = 'x'; char nl = '\n';
  • Kein gesonderter String-Typ
    • Strings sind null-terminierte Arrays von Zeichen des Typs char
    • Verbrauchen Länge + 1 Bytes
char name[] = "LMU";

Interpretiert als “erzeuge ein passendes lokales Array und kopiere die angegebene String-Konstante hinein”

0x4C0x4D0x550x00
'L''M''U''\0'

字符的类型是 char, 单引号写字符常量, '\n' 是换行. C 没有单独的字符串类型: 字符串就是以 0 结尾的 char 数组 (null-terminated), 所以占「长度 + 1」个字节. char name[] = "LMU"; 的意思是「建一个大小正好的局部数组, 把字符串常量复制进去」: 4 个字节 0x4C 0x4D 0x55 0x00, 也就是 'L' 'M' 'U' 和结尾的 '\0' (ASCII 码 0).

易错: sizeof(name) 是 4 (含结尾的 0), 而 strlen(name) 是 3. 字符串函数靠找那个 0 来判断字符串在哪里结束, 少了它就会一直读下去.

Folie 29

String Pointer

  • Strings werden meistens nur über einen Zeiger (Pointer) auf ihren ersten Buchstaben referenziert
    • char * : Typ von Pointern auf char
    • const char *: Typ von Pointern auf char, wobei der Speicherinhalt nicht verändert werden darf
const char *name = "LMU";

Interpretiert als „zeige auf den ersten Buchstaben“

0x4C0x4D0x550x00
'L''M''U''\0'

char * const : Typ von Pointern auf char, wobei der Pointer nicht verändert werden darf

字符串通常只通过一个指向它第一个字符的指针来引用. char * 是指向 char 的指针; const char * 也是指向 char 的指针, 但不允许通过它修改所指的内容. const char *name = "LMU"; 的意思是「指向第一个字母」: 字符串常量存在程序的只读数据区里, name 只保存它的地址, 不再复制.

和上一页对比: char name[] = "LMU" 是一个自己的数组 (可以改 name[0] = 'X'); const char *name = "LMU" 是指向常量的指针 (不能改内容, 但 name 可以改指向别的字符串).

const 的位置: const char *p (= char const *p): 内容不能改, 指针能改. char * const p: 指针本身不能改 (不能指向别处), 内容能改. 记法: const 修饰紧挨在它左边的东西, 左边没有东西时修饰右边.

结构体

Folie 30–32

C Structs

  • C ist nicht objektorientiert
    • Keine Klassen
    • Trotzdem werden Daten gruppiert
  • Beispiel: 2D-Punkte
    • Java: Klassen mit zwei Feldern x und y
    • C: struct mit zwei Feldern x und y
    • C structs haben keine Methoden
int main() {
    struct {
        int x;    // struct field
        int y;    // struct field
    } myPointA; // variable name
    …
    myPointA.x = 4;
    myPointA.y = 2;
}

Folie 31: "Tag" für diesen struct Typ (rot eingekreist: point)

int main() {
    struct point {
        int x;    // struct-Feld
        int y;    // struct-Feld
    } myPointA; // Variablenname
    …
    myPointA.x = 4;
    myPointA.y = 2;

    struct point myPointB; // struct-Typ wird
    myPointB.x = 4;        // über Tag verwendet
    myPointB.y = 2;
}

Folie 32

struct point {// Ein globaler struct Typ mit
       int x;   // Tag kann in der gesamten
       int y;   // Datei verwendet werden
}; // Nur Semikolon am Ende

int main() {
    struct point myPointB;
    myPointB.x = 4;
    myPointB.y = 2;
}

C 不是面向对象的语言, 没有类, 但仍然可以把数据组合在一起: struct 结构体. 二维点的例子: Java 写一个有 x、y 两个字段的类, C 写一个有 x、y 两个字段的 struct; C 的 struct 没有方法.

三页是同一个例子的三步. ① 匿名结构体: 直接定义一个变量 myPointA, 这个类型没有名字, 不能再定义第二个同类型的变量. ② 加一个 Tag 标签 point: 之后可以写 struct point myPointB; 再声明同类型的变量. 注意类型名是 struct point 两个词, 不是单独的 point. ③ 把 struct 定义放到所有函数外面, 成为全局的类型, 整个文件都能用; 定义末尾只有一个分号 (没有变量名).

易错: struct 定义末尾的 }; 不能漏分号, 这和 Java 的类定义不同.

Folie 33

Struct Memory Layout

  • Struct enthält zwei String Buffer (Char Arrays von Länge 20)
    • Strings liegen im Struct zusammenhängend im Speicher
struct student {
      char first_name[20];
      char last_name[20];
      unsigned long id;
};

结构体的内存布局: struct student 里有两个字符串缓冲区 (长度 20 的 char 数组) 和一个 id. 字段按声明顺序连续排在内存里, 字符串的字符就在结构体内部. 在 64 位 macOS/Linux 上, 整个结构体占 20 + 20 + 8 = 48 字节 (40 正好是 8 的倍数, id 前面不需要填充).

易错: 名字最多只能存 19 个字符, 第 20 个字节要留给结尾的 '\0'.

Folie 34

Alternativ: Struct mit String Pointern

  • Struct enthält zwei String Pointer (Adresse des ersten Buchstaben des Strings)
    • Die eigentlichen Strings sind außerhalb des Structs im Speicher, in ihren eigenen Speicherbereichen die getrennt verwaltet werden müssen
struct student_wp {
     char *pFirst_name;
     char *pLast_name;
     unsigned long id;
};

另一种写法: 结构体里只放两个字符串指针 (字符串第一个字母的地址). 真正的字符串在结构体外面, 在各自的内存区域里, 需要另外管理 (分配、释放). 这样结构体小了 (8 + 8 + 8 = 24 字节), 名字的长度也不受 20 的限制, 但多了管理负担: 复制结构体时只复制了指针, 两个结构体会共用同一个字符串.

Folie 35

Array von Structs

struct student student_array[100]; 是 100 个结构体紧挨着排成的数组, 每一行是一个完整的 student (两个 20 字节的名字加 id). 第 i 个元素从 i × 48 字节处开始, 所以 student_array[i] 能直接算出地址.

Folie 36

Zugriffe auf Structs

  • Auf Felder eines Structs wird zugegriffen wie auf Felder in Java Objekten
struct student john;
john.id = 123456;
strcpy(john.first_name, "John");
strcpy(john.last_name, "Smith");

Kopiert String-Konstante "Smith" in den String Buffer (Char Array) innerhalb des structs.

访问字段的写法和 Java 对象一样, 用点号. 字符串字段不能直接赋值 (john.first_name = "John" 编译不过, 数组不能被赋值), 要用 strcpy 把字符串常量复制进结构体内部的缓冲区. strcpy 声明在 <string.h> 里, 要包含这个头文件.

Folie 37

Pointer und Structs

  • Häufig wird auf Structs auch über einen Pointer zugegriffen 
    struct student *pStud;
  • Zugriff auf ein Feld im Struct durch einen Pointer: 
    (*pStud).id
  • Syntaktischer Zucker mit Pfeilnotation: 
    pStud->id

结构体也常通过指针访问. 通过指针取字段: 先解引用再取字段 (*pStud).id; 括号不能省, 因为 . 的优先级比 * 高, *pStud.id 会被理解成 *(pStud.id). 这种写法太常用, 所以有syntaktischer Zucker 语法糖: 箭头 pStud->id, 意思完全相同.

Folie 38

Typabkürzung mit Typedef

  • Arbeiten mit Struct Typen erfordert viel Schreibarbeit
    • struct student john;
  • Ebenso bei anderen Typen
    • Pointer auf Pointer, etc.
  • typedef ermöglicht Typabkürzungen in C (wie type in Haskell)
typedef unsigned long size_t;
//      Type          Name

每次都写 struct student 很啰嗦, 其他复杂类型 (指向指针的指针等) 也一样. typedef 给类型起一个简称, 类似 Haskell 的 type: typedef 原类型 新名字;. 例子里给 unsigned long 起名 size_t.

易错: typedef 只是起别名, 不产生新类型, size_t 和 unsigned long 可以随意混用.

例子里的 size_t 是标准库真实存在的类型 (表示大小和长度, strlen、sizeof 的结果都是它), 由各平台的头文件定义, 自己的程序里不要再 typedef 一次. 在 64 位 macOS/Linux 上它确实是 unsigned long; 在 64 位 Windows 上 long 只有 32 位 (见 Folie 17 的表), 那里 size_t 是 unsigned long long.

Folie 39

Typedef für Structs

typedef struct student {
   char first_name[20];
   char last_name[20];
   unsigned long id;
} student_t;

int main() {
   struct student john;
   student_t john;
   student_t *pStud;
  • Für typedef lässt sich auch ein anonymes struct verwenden
    • typedef kann allerdings nicht rekursiv verwendet werden! Verkettete Listen brauchen getaggtes struct
  • Die Typabkürzung reicht für den späteren Zugriff

(Auf der Folie sind der Tag student rot durchgestrichen und die Zeile struct student john; durchgestrichen.)

结构体最常和 typedef 一起用: typedef struct { … } student_t; 定义了类型简称 student_t, 之后直接写 student_t john;. 幻灯片把标签 student 划掉, 意思是: 有了 typedef, 标签可以省掉, 用匿名结构体也行; 但这时 struct student john; 就不能再用了 (也被划掉), 只能用简称.

为什么链表需要标签: typedef 不能递归使用. 链表节点要包含「指向同类节点的指针」, 而在结构体内部, typedef 的名字还没定义完, 只能用标签:

typedef struct node {
    int value;
    struct node *next;   /* student_t-style name not yet available here */
} node_t;

(上面这段我编译过, 没有错误.) 名字后缀 _t 是常见的约定, 表示「这是一个类型」.

Folie 41

Grundlegende Funktionen

  • Put string: puts – Gibt einen String aus und fügt eine neue Zeile an
    • puts("Hello");
  • Print formatted: printf – Gibt einen String und andere Variablen aus
    • Format: %d: Dezimalzahl, %f: Gleitkommazahl, %s String, uvm.
    • printf("The number of %s is %d\n", name, s);
  • Scan formatted: scanf
    • Format wie printf, aber liest von Standardeingabe und speichert in übergebenen Variablen
    • scanf("%d", &num);
    • Gibt die Anzahl der erfolgreich gelesenen Elemente zurück

三个基本输入输出函数. puts: 输出一个字符串, 并自动加换行. printf: 格式化输出, %d 十进制整数, %f 浮点数, %s 字符串, 还有很多; 例子里 %s 被 name 替换, %d 被 s 替换, 顺序一一对应. scanf: 格式写法和 printf 一样, 但从标准输入读, 存进传入的变量 (所以传地址), 返回成功读到的项数 (Folie 19 用的就是这个返回值).

易错: 格式和参数类型必须匹配. 用 %d 打印 long 或 double 是未定义行为, long 要写 %ld, size_t 要写 %zu.

Folie 42

Stringfunktionen

int strcmp(s1, s2)Gibt Wert >0, =0, oder <0 zurück entsprechend lexikographischer Ordnung
size_t strlen(s)Gibt Länge von s zurück
char *strcpy(s1,s2)Kopiert s2 nach s1, inklusive \0; gibt s1 zurück
char *strcat(s1,s2)Konkateniert s2 an s1; gibt s1 zurück
  • Strings wachsen nicht automatisch, Puffer müssen groß genug gewählt werden
  • Keine dieser Funktionen prüft die Länge

四个字符串函数 (都在 <string.h> 里). strcmp 按字典序比较: s1 在前返回负数, 相等返回 0, s1 在后返回正数. strlen 返回长度 (不含结尾的 '\0'). strcpy(s1, s2) 把 s2 连同 '\0' 复制到 s1, 返回 s1. strcat(s1, s2) 把 s2 接到 s1 后面, 返回 s1. 字符串不会自动变长, 缓冲区必须预先开得够大; 这些函数都不检查长度, 目标缓冲区太小就是 Folie 27 说的缓冲区溢出.

易错: 判断两个字符串相等要写 strcmp(a, b) == 0. 写 a == b 比较的是两个指针 (地址), 内容相同也可能为假.

Teil 1: Virtualisierung

  • Die Anwendung muss sich nicht um die Details der Hardware kümmern
  • Beispiel: Virtualisierung von CPU und Speicher

第 1 部分 虚拟化: 让每个应用程序产生一种错觉, 好像所有资源都归它一个人用; 应用程序不用关心硬件细节. 例子: CPU 的虚拟化 (很多程序轮流用一个 CPU, 每个都以为自己独占) 和内存的虚拟化 (每个程序都有自己从 0 开始的地址空间). 第 2 讲从 CPU 虚拟化开始.

Folie 45

Teil 2: Nebenläufigkeit

  • Ereignisse geschehen gleichzeitig und können miteinander zusammenhängen
  • Das Betriebssystem muss nebenläufige Ereignisse und Prozesse verwalten können
  • Einfacher Fall
    • Nebenläufigkeit wird vor vollständig unabhängigen Prozessen versteckt
  • Schwieriger Fall
    • OS verwaltet die Nebenläufigkeit von miteinander interagierenden Prozessen
    • OS stellt Prozessen Abstraktionen zur Verfügung (Locks, Semaphore, Shared Memory, …)
  • Beispiel: Koordination von Threads

第 2 部分 并发: 事件同时发生, 而且可能相互关联; 操作系统必须能管理并发的事件和进程. 简单的情况: 进程之间完全独立, 操作系统把并发对它们隐藏起来 (每个进程感觉不到别人). 难的情况: 进程之间相互作用, 操作系统要管理它们的并发, 并提供抽象: Lock 锁、Semaphor 信号量、Shared Memory 共享内存 等. 例子: 线程之间的协调.

Folie 46

Teil 3: Persistenz

  • Informationen müssen dauerhaft verfügbar gemacht werden
    • Informationen müssen einzelne Prozesse überdauern können
    • System kann neu gestartet werden, Möglichkeit von Abstürzen oder Stromausfällen
  • Herausforderungen
    • Abstraktion von der genauen Art der physischen Speicherung in Dateien, Verzeichnisse, Verweise (Links)
    • Korrektheit auch bei unvorhergesehenen Ausfällen?
    • Performance: Festplatten (selbst SSDs) sind sehr langsam, verglichen mit Hauptspeicher (RAM)
  • Beispiel: Dateisystem kümmert sich um korrekte Updates

第 3 部分 持久化: 信息必须能长期保存, 要比单个进程活得久; 系统可能重启, 也可能崩溃或断电. 难点: 抽象 (把具体的物理存储方式抽象成文件、目录、链接); 正确性 (意外故障时数据还对吗?); 性能 (硬盘, 即使是 SSD, 也比内存慢得多). 例子: 文件系统负责保证更新是正确的 (例如写到一半断电, 文件不能变成一半旧一半新).
