Abstract Abstracts. An abstract is a summary at the beginning of a scientific paper.

Among the documents available in the “Materials” section in Moodle, you will find these three papers:

  1. Donald E. Knuth and Peter B. Bendix, “Simple Word Problems in Universal Algebras,” Computational Problems in Abstract Algebra, pp. 263–297, Pergamon Press, 1970.
  2. Susan Owicki and Leslie Lamport, “Proving Liveness Properties of Concurrent Programs,” ACM Transactions on Programming Languages and Systems 4(3), pp. 455–495, 1982.
  3. Alejandro Russo, “Functional Pearl: Two Can Keep a Secret, If One of Them Uses Haskell,” ACM SIGPLAN Notices 50(9), pp. 280–288, 2015.

The last reference claims to be a “functional pearl”: a concise, elegant example of functional programming. Carefully read the abstracts of all three papers, then answer the following questions, referring back to the abstracts if necessary.

  1. Which abstract did you like best? Why?
  2. Which school of writing does each of the abstracts belong to?
  3. Point out three differences you noticed in how the abstracts are written.
  4. Choose one of the three abstracts, and write a brief review of it. Your review should be about 100 words. In your text, point out at least one aspect you like and at least one aspect you would change.

读三篇论文的摘要 (Knuth–Bendix 1970 年提出的 Knuth–Bendix 完备化算法; Owicki–Lamport 1982 年关于并发程序活性 (liveness) 的证明; Russo 2015 年的 functional pearl, 用 Haskell 实现信息流安全), 回答: a) 最喜欢哪篇摘要, 为什么? b) 每篇属于哪个写作流派 (第 1 讲: 「学术」流派 vs. 平实英语流派)? c) 指出三处写法上的差异. d) 选一篇写约 100 词的评述, 至少说一个优点和一个想改的地方.

答案 (先自己做再看)

思路. b) 对照第 1 讲那张两栏表逐项看: 被动语态多不多? 句子长不长? 抽象词多还是具体例子多? 有没有多余的词? 有没有用 we/I? 平实英语流派的摘要往往以「We present / We show」开头, 句子短, 直接说做了什么、结果是什么. 1970 和 1982 年的两篇时代较早, 更可能偏「学术」流派 (被动、名词化); 2015 年的 functional pearl 文体上一般更轻松, 常有设问和第一人称.

c) 可以比较的维度: 长度; 第一句是讲背景还是直接讲贡献; 人称 (we、the authors、被动); 有没有给出具体结果或例子; 术语是否解释; 语气 (正式还是带点幽默, pearl 的标题「Two can keep a secret, if one of them uses Haskell」本身就是双关).

d) 100 词左右的评述可以按「一句概括 + 一个优点 + 一个改进 + 一句结论」组织, 例如: 「The abstract states the problem in its first sentence and the main result in its last, which makes the contribution easy to find. However, the second sentence packs three technical terms into a passive construction; splitting it and adding a concrete example would help nonexperts. …」. 要具体指出是哪一句、哪个词, 而不是笼统地说「写得好」.

In-class Exercise 2-1 · Curse of Knowledge

Sheet 2 · In-class exercise 2-1

Curse of Knowledge. Start by reading the following definition adapted from Jonathan Katz and Yehuda Lindell, Introduction to Modern Cryptography, Second Edition, CRC Press, 2014:

A message authentication code (or MAC) consists of three probabilistic polynomial-time algorithms (Gen, Mac, Vrfy) such that:

  • The key-generation algorithm Gen takes as input the security parameter 1n and outputs a key k with ∣k∣≥n.
  • The tag-generation algorithm Mac takes as input a key k and a message m∈{0,1}∗, and outputs a tag t. Since this algorithm may be randomized, we write this as t←Mack​(m).
  • The deterministic verification algorithm Vrfy takes as input a key k, a message m, and a tag t. It outputs a bit b, with b=1 meaning valid and b=0 meaning invalid. We write this as b:=Vrfyk​(m,t).

It is required that for every n, every key k output by Gen(1n), and every m∈{0,1}∗, it holds that Vrfyk​(m,Mack​(m))=1.

If there is a function ℓ such that for every k output by Gen(1n), algorithm Mack​ is only defined for messages m∈{0,1}ℓ(n), then we call the scheme a fixed-length MAC for messages of length ℓ(n).

Identify the background knowledge required to understand this definition for a novice to the field of cryptography.

读一段密码学教科书里「消息认证码 (MAC)」的定义, 列出密码学新手要看懂它需要哪些背景知识. 这正是第 2 讲「知识的诅咒」的反向练习: 专家写的时候觉得理所当然的东西, 一条条找出来.

答案 (先自己做再看)

需要的背景知识 (从概念到记号):

  • MAC 是干什么的: 通信双方共享一把密钥, 发送方给消息附上一个标签 (tag), 接收方据此确认消息没被篡改、确实来自持钥人. 定义里完全没说动机.
  • 算法的分类: 概率算法 (可以用随机数, 同样的输入可能给出不同的输出) vs. 确定性算法; 多项式时间 (运行时间以输入长度的多项式为界); 合起来的 probabilistic polynomial-time (PPT), 这是复杂性理论的概念.
  • 安全参数 n 以及一元记法 1n (n 个 1 组成的串): 为什么把 n 写成 1n 传给算法 (让「多项式时间」以 n 来度量).
  • 串的记号: {0,1}∗ 表示所有有限长的比特串, {0,1}ℓ(n) 表示长度恰为 ℓ(n) 的比特串; ∣k∣ 表示串 k 的长度.
  • 赋值记号: t←Mack​(m) 表示「运行概率算法、把输出赋给 t」, b:=Vrfyk​(m,t) 表示确定性的赋值; 两个箭头 / 冒号等号的区别本身就是约定.
  • 下标表示密钥: Mack​ 是「用密钥 k 的 Mac」; 「算法 Mack​ 只对某些消息有定义」把一个算法看成部分函数.
  • 正确性条件的读法: 对一切 n、一切由 Gen 生成的 k、一切消息 m, 诚实生成的标签都能通过验证 (这还不是安全性, 安全性要另外定义).
  • 「scheme 方案」指三元组 (Gen, Mac, Vrfy); 「fixed-length MAC」只处理固定长度消息, 这是为后面把短消息方案扩展到任意长度做铺垫.

还可以指出写法上可以补救的地方: 先给一句话的直观解释和一个例子; 解释 1n 和 ←; 说明 Vrfy 为什么必须是确定性的.

Transatlantic Medley. The following text inconsistently mixes the rules of American and British English. Identify as many constructs as possible that are specific to either language variant.

“Alex, we have a small problem”, said the woman. Her irritated tone did not match the way she casually leant against the filing cabinet. “Is that a check mark?”

Alex tried to analyse the splotches on the page. “Looks like an exclamation point to me.”

“Bloody hell. A pipe broke in the archive room, and now the writing on these is entirely unrecognisable.”

‘Actually, that might be more of a midsize problem then, Dr Arbour. If it’s unfeasible to discern the grades, we’re obligated to repeat the exam within the autumn term.’ He was sceptical they would be able to organise that in time, but that was a moot point just now.

Dr. Arbour frowned, and dropped the papers she was holding into the rubbish bin. “Have the committee ruled on that yet?”

“Not yet. They tabled it until after the curricula are dealt with. But you know how the maths department’s vice president feels about issues of this caliber. I doubt they’ll rule in our favour.”

“We could always randomize the marks,” suggested Dr Arbour.

“If we do that, I’ll need to go update my CV.” A stunt like that was sure to get his teaching licence revoked.

这段小故事故意把英式和美式英语混在一起: 两位老师发现一场考试的试卷被水泡坏了, 成绩看不清. 要求找出尽可能多的、只属于其中一种变体的写法.

答案 (先自己做再看)
  • 标点: 「small problem”, said」逗号在引号外 = 英式 (美式放在引号里: problem,”); 后文「the marks,” suggested」又放在里面 = 美式. 单引号 ‘Actually, …’ 作主引号 = 英式; 其余用双引号 = 美式. 「Dr Arbour」不加句点 = 英式, 「Dr. Arbour」 = 美式.
  • 拼写: 英式: analyse、unrecognisable、sceptical、organise、favour、licence (名词); 美式: randomize、caliber (英式 calibre). 「leant」 = 英式过去式 (美式 leaned).
  • 词汇: 美式: check mark (英 tick)、exclamation point (英 exclamation mark)、midsize (英 medium-sized)、obligated (英 obliged)、grades (英 marks)、table 表示「搁置」(英式里 table a motion 恰恰相反, 是「提交讨论」); 英式: Bloody hell、autumn term (美 fall semester)、rubbish bin (美 trash can)、maths (美 math)、marks、CV (美国非学术场合多用 résumé). unfeasible 在英式里更常见, 美式技术文本多用 infeasible.
  • 语法: 「Have the committee ruled」把集体名词当复数 = 英式 (美式: Has the committee ruled); 「go update my CV」省略 and = 美式 (英式: go and update).

改写时选定一种变体从头到尾统一 (第 3 讲): 例如全用美式, 就是 “Alex, we have a small problem,” … leaned … analyze … unrecognizable … “Actually, … Dr. Arbour …” … obligated … fall semester … skeptical … organize … trash can … “Has the committee ruled …” … math department … caliber … favor … randomize the grades … update my résumé … teaching license.

Said in So Many Words. The following text explains the concept of tail recursion.

Within the discipline of functional programming, in order for a function to be described as tail recursive, it must fulfill the following criterion: Whenever a function is called recursively, whatever result this recursive call yields must already constitute the final result of the function itself, without any additional computations occurring that further modify this recursive result. Compared with the naive approach, such an implementation can be said to reduce the memory space a function requires for its execution: Because of the fact that the values of intermediate recursive calls do not need to be processed further, it is not necessary for the compiler to store every return call location up until the point where the entire recursion terminates.

It should, however, also be noted that this constraint on compiler optimization is not always equally applicable to all programming languages. For instance, if we consider the language Haskell as an example, we find that because evaluations are performed lazily, these considerations become redundant in any and all cases where the evaluation of the recursive call can be delayed up until such a point where its result is actually needed in the computation.

  1. Rewrite the above text to make it as concise as you can.
  2. Compare your version with the original version in terms of word count.
  3. Which version do you find better—e.g., more easily comprehensible, more engaging, or more pleasing to read?
  4. Are there further improvements you could make to your rewritten version?

一段解释尾递归的啰嗦文字: a) 尽量精简地改写; b) 比较字数; c) 哪个版本更好 (更好懂、更吸引人、读起来更舒服)? d) 你的版本还能怎么改进?

答案 (先自己做再看)

a) 一种改写:

A function is tail recursive if each recursive call is its last action: the result of the call is returned unchanged. Tail recursion saves memory, because the compiler need not keep a return address for every pending call; it can reuse the current stack frame. This optimization matters less in lazy languages such as Haskell, where a recursive call is evaluated only when its result is needed.

b) 原文 191 词 (按空格分词), 改写后 67 词, 约为原来的三分之一.

被动语态和改写 (主语多用 we 或 the algorithm):

  • 「An algorithm is described which is capable of …」→ 「We describe an algorithm that can solve …」
  • 「whether … two words … can be proved equal」→ 「whether one can prove two words … equal」(这里被动其实很自然, 可以保留).
  • 「the general word problem is well known to be unsolvable」→ 「it is well known that the general word problem is unsolvable」.
  • 「if we are given the binary operator …」→ 「given the binary operator …」或 「if we take the binary operator …」.
  • 「The method is based on a well-ordering …」→ 「The method relies on a well-ordering …」; 「each identity can be construed as a ‘reduction’」→ 「we can construe each identity as a reduction」.
  • 「A set of reduction identities is said to be ‘complete’ when …」→ 「We call a set of reduction identities complete if …」.
  • 「The method used in this algorithm is essentially to test …」→ 「Essentially, the algorithm tests …」; 「which can be added to the list」→ 「that it can add to the list」.
  • 「The process is repeated until either a complete set is achieved or …」→ 「The algorithm repeats this process until it obtains a complete set or encounters a situation that it cannot yet handle」.
  • 「Results of several computational experiments … are given.」→ 「We report the results of several computational experiments.」

附加题: 三个 which 都引导限制性从句, 都可以换成 that: 「An algorithm … which is capable」、「a new consequence of the identities which can be added」、「an anomalous situation occurs which cannot at present be handled」. 后两处的从句还和先行词隔开了 (identities 和 situation occurs), 改写时最好让从句紧跟先行词.

What happens when two processes wait for each other—forever? Consider processes P and Q, each of which needs two resources (say, a printer and a file). P locks the printer; Q locks the file.     for (int i = 0; i < n; i++) {
        for (int j = 0; j < n - i - 1; j++) {
            if (a[j] > a[j + 1]) {

static public void selectionSort(int[] a) {
    final int n = a.length;
    for (int i = 0; i < n - 1; i++) {
        int min = i;
        for (int j = i + 1; j < n; j++) {
            if (a[j] < a[min]) {
                min = j;

        if (min > i) {
            swap(a, i, min);

答案 (先自己做再看)

两段参考描述:

Bubble sort. The algorithm makes n passes over the array a of length n. In pass i (counting from 0), it compares each pair of neighbors a[j] and a[j + 1] for j from 0 to n − i − 2 and swaps them if a[j] > a[j + 1]. After pass i, the i + 1 largest elements are in their final positions at the end of the array, so each pass can stop one position earlier than the previous one.

Selection sort. For each position i from 0 to n − 2, the algorithm finds the index min of the smallest element among a[i], …, a[n − 1]; if several elements are equally small, it takes the first one. If min differs from i, it swaps a[i] and a[min]. Afterwards, a[0], …, a[i] contain the i + 1 smallest elements in ascending order.

Input:  A set P of points in the plane.
Output: A list L containing the vertices of CH(P) in clockwise order.

 3:     valid ← true

 5:         if r lies to the left of the directed line from p to q then

 7:         end if
 8:     end for
 9:     if valid then
10:         add the directed edge →pq to E.
11:     end if
12: end for
13: From the set E of edges construct a list L of vertices of CH(P),

Skip Lists: Randomized Search Structures as a Simple Alternative to Balanced Trees

Balanced search trees guarantee logarithmic-time operations, but their rebalancing algorithms are intricate and hard to implement correctly. We present skip lists, a data structure that achieves the same expected performance using randomization instead of rebalancing. A skip list is a hierarchy of sorted linked lists: the bottom list contains all elements, and each list contains every element of the list below with probability 1/2. A search starts in the top list and moves down whenever the next element is too large. We show that search, insertion, and deletion take O(logn) expected time and that the structure uses O(n) expected space, independently of the input order. Benchmarks show that skip lists are competitive with balanced trees while requiring considerably less code.

答案 (先自己做再看)

教程骨架 (英文正文, 每步一个可以直接复制运行的例子):

Finding Text with grep. grep prints every line of its input that matches a pattern. It is useful for finding where a function is used, which log entries contain an error, or which notes mention a topic.

Searching one file. grep error server.log prints all lines of server.log that contain error. Add -i to ignore case and -n to show line numbers: grep -in error server.log.

Searching several files. grep hello *.txt searches all files ending in .txt in the current directory. The shell, not grep, expands *.txt into a list of file names; grep then prefixes each match with the file name.

Searching a directory tree. grep -r hello notes/ searches every file in notes and its subdirectories. To restrict the search to certain files, combine it with --include: grep -r --include='*.txt' hello notes/. The quotes prevent the shell from expanding the pattern.

Patterns. The pattern is a regular expression: grep '^#' script.sh finds lines that start with #. Use -F to search for a fixed string that contains special characters, and -w to match whole words only.

要点 (第 13 讲): 教程以任务为导向, 先给最常用的情形; 每个命令都能运行; 解释容易踩坑的地方 (通配符是 shell 展开的, 所以 *.txt 不会进入子目录; 而 -r 不加 --include 会搜所有文件).

    private Random random;

    public WaitingList() {
        items = new ArrayList<>();
        random = new Random();
    }

    public void addNumber(int number) {

            throw new IllegalArgumentException("Number "

        int number;
        do {
            number = random.nextInt(1000) + 1;

    public Integer drawNumber() {
        if (items.isEmpty()) {
            return null;
        }
        return items.remove(0);
    }
}
