Folie 26

Rückblick und Motivation (Fortsetzung von Folie 24)

  • Lösung:
    • Erweiterung des Konzeptes zu Objekten und Klassen.
    • Ähnlichkeiten und Unterschiede zwischen Klassenstrukturen identifizieren
    • Eine neue Hierarchie der ähnlichen Klassen konzipieren

问题: 三个账户类之间又出现了重复: Sparkonto 和 Bankkonto 有相同的属性和方法, Girokonto 和 Bankkonto 有同名的方法. 重复定义不仅浪费时间, 还难以维护: 比如要给所有账户的 einzahlen 加一个「金额不能为负」的检查, 就得改三个地方, 漏改一个就不一致.

解决办法: 扩展类和对象的概念: 找出类之间的共同点和不同点, 把相似的类组织成一个层次结构 (Hierarchie). 共同的部分只写一次, 放在上层. 这就是继承.

继承
Vererbung

Folie 27

Vererbung ist ein Mechanismus zur Implementierung von Klassen durch Erweiterung existierender Klassen

Beispiel:

  • Die Klasse Bankkonto stellt die Grundfunktionalität eines Bankkontos bereit.
  • Möchte man verschiedene spezielle Arten von Bankkonten implementieren, so kann die Klasse Bankkonto durch Vererbung erweitern:
    • Sparkonto: hat zusätzlich einen Zinssatz, Zinsen können gut geschrieben werden
    • Girokonto: bei jeder Transaktion werden Gebühren berechnet

Vererbung 继承: 通过扩展已有的类来实现新类的机制. Bankkonto 提供账户的基本功能; 特殊的账户通过继承来扩展它: Sparkonto 额外有利率、能计息; Girokonto 每笔交易收手续费. 新类自动拥有旧类的一切, 只需写出不同的地方.

原文笔误: 「so kann man die Klasse Bankkonto durch Vererbung erweitern」漏了主语 man. 「gut geschrieben」应写作「gutgeschrieben」(记入贷方).

Folie 28

Grammatik für Klassendeklaration (mit Vererbung)

ClassDecl   = "class" Identifier [ "(" Identifier ")" ] ":" ClassBody
ClassBody   = ConstructorDecl|MethodDecl
MethodDecl  = Header Block
Header      = "def" Identifier "(" "self" [ "," FormalParam ] ")" ":"
FormalParam = Identifier { "," Identifier }
  • Der Identifier zwischen den "(" ")"-Klammern ist der Klassenname der allgemeine Klasse (Oberklasse).
  • Angabe der Oberklasse ist optional
  • Oberklasse ist standardmäßig die vordefinierte Klasse object wenn nichts angegeben

有继承时, 类名后面可以加 (父类名): class Sparkonto(Bankkonto):. 父类可以不写; 不写时父类默认是 Python 预定义的 object 类 (所以第 5 章 help 的输出里有 class Point(builtins.object)).

幻灯片小错: ClassBody = ConstructorDecl|MethodDecl 又退回了第 5 章的写法 (只允许一个声明); 第 6 章 Folie 11 已改成 { MethodDecl }. 「der allgemeine Klasse」应为「der allgemeinen Klasse」.

        self.zinssatz = zinssatz

    def zinsen_anrechnen(self):
        zinsen = self.kontostand * self.zinssatz/100.0
        self.kontostand += zinsen
  • Ein Sparkonto erbt alle Attribute und Methoden eines Bankkontos und fügt eigene hinzu.

用继承重写 Sparkonto: 只写新增的东西.

  • class Sparkonto(Bankkonto): Sparkonto 是 Bankkonto 的子类. einzahlen、abheben 不用再写, 自动继承.
  • super().__init__(anfangsbetrag): 调用父类的 __init__ 来设置 kontostand, 然后再设置自己的 zinssatz.
  • zinsen_anrechnen 是新方法.

读图: UML 里继承画成从子类指向父类的箭头, 箭头是空心三角形. 「Sparkonto 是一种 Bankkonto」(is-a 关系).

Vererbung einführen

  • Um die Erbreihenfolge zwischen zwei Klassen festzulegen, muss nur die erbende Klasse (Unterklasse) im class-Aufruf in Klammern die allgemeine Klasse (Oberklasse) notiert werden.
    Beispiel: class Sparkonto(Bankkonto):
  • Alle Attribute und Methoden der Oberklasse werden dann implizit vererbt, aber die __init__-Methode wird nur geerbt falls keine eigene __init__-Methode definiert wird.
  • Die __init__-Methode der Oberklasse wird explizit im neu definierten Konstruktor der Unterklasse aufgerufen.
  • 在子类的 class 行里把父类名写在括号里, 就建立了继承关系.
  • 父类的所有方法 (以及父类 __init__ 里设置的属性) 都隐式继承. 例外: 子类自己定义了 __init__ 时, 父类的 __init__ 不会自动执行.
  • 所以子类的 __init__ 里要显式调用父类的 __init__, 否则 kontostand 这类在父类 __init__ 里设置的属性就不存在.

易错: 子类 __init__ 忘了写 super().__init__(…), 之后调用 einzahlen 时就会出现 AttributeError: … no attribute 'kontostand'.

调用父类的构造方法
Aufruf des __init__-Konstruktors der Oberklasse

Folie 32
  • Die __init__-Methode der Oberklasse muss explizit im neu definierten Konstruktor der Unterklasse aufgerufen werden.
  • Aufruf des Konstruktors der Oberklasse __init__-Methode:
    super().__init__(a1,...,an)
    Beachte: Aufruf ohne self
  • super() steht für „superclass“, sprich Oberklasse.
  • Wir stellen damit eine Verbindung zwischen der Oberklasse und der Unterklasse her

重写方法
Überschreiben von Methoden

Folie 35
  • In vielen Fällen möchte man die Implementierung von Methoden in der Unterklasse abändern.
  • Beispiel: Beim Girokonto soll bei jeder Ein- und Auszahlung eine Gebühr vom Kontostand abgezogen werden.
  • Deshalb: Man darf in der Unterklasse Methoden der Oberklasse neu implementieren. Das nennt man überschreiben.
  • Eine überschriebene Methode muss in der Unterklasse denselben Namen und dieselben Parameter (in Anzahl) wie die Methode der Oberklasse haben.
  • Überschreiben in UML-Diagrammen: Die überschriebene Methode wird in der Unterklasse nochmal aufgeführt.

Überschreiben 重写 (英语 override): 子类重新实现父类的某个方法. Girokonto 的存取款要多扣手续费, 所以要重写 einzahlen 和 abheben.

规则: 重写的方法要和父类方法同名, 参数个数相同. UML 里重写的方法要在子类里再列一次 (继承来但没重写的不列).

注意区分: 重写 (override, 子类改写父类同名方法) 和 Java 里的重载 (overload, 同一个类里同名但参数不同的多个方法, Python 不支持).

「参数个数必须相同」是好的设计规则 (否则用父类的方式调用子类对象会出错), 但 Python 本身不强制检查: 子类可以定义参数个数不同的同名方法, 程序照样能运行, 只是调用时可能 TypeError.

动态绑定
Dynamische Bindung

Folie 41
  • Bei einem Methodenaufruf e.m(a1,...,an) muss eine Implementierung der Methode m ausgewählt und ausgeführt werden.
  • Die Auswahl der Implementierung richtet sich nach der Klasse C des Objekts, auf welches e im aktuellen Zustand zeigt.
  • Ist die Methode m in der Klasse C definiert, so wird diese Implementierung ausgeführt. Ansonsten wird in der Oberklasse C weitergesucht.
  • Die Entscheidung, welche Implementierung der Methode benutzt wird, wird dynamisch (d.h. erst zur Laufzeit) getroffen. Man spricht von dynamischer Bindung (des Methodennamens an die auszuführende Implementierung).

调用 e.m(…) 时, 用哪一个 m 的实现? 规则:

  1. 看 e 当前指向的对象属于哪个类 C (是对象的类, 不是变量名或「声明」的类型).
  2. C 里定义了 m → 用 C 的; 没定义 → 去 C 的父类里找, 再找父类的父类……直到 object.

这个选择在运行时才做, 所以叫dynamische Bindung 动态绑定. 

>>> konten = [Bankkonto(100), Girokonto(100, 1)]
>>> for k in konten:
...     k.einzahlen(10)
...
>>> [k.kontostand for k in konten]
[110, 109]

同一行 k.einzahlen(10), 第一次执行的是 Bankkonto 的版本, 第二次是 Girokonto 重写的版本 (多扣 1). 这正是继承 + 重写的威力: 调用方不必知道具体是哪种账户.

原文笔误: 「Ansonsten wird in der Oberklasse C weitergesucht」应为「in der Oberklasse von C」.

Spezielle Methoden überschreiben (Fortsetzung)

    def __len__(self):
        """Darstellung der Laenge einer Instanz
        (spezielle Methode) wird überschrieben."""

        """Vergleich zwei Instanz

Die __eq__-Methode, wir verwendet, um zwei Objekte anhand ihrer Werte zu vergleichen. Python ruft automatisch die __eq__-Methode einer Klasse auf, wenn Sie den ==-Operator verwenden, um die Instanzen der Klasse zu vergleichen.

前后带双下划线的方法叫特殊方法 (spezielle Methoden, 也叫 dunder methods). 它们在 object 类里已有默认实现, 每个类都继承了; 在自己的类里重写它们, 就能让内置函数和运算符作用于自己的对象:

特殊方法被谁自动调用Buch 里的实现
__str__(self)str(b)、print(b)返回「作者: 书名」
__len__(self)len(b)返回页数
__eq__(self, other)b1 == b2书名和作者都相同就算相等 (不比较页数)

不重写时: print 输出 <__main__.Buch object at 0x…>; len 报 TypeError; == 比较的是引用 (第 5 章). 重写 __eq__ 以后, == 就比较内容了.

幻灯片排版问题和笔误: __eq__ 的 return … and ↵ self.autor == … 在 and 后换行而没有括号, 照抄是 SyntaxError; 要写在一行, 或写成 return (self.titel == other.titel and ↵ self.autor == other.autor). 说明文字「wir verwendet」应为「wird verwendet」; Docstring「Vergleich zwei Instanz」应为「Vergleich zweier Instanzen」.

Folie 48

Prozess der Modellierung und Problemlösung:

Einige Prinzipien beim Entwurf

  • Substantive der Problembeschreibung werden oft durch Klassen abgebildet.
  • Verben der Problembeschreibung werden oft zu Methoden im Modell.
  • Klassen sollten nicht zu sehr gekoppelt sein, d.h. sich möglichst nicht gegenseitig benutzen.
  • Klassen nicht zu groß machen, sondern in Teile zerlegen

建模和解题的过程: 问题 → (抽象和建模) → 模型 (例如 UML 类图) → (实现) → 程序.

设计原则:

  • 问题描述里的名词常成为类 (Buch、Nutzer、Exemplar);
  • 动词常成为方法 (ausleihen 借);
  • 类之间不要耦合 (Kopplung) 太紧: 尽量不要互相调用来调用去, 否则改一个类就牵连很多类;
  • 类不要太大, 拆成几个部分.

讨论: 让 Exemplar 继承 Buch 是一种可能的建模 (幻灯片标题就说是「mögliche 可能的」). 也可以把 Exemplar 和 Buch 之间建成关联 (「一个副本是某本书的一份」), 更符合「同一本书有多个副本」的描述, 因为继承表示的是「是一种」.
