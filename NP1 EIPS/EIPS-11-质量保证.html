⟹ Software enthält Fehlerzustände (engl. faults, bugs)

第二个原因: 需求不明确. 「求一列数的平均值」看似简单, 实际有很多没说清的地方: 算术平均、几何平均还是平方平均? 空序列怎么办? 输入是列表还是元组, 数是 int 还是 float? 结果要不要取整? 怎么处理「负面」输入 (如 None)? 规格不清, 写出来的程序就很可能和期望不符. 结论: 软件一定含有错误.

原文用词不准: 「Umgang mit Negativeingaben (z.B. None)」: None 不是「负数」, 这里指的是无效或异常的输入 (德语常说 ungültige Eingaben).

Beispiel Fehlerzustand, Fehlerwirkung und Fehlhandlung

def mittel(liste):
  summe = 0;
  for eintrag in liste:
    summe += eintrag
  return summe // len(liste)
FehlerwirkungAufruf von mittel auf [1,2] gibt 1 statt 1.5 zurück
FehlerzustandGanzzahldivision //
FehlhandlungVerwendung des falschen Divisionsoperators

三个容易混的术语, 按因果顺序:

术语英语是什么例子
Fehlhandlung 错误行为mistake, error人做错的事程序员用错了除法运算符
Fehlerzustand 缺陷fault, defect, bug代码里错误的那个地方写成了整除 //
Fehlerwirkung 失效failure运行时观察到的偏差mittel([1, 2]) 返回 1 而不是 1.5

人的错误行为在代码里留下缺陷, 缺陷在运行时 (可能) 导致失效. 注意「可能」: 缺陷不一定每次都显现, 例如 mittel([2, 4]) 用 // 也得到正确的 3. 实际运行确认 mittel([1, 2]) 是 1. 行末的分号 summe = 0; 在 Python 里多余但合法.

Folie 9

Testen ist eine (übliche) Maßnahme zur Qualitätssicherung

TestenAufdecken von Fehlerwirkungen (Abweichungen vom erwarteten Verhalten)
DebuggingBestimmung des Fehlerzustands (Gründe für Fehlerwirkung)

Softwarequalität erhöht sich nach dem Fix

三步分工: 测试发现失效 (程序表现不对); 调试找出缺陷在哪里 (为什么不对); 修复改正代码. 只有修复之后软件质量才真正提高, 测试本身只负责「发现」.

Folie 10

Testen als dynamische Überprüfung

Program testing can be used to show the presence of bugs, but never to show their absence! (Edsger W. Dijkstra)

Beware of bugs in the above code; I have only proved it correct, not tried it. (Donald Knuth)

两句名言:

  • Dijkstra: 「测试能证明 bug 存在, 但永远不能证明 bug 不存在.」测试只检查了一部分输入, 没出错不代表其他输入不出错.
  • Knuth: 「小心上面代码里的 bug; 我只证明了它是正确的, 还没试运行过.」反过来, 数学证明也可能遗漏实际问题 (证明的模型和真实程序不一样).

结论: 测试和证明 (Verifikation) 互相补充.

Folie 11

Testen als dynamische Überprüfung

  • ✓ Ausführen des tatsächlichen Systems
    → gefundene Fehler lassen sich konkret nachvollziehen
    z.B.: Absturz, Nichtterminierung, falsche Ausgaben, Performanzprobleme
  • ✓ Einfach umzusetzen & gut automatisierbar
    → in der Praxis etabliert (z.B. Test-Driven Dev.)
  • ✓ Erzeugt ein ziemlich gutes Grundvertrauen
    → keine “offensichtlichen” Fehler
  • × Deckt nur (fast) immer einen Teil des System-Verhaltens ab
    → evtl. nicht ausreichend für teure und sicherheitskritische Systeme

测试是动态检查 (真的运行程序). 优点: 运行的是真实系统, 找到的错误 (崩溃、不终止、输出错误、性能问题) 可以具体复现; 容易实现、容易自动化, 实践中广泛使用; 能建立基本的信心 (没有明显错误). 缺点: 几乎总是只覆盖一部分行为, 对昂贵或安全攸关的系统 (飞机、医疗设备) 可能不够.

不可能测试所有输入: 输入太多 (一个接收两个 int 的函数就有无穷多组输入)、时间和预算有限、不划算. 图里: 测试投入越多 (横轴向右), 遗留缺陷造成的损失 (蓝色虚线) 越小, 但测试本身的成本 (绿色斜线) 越大; 两条线的交点附近是性价比最好的投入.

风险导向测试: 风险 = 发生概率 × 损失. 先测风险高的部分, 而且测得更仔细.

Risikobestimmung – Kosten

Berücksichtigung verschiedener Aspekte wie

  • Vertragsstrafen
  • Rechtliche Konsequenzen
  • Auswirkung auf die eigene Reputation, zukünftiger Verkauf von Produkten

评估风险的两部分:

  • 发生概率: 这个功能多常用; 出错的可能性 (这个组件过去的质量、开发者的水平、功能的复杂程度); 现有测试漏掉它的可能性.
  • 损失: 合同违约金、法律后果、声誉和今后的销售; 修复成本: 影响多少客户、发布新版本有多难多贵 (网页应用改一下就行, 汽车或卫星里的软件就很难更新).
Folie 16

Testen: Was möchte man wissen? (Beispiele)

Fragestellungen

  • Systemverhalten bei ungültigen Eingaben
  • Kompatibilität zwischen Systemteilen
  • Verhalten bei externen Fehlern (z.B. Verbindungsunterbrechung)
  • Verhalten unter hoher Last (viele Anfragen, große Daten)
  • Dokumentation des Ist-Verhaltens → Regressionen erkennen
  • Zuverlässigkeit (z.B. Fehlerrate in der Entwicklungsphase)

Kenngrößen

  • Welche Anforderungen wurden berücksichtigt?
  • Codeabdeckung (Coverage)
  • Abdeckung der Wertebereiche von Eingaben
  • Systemabdeckung (für welche Teile gibt es Tests)
  • Automatisierung der Testausführung

测试要回答的问题: 无效输入时系统怎样表现; 各部分能否配合; 外部故障 (断网) 时怎样; 高负载下怎样; 记录当前行为以发现Regression 回归 (改代码后原来好的功能坏了); 可靠性.

衡量测试的指标: 覆盖了哪些需求; 代码覆盖率 (多少代码被执行过); 输入取值范围的覆盖; 系统哪些部分有测试; 测试执行是否自动化.

测试用例
Beispiel Primzahl

Folie 18

Beipspiel Primzahl

def ist_primzahl(n):
    """
    Testet ob eine Zahl eine Primzahl ist.
    """
    for i in range(3, n):
        if n % i == 0:
            return False
    return True

一个要测试的素数函数: 试除 3 到 n−1, 有能整除的就不是素数.

它其实有 bug (下面几张幻灯片用测试来找): 从 3 开始试除, 漏掉了 2. 用脚本对 −3 到 29 实际运行, 返回 True 的是: [-3, -2, -1, 0, 1, 2, 3, 4, 5, 7, 11, …]. 也就是 4 被当成了素数 (range(3, 4) 只试 3), 0、1 和所有负数也被当成了素数. 其他偶数恰好能被某个 ≥ 3 的数整除 (6 被 3、8 被 4……), 所以没暴露.

原文笔误: 标题「Beipspiel」应为「Beispiel」.

Folie 19

Testfälle

print(ist_primzahl(6))   # Ergebnis: False

print(ist_primzahl(2))   # Ergebnis: True

print(ist_Primzahl(-6))  # Ergebnis: True

Für negative ganze Zahlen liefert die Funktion immer True zurück.

print(ist_Primzahl(0.5))
# Ergebnis: range() integer end argument expected, got float.

Ruft man die Funktionen mit Float-Zahlen auf, gibt es einen TypeError, weil range nicht für Float-Werte definiert ist.

手工测试: 6 → False (对), 2 → True (对), −6 → True (错! 负数不是素数): range(3, −6) 是空的, 循环不执行, 直接返回 True. 0.5 → TypeError: range 的参数必须是整数. 这些测试暴露了函数对「非正整数」输入的问题.

幻灯片错误和版本差异: 后两行调用的是 ist_Primzahl (大写 P), 而函数名是 ist_primzahl; Python 区分大小写, 实际运行报 NameError: name 'ist_Primzahl' is not defined, 得不到注释里的结果. 另外 range 收到 float 时, Python 3.15 的报错是 TypeError: 'float' object cannot be interpreted as an integer; 幻灯片里那句「range() integer end argument expected, got float」是 Python 2 的旧信息.

Folie 20

Explizite Überprüfung der Primzahl-Funktion

if ist_primzahl(3) == True and ist_primzahl(6) ==
    False and ist_primzahl(10) == False:
     print("Test für Primzahl-Funktion erfolgreich")
else:
     print("Primzahl-Funktion liefert fehlerhafte
         Werte")

# Ergebnis: Test für Primzahl-Funktion erfolgreich

把几个「输入 → 期望结果」写成一个条件, 自动判断是否全部通过. 实际运行: 条件为 True, 输出「erfolgreich 成功」.

这正好印证了 Dijkstra 的话: 三个测试都通过了, 函数却仍然有 bug (4、负数、0、1 都判错). 测试用例选得不好, 就发现不了缺陷. 后面的 Folie 34、35 讲怎样系统地选用例.

幻灯片排版问题: if 条件在 == 后换行而没有括号, 字符串 "Primzahl-Funktion liefert fehlerhafte 也在引号内折行, 照抄都是 SyntaxError; 只是幻灯片宽度不够. 实际要把条件包进括号或写在一行. 另外和 True/False 比较可以省掉: if ist_primzahl(3) and not ist_primzahl(6) ….

一个完整的Testfall 测试用例包括:

  • Vorbedingung 前置条件: 测试前环境要满足什么 (文件存在);
  • Eingaben 输入;
  • erwartetes Ergebnis 期望结果 (返回值);
  • Nachbedingung 后置条件: 执行后环境应处于什么状态 (文件被删除了);
  • Testanweisungen 测试步骤: 具体怎么调用;
  • Testauswertung 测试评估: 比较期望结果和实际结果, 判定「通过」或「失败」, 通常自动完成.

纯函数 (ist_primzahl) 没有前置/后置条件, 只看返回值; 有副作用的函数 (os.remove 删除文件, 返回 None) 的真正效果要通过后置条件检查.

Assertion 断言: assert 条件, "说明". 运行到这里时检查条件; 为假就抛出 AssertionError 并带上说明文字; 为真什么都不做. 用途: 检查程序不应出现的状态, 防止自己的编程错误 (例: 平方根的结果一定 ≥ 0). 防范别人传进来的错误输入 (前置条件) 则用异常 (第 14 章). 

>>> y = -1
>>> assert y >= 0, "unexpected result of sqrt"
Traceback (most recent call last):
  ...
AssertionError: unexpected result of sqrt

运行时检查通常只在开发阶段用: 用 python -O 运行时所有 assert 都会被跳过.

原文笔误: 「unexcepted result」应为「unexpected」.

Folie 24

Verwendung von Absicherungen

  • als erwartetes Ergebnis: keine Verletzung, Ausnahme
    • Assertions für Modultests
    • Ausnahme bzgl. Vorbedingung für Integrationstests
  • Assertions zum automatischen Abgleich von berechnetem Ergebnis und erwartetem Ergebnis

两种用法: 程序里的断言和异常本身就是一种检查 (测试时期望它们不被触发, 或者期望某个异常被正确抛出); 在测试代码里用 assert 自动比较实际结果和期望结果, 这正是 pytest 的写法 (Folie 39).

  • Um zu überpüfen, das die Einzelteile eines Systesm funktionieren, werden sogenannte Modultests verwendet

  • Automatisierung: Integration in Entwicklungsprozesse
  • Tools: PyTest, Unittest, DocTest, Robot …

Modultest 单元测试: 检查系统的各个部分 (函数、类、方法、包) 是否正确. 写成 Test-Suite 测试套件 (一组测试), 每个测试 = 准备 + 具体输入 + 期望结果 + 收尾. 通常用 assert 检查, 并集成到开发流程中自动运行. Python 的工具: pytest、unittest (标准库)、doctest (把 Docstring 里的 >>> 例子当测试)、Robot Framework.

系统地创建测试用例
Testfälle erzeugen

Folie 26
  • Testen eines Programms heißt, gezielt nach fehlerhaftem Verhalten zu suchen
  • Ein Testfall besteht aus einer Eingabe und dem erwarteten Ergebnis. Die Testfälle bilden eine Testsuite.
  • Schon vor dem Programmieren: systematisch Testfälle erstellen:
    • Basisfälle und Grenzfälle (z.B. erstes bzw. letztes Element in einer Datenstruktur)
    • Jede Anweisung im Code soll durch einen Testfall abgedeckt (d.h. ausgeführt) werden
    • Versuche eingaben zu finden, die die Bedingungen im Programm unabhängig voneinander wahr bzw. falsch machen (soweit möglich).
  • Tests, die zur Entdeckung eines Fehlers geführt haben, sollten aufbewahrt werden!

测试 = 有目的地寻找错误行为 (不是为了证明程序对). 系统地设计用例:

  • Basisfälle 基本情况和 Grenzfälle 边界情况: 例如数据结构的第一个和最后一个元素、空列表、0、负数;
  • 每条语句至少被一个用例执行到 (语句覆盖, Folie 33);
  • 让程序里的每个条件分别为真和为假 (分支覆盖).

发现过 bug 的测试要保留下来, 作为回归测试 (防止这个 bug 以后又出现).

Folie 32

Beispiel: Maximum durch “Elimination” (1)

# Nicht optimaler Code
def maximum(a, links, rechts):

    while links < rechts:
        if a[links] < a[rechts]:
            links += 1
        else:
            rechts -= 1

    return a[links]
  1. Anne Kaldewaij and Berry Schoenmakebs: Searching by elimination, 1990
  2. Edsger W. Dijkstra: Why numbering should start at zero, 1982 https://www.cs.utexas.edu/users/EWD/transcriptions/EWD08xx/EWD831.html

「淘汰法」求最大值: 两个指针 links、rechts 从两端向中间走; 每次比较两端的元素, 较小的那个不可能是最大值, 把它淘汰 (对应的指针向内移一步). 两个指针相遇时, 剩下的那个就是最大值.

这个实现把 rechts 当作包含在范围内 (会访问 a[rechts]), 和 Folie 29 约定的左闭右开不一致, 所以 Folie 29 的测试会失败 (Folie 40). 参考文献 2 是 Dijkstra 论证「下标应从 0 开始、区间应左闭右开」的著名短文, 正好对应这个问题.

实际运行 (rechts 包含在内的理解): maximum([3, 9, 4], 0, 2) = 9.

原文笔误: 第一作者名「Schoenmakebs」应为「Schoenmakers」(Berry Schoenmakers).

Modultests: Diskussion

  • ✓ Source-Code nicht notwendig
  • ✓ Komplexe Szenarien möglich: genaue Beschreibung der erwarteten Ergebnisse
  • ✓ Einfach umzusetzen & zu automatisieren
  • ✓ Fängt Regressionen ab (neue Fehler)
  • × unklar, wie viel Code überprüft wurde → Abdeckungsmaße
  • × Manueller Aufwand → Testfallgenerierung
  • × unklar, wie viel Verhalten überprüft wurde → Verifikation

单元测试的优点: 写测试不一定需要源代码 (只要知道接口和需求); 可以精确描述复杂场景的期望结果; 容易实现和自动化; 能捕获回归.

缺点和对应的补救: 不清楚测了多少代码 → 覆盖率 (下一节); 要手工写用例 → 自动生成测试用例; 不清楚检查了多少行为 → 形式化验证.

  • Testfälle und Test Suites zur Prüfung von Anforderungen und Code Abdeckung entwickeln können
  • Automatisierte Tests im Framework Pytest entwickeln können
    https://docs.pytest.org
  • Abdeckungsmessung mit Coverage Modul durchführen können

学完这一章, 应当能够:

  1. 设计测试用例和测试套件: 面向需求 (等价类 + 边界值) 和面向代码覆盖 (每条语句、每个分支); 知道测试用例的组成部分; 分清 Fehlhandlung / Fehlerzustand / Fehlerwirkung.
  2. 用 pytest 编写自动化测试: test_ 开头的函数、assert、pytest.raises、pytest.main.
  3. 用 coverage 模块测量覆盖率: coverage run [--branch]、coverage report、coverage html, 并能读懂报告.
