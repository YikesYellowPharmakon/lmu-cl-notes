Fehlerquellen

Folie 3

Ein Programm kann aus vielen Gründen ein unerwünschtes Verhalten zeigen:

  • Logische Fehler beim Entwurf, d.h. bei der Modellierung des Problems: Entwurf entspricht nicht den Anforderungen
  • Fehler bei der Umsetzung des Entwurfs in ein Programm
    • Programm entspricht nicht dem Entwurf (logischer Programmierfehler)
    • Algorithmen falsch implementiert (logischer Programmierfehler)
    • Programm bricht ab wegen vermeidbarem Laufzeitfehler, z.B. Division durch 0, falscher Zugriff auf Eintrag in Liste, ...
Folie 4

Fehlerquellen (2)

  • Ungenügender Umgang mit außergewöhnlichen Situationen, die nicht vermieden werden können
    • Fehlerhafte Benutzereingaben, z.B. Datum 31.11.2019
    • Fehlerhafter Dateizugriff, z.B. Datei existiert nicht
    • Abbruch der Netzwerkverbindung, ...

程序行为不符合预期的原因, 分三类:

  1. 设计阶段的逻辑错误: 建模本身就不满足需求 (第 1 章的软件开发过程).
  2. 实现阶段的错误: 程序和设计不符、算法写错 (都是逻辑错误, 程序能运行但结果不对); 或者本来可以避免的运行时错误导致程序中断, 如除以 0、列表下标越界.
  3. 无法避免的特殊情况没有处理好: 用户输入错 (11 月没有 31 号)、文件不存在、网络断开. 这些不是程序员的错, 但程序必须能应对.
Folie 5

Robuste Programme

  • Wir beschäftigen uns nicht damit, wie man logische Fehler in einem Programm finden kann.
  • Wir konzentrieren uns auf das Erkennen, Vermeiden und Behandeln von Ausnahmesituationen, die zu Laufzeitfehlern führen können.
  • Unser Ziel ist es, robuste Programme zu schreiben.

Definition
Ein Programm heißt robust, falls es auch beim Auftreten von Fehlern reagiert.

本章不讲怎样找逻辑错误 (那是第 11 章测试的事), 而讲怎样识别 (Erkennen)、避免 (Vermeiden)、处理 (Behandeln) 会导致运行时错误的Ausnahmesituation 异常情况. 幻灯片页脚的导航条 Erkennen · Vermeiden · Behandlung · Exception · Dateizugriff 就是本章的结构.

定义: 一个程序在出错时也能 (合理地) 作出反应, 就叫robust 健壮. 例如输入错了就提示重输, 而不是直接崩溃.

幻灯片表述不完整: 「falls es auch beim Auftreten von Fehlern reagiert」: 任何程序出错时都会「反应」(崩溃也算反应). 意思应是「angemessen reagiert 恰当地反应」.

识别异常情况
Ausnahmesituationen erkennen

Folie 6

Ausnahmesituationen erkennen (1)

Beispiel: Berechnung der Fakultät

def fact(n):
    if n==0:
        return 1
    else:
        return n*fact(n-1)
# Ausführen
m = -1 # Negative Zahl
k = fact(m)
print("Fakultät von " + str(m) + " ist " + str(k)
  • Es kann zu Nichtterminierung kommen
  • Diese Ausnahmesituation wird in der Methode fact nicht erkannt

阶乘 (第 12 章) 只对 n ≥ 0 有定义. 传入 −1: −1 → −2 → −3 …… 永远到不了 n == 0, 递归不会结束 (Nichtterminierung 不终止). 函数本身没有识别出「参数为负」这种异常情况.

实际在 Python 里不会真的无限运行: 递归深度到上限 (默认约 1000 层) 时抛出 RecursionError: maximum recursion depth exceeded.

幻灯片代码错误: 最后一行 print(...) 少了右括号, 照抄运行在执行前就报 SyntaxError: '(' was never closed, 根本看不到递归的问题. Folie 7 的同一行补上了括号.

Folie 7

Ausnahmesituationen erkennen (2)

def fact2(n):
    if n < 0:
        return -1
    elif n == 0:
        return 1
    else:
        return n * fact2(n-1)

# Ausführung

m = -2
k = fact2(m)
print("Fakultät von " + str(m) + " ist " + str(k))

Die Ausnahmesituation n < 0 wird in der Methode fact2 zwar erkannt, aber nicht adäquat an den Aufrufer gemeldet.

第二版识别出了 n < 0, 返回 −1 作为「错误码」. 输出「Fakultät von -2 ist -1」, 好像 −2 的阶乘真的是 −1. 问题: 调用者必须记得检查返回值是不是 −1, 忘了就会拿错误的值继续算; 而且如果某个函数的正常结果也可能是 −1, 错误码就和正常值混在一起了. 所以说情况被识别了, 但没有恰当地报告给调用者.

Folie 8

Ausnahmesituationen erkennen und Ausnahme auslösen

def fact3(n):
    if n < 0:
        raise ValueError("Eingabe darf nicht kleiner als 0 sein.")
    elif n == 0:
        return 1
    else:
        return n * fact3(n-1)

# Ausführung

m = -2
k = fact3(m)
print("Fakultät von " + str(m) + " ist " + str(k))

Die Ausnahme wird in der Methode fact3 erkannt und eine Ausnahme wird erzeugt („geworfen“).

  • Die Ausnahme enthält eine individuelle Information, die die Fehlersituation beschreibt.
  • Wird eine Ausnahme ausgelöst, dann werden die Methode und das Programm abgebrochen und die Fehlermeldung wird auf der Konsole gemeldet.
  • Alternativ kann die Ausnahme auch individuell im main-Programm behandelt werden (vgl. später).

第三版: 用 raise 抛出 (auslösen, 口语「werfen」) 一个异常. 异常对象带着描述错误的信息 (这里是那句德语). 抛出后函数立即中止, 不会返回一个看似正常的值; 如果没有人处理它, 整个程序中止, 控制台打印 Traceback 和错误信息: 

ValueError: Eingabe darf nicht kleiner als 0 sein.

好处: 调用者不可能「忘记检查」, 错误不会悄悄传下去; 想继续运行的话, 可以在调用处捕获异常 (Folie 19 起).

幻灯片表述不准确: Folie 9「werden die Methode und das Programm abgebrochen」只在异常没有被处理时成立, 下一句其实就在说可以处理. 另外 Python 里没有 Java 那样的「main-Programm」, 指的是模块顶层调用 fact3 的代码; fact、fact2、fact3 也是函数, 不是方法 (Methode 属于类, 第 5 章).

Traceback einer Fehlermeldung lesen lernen, um herauszufinden, an welcher Stelle im Code ein Fehler aufgetreten ist.

调用栈 (第 12 章): 模块顶层调用 methode1, methode1 调用 methode2, methode2 里除以 0. Traceback 按「最近的调用在最后」(most recent call last) 列出每一层: 文件、行号、函数名和那一行代码; 最后一行是异常类型和信息. 读 Traceback: 先看最后一行 (什么错), 再往上看 (在哪里、怎么调用到那里的).

3.15 实测 (行号按幻灯片上的代码数): 

Traceback (most recent call last):
  File "f14.py", line 8, in <module>
    print(methode1())
          ~~~~~~~~^^
  File "f14.py", line 7, in methode1
    methode2()
    ~~~~~~~~^^
  File "f14.py", line 3, in methode2
    a = 42 / 0

  1. 报错信息「integer division or modulo by zero」不对: 42 / 0 是普通除法, Python 3 一直报 ZeroDivisionError: division by zero. 幻灯片的写法是 Python 2 或旧版 Python 3 里整数 //、% 的信息 (3.15 里它们也统一成了「division by zero」).
  2. 行号和代码对不上: 按幻灯片上的代码, print(methode1()) 在第 8 行、methode2() 在第 7 行, Traceback 却写 10 和 8. 只有第 3 行对.

避免异常
Vermeiden von Ausnahmen

Folie 15 
def fact4(n):
    if n < 0:
        raise ValueError("Eingabe darf nicht kleiner als 0 sein.")
    elif n == 0:
        return 1
    else:
        return n * fact4(n-1)
# Ausführung
m = ...
if m >= 0:
    k = fact4(m)
    print("Fakultät von " + str(m) + " ist " + str(k))
  • Die Ausnahme wird vermieden, indem vor dem Aufruf von fact4 getestet wird, ob das Argument größer gleich 0 ist.
  • Es kann (diesbezüglich) keine Ausnahme mehr ausgelöst werden.
    • Die Methode fact4 beinhaltet jedoch weiterhin eine Ausnahmeerkennung mit Ausnahmeauslösung, da sie nicht sicher ist, ob sie korrekt aufgerufen wird („defensive Programmierung“).

避免: 调用前先检查参数 (m ≥ 0 才调用), 这样就不会触发异常. 但 fact4 内部仍然保留检查和 raise: 函数不能假定每个调用者都会先检查. 这叫defensive Programmierung 防御式编程: 每个函数自己保护自己, 不信任输入.

抛出异常
Auslösen von Ausnahmen

Folie 16
  • Mittels der raise-Anweisung kann man eine Ausnahme auslösen.
  • Syntax: raise exp
  • Der Ausdruck exp muss eine Instanz einer von Exception abgeleiteten Klasse (d.h. eine Ausnahme oder ein Fehlerobjekt) bezeichnen.
  • Beispiel: raise ValueError(...)
  • Die Ausführung einer raise-Anweisung stoppt den Kontrollfluss der Methode und löst die von exp definierte Ausnahme aus. Die nachfolgenden Anweisungen im Rumpf der Methode werden nicht mehr ausgeführt (wie bei return)
  • Es kommt zu einem Abbruch des Programms, wenn die Ausnahme nicht in einer übergeordneten Methode abgefangen und behandelt wird.

raise 语句: raise 表达式, 表达式的值必须是一个异常对象, 即 Exception (或其子类) 的实例, 例如 ValueError("...").

  • raise 像 return 一样立即结束当前函数, 后面的语句不再执行. 区别: return 把值交给调用者, 调用者照常继续; raise 把异常沿调用栈往上传, 每一层都被中止, 直到某一层的 try/except 接住它.
  • 如果一直传到最外层都没人接, 程序中止并打印 Traceback.

细节: 严格说异常类的根是 BaseException; Exception 是它下面「普通错误」的那一支 (KeyboardInterrupt、SystemExit 直接继承 BaseException, 所以 except Exception 接不住 Ctrl+C). 也可以只写类名 raise ValueError, Python 会自动创建实例; 在 except 块里单独写 raise, 则把当前正在处理的异常重新抛出 (Folie 47).

Folie 17

Vermeiden von Programmabbruch

Beispiel: Der Ausdruck x / y kann nicht ausgewertet werden, wenn y den Wert 0 hat. In diesem Fall wird eine sogenannte Ausnahme (Exception) ausgelöst.

  • Ziel der Fehlerbehandlung dabei ist es solche zu vermeiden.
  • Eine vorherige Überprüfung ist nicht immer möglich.
  • Empfehlung: Im Nachgang auf Fehler zu reagieren, als diese bereits im Vorfeld abzufangen.
  • Im Folgenden lernen wir, wie wir im Code Fehlerbehandlung einbauen.

例: y 为 0 时 x / y 无法计算, Python 抛出异常. 错误处理的目标是避免程序中止. 但事先检查不总是可行 (例如「文件存在」这件事, 检查完到真正打开之间文件可能被删掉; 「字符串是不是合法整数」写检查代码比直接转换还麻烦).

建议: 出错后再反应 (先尝试, 失败了捕获异常), 而不是事先把每种错误都排除. Python 社区把这叫 EAFP (easier to ask forgiveness than permission, 请求原谅比请求许可容易), 与之相对的「先检查再做」叫 LBYL (look before you leap).

原文语法错误: 「Empfehlung: Im Nachgang auf Fehler zu reagieren, als diese bereits im Vorfeld abzufangen」缺了比较的另一半, 应为「Lieber im Nachgang auf Fehler reagieren, als diese bereits im Vorfeld abzufangen」. 「Ziel … ist es, solche zu vermeiden」中的「solche」指代不清, 从标题看指的是程序中止, 不是异常本身.

Fehlerbehandlung nach Entstehung

Folie 18

Ausnahmen (Instanzen der Klasse Exception)

  • Eine Ausnahme ist eine Instanz einer Klasse, die Informationen zum letzten Laufzeitfehler enthält.
  • In Python sind Laufzeitfehler ebenfalls Objekte.

Bemerkungen:

  • Ausnahmen können vom Programmierer im Programm durch Ausnahmebehandlung abgefangen werden (und sind vom Programmierer definierbar).
  • Ausnahmeobjekte werden vom Python-Laufzeitsystem automatisch erzeugt, wenn eine Fehlersituation auftritt.
  • Daher schreiben wir Code, der diese Instanz abfängt und nicht mehr weiterreicht.
  • Genau zu diesem Zweck existieren try-except-Blocks.

异常是一个对象: 某个异常类的实例, 里面装着关于这次运行时错误的信息 (类型、信息文本、发生位置). 出错时 Python 运行时系统自动创建它 (例如除以 0 时创建 ZeroDivisionError 对象), 程序员也可以自己创建并 raise, 还可以定义自己的异常类 (Folie 26).

处理异常 = 写代码接住这个对象, 不让它继续往上传到导致程序中止. 这就是 try-except 块的用途.

Folie 19

Ausnahmebehandlung in Python

for x in range(-3, 3):
    try:
        print(1/x)
    except ZeroDivisionError as e:
        print("Eine Ausnahme wurde abgefangen:", e)
  • Tritt während der Ausführung des try-Blocks eine Ausnahme der Klasse ZeroDivisionError auf, so wird der Code des entsprechenden except-Blocks ausgeführt; danach setzt Python die Ausführung mit der ersten Zeile nach dem try-except-Block fort.
  • Bemerkung: Ausnahmen haben eine hierarchische Struktur, d. h. manche Ausnahmen sind Spezialisierungen von anderen. So ist beispielsweise ZeroDivisionError eine Abwandlung von ArithmeticError.

x 取 −3 到 2. try 块里出现 ZeroDivisionError 时, 跳到对应的 except 块执行, 然后接着执行 try-except 之后的代码 (这里是下一轮循环), 程序不中止. as e 把异常对象绑定到变量 e, 打印 e 得到错误信息. 实际输出: 

-0.3333333333333333
-0.5
-1.0
Eine Ausnahme wurde abgefangen: division by zero
1.0
0.5

异常类构成继承层次 (第 7 章): ZeroDivisionError 是 ArithmeticError 的子类, ArithmeticError 又是 Exception 的子类 (实测 ZeroDivisionError.__mro__). except ArithmeticError 也能接住 ZeroDivisionError (Folie 37).

Folie 20

Ausnahmebehandlung in Python (2)

Mit Hilfe der Ausnahmebehandlung können wir robusten Code für das Lesen eines Integers von der Eingabe schreiben:

while True:
    try:
        n = input("Bitte gebe eine ganze Zahl ein: ")
        n = int(n)
        break
    except ValueError:
        print("Keine gültige Zahl, probiere es nochmals ...")
print("Großartig! Das war eine korrekte ganze Zahl")

健壮地读入整数 (Folie 11 的改进版): 无限循环, 每轮尝试转换; 成功就 break 跳出; 转换失败 (ValueError) 时, int(n) 后面的 break 不会执行, 打印提示后进入下一轮重新输入. 这就是 EAFP: 不去检查字符串是不是数字, 直接转, 失败了再说.

Folie 22

Behandlung von Ausnahmen: try und except (1)

  • Zunächst wird der try-Block normal ausgeführt.
  • Tritt im try-Block keine Ausnahmesituation auf, so wird der Block zur Ausnahmebehandlung ignoriert.
  • Tritt im try-Block eine Ausnahmesituation auf, so wird die Berechnung dieses Blocks abgebrochen.
    • Ist die Ausnahme vom abgefangenen Exception-Typ, so wird der Block nach dem except ausgeführt, und ggf. eine lokale Variable e für die Exception angelegt.
    • Ansonsten wird die Ausnahme weiter an die Aufrufstelle durchgereicht und evtl. dort behandelt
  • Insgesamt unbehandelte Ausnahmen brechen die Programmausführung letztendlich ab

try 语句的语法和执行规则:

  1. 先正常执行 try 块.
  2. 没有异常: 跳过 except 块.
  3. 有异常: try 块在出错的那一行中断 (后面的语句不再执行).
    • 异常类型和 except 后写的类型匹配 (是它或它的子类): 执行 except 块; 写了 as e 的话, 异常对象存进变量 e.
    • 不匹配: 异常继续传给调用者, 也许那里有 try 能处理它.
  4. 传到最外层仍无人处理: 程序中止.

except Exception 接住几乎所有错误 (因为它们都是 Exception 的子类). 一般应写尽量具体的类型, 只接住自己预料到并能处理的错误, 否则会把程序 bug 也悄悄吞掉 (Folie 25).

Folie 24–25

Welche Fehler abfangen?

Richtlinen:

  • “externe” Fehlerquellen immer abfangen und behandeln: falsche Benutzereingabe, Verbindungsabbruch, . . .
  • Konsequenzen aus logischen Programmfehlern niemals abfangen
    z.B. nicht jeden Aufruf von fact schützen
  • Oft besser: Ausprobieren und Abfangen statt vorher prüfen

该捕获哪些错误? 准则:

  • 外部错误来源 (用户输入错、连接中断……) 一定要捕获并处理, 因为程序员无法阻止它们发生.
  • 程序逻辑错误的后果绝不要捕获: 例如不要给每个 fact 调用都包一层 try. 如果某处用负数调用了 fact, 说明程序有 bug, 应该让它崩溃并修好代码, 而不是把错误吞掉.
  • 往往先尝试再捕获比事先检查好 (EAFP, Folie 17).

原文笔误: 「Richtlinen」应为「Richtlinien」(Folie 55 又写成「Richtline」). Folie 24 是只有标题的动画前一页.

Folie 26

Mittels Vererbung kann man eigene Ausnahmeklassen definieren

Dazu brauchen wir lediglich eine eigene Klasse zu erstellen, die von der Exception-Basisklasse Exception erbt, und dann ganz nach Anforderung weitere Attribute und Methoden zum Umgang mit Ihrer Exception hinzuzufügen.

Beispiel:

  • Klasse Konto.
  • Es soll nicht möglich sein, ein negativen Betrag einzuzahlen.
  • Implementierung:
class Konto:
    def __init__(self, betrag):
        if not betrag > 0:
            raise ValueError("Betrag muss größer als 0 sein")
        self.kontostand = betrag
    def abheben(self, betrag):
        self.kontostand -= betrag

用继承 (第 7 章) 定义自己的异常类: 写一个继承 Exception 的类, 按需要加属性和方法.

例子: 银行账户 Konto (第 5 章的例子). 构造时金额必须大于 0, 否则抛 ValueError (这一步还是用现成的异常类). abheben (取款) 目前没有任何检查, 可以把账户取成负数.

原文问题: 「ein negativen Betrag」应为「einen」; 「Ihrer Exception」突然换成敬称, 和前文「wir」不一致. 内容上, 说的是不能存入负数, 但条件 not betrag > 0 把 0 也拒绝了 (实测 Konto(0) 抛 ValueError), 和异常信息「muss größer als 0 sein」一致, 和「negativ」的说法不完全一致. 另外这里检查的是开户时的金额, 类里并没有「einzahlen 存款」方法.

Folie 28

Benutzerdefinierte Ausnahmen (3)

Wir modifizieren die Methode abheben der Klasse Konto dahingehend, dass bei einem ungültigen Abhebevorgang eine KontoException-Instanz geworfen wird.

class Konto:

    def __init__(self, betrag):
        if not betrag > 0:
            raise ValueError("Betrag muss größer als 0 sein")
        self.kontostand = betrag

    def abheben(self, betrag):
        if betrag > self.kontostand:
            raise KontoException(self.kontostand, betrag)
        self.kontostand -= betrag

不允许透支: 取款金额大于余额时, 抛出自己定义的 KontoException. 这个异常类继承 Exception, 额外存两个属性: 当时的余额和想取的金额, 处理异常的代码可以读取它们 (Folie 29). 自定义异常的好处: 调用者可以专门捕获「余额不足」, 和其他 ValueError 区分开.

Beispiel für Benutzerdefinierte Ausnahme

Beispiel für Benutzerdefinierte Ausnahme (3)

finally 块
Behandlung von Ausnahmen: finally

Folie 32

Manchmal möchte man Code nach der Ausführung des try-Blocks ausführen, unabhängig davon ob eine Ausnahme aufgetreten ist.

  • Beispiel: Schließen einer im try-Block geöffneten Datei
  • Das kann man mit einem finally-Block erreichen, der in jedem Fall nach dem try-Block un der Ausnahmebehandlung ausgeführt wird.
try:
    # Block für normalen Code
except Exception:
    # Ausnahmebehandlung falls Exception aufgetreten ist
finally:
    # Code der in jedem Fall ausgeführt werden soll (nach
    #   normalem, Ende, nach Ausnahmebehandlung und nach
    #   Auslösung einer nicht behandelten Ausnahme)

finally 块无论如何都会执行: try 正常结束后、except 处理完后, 甚至异常没被处理、要继续往上传之前 (先执行 finally, 再传). 典型用途: 释放资源, 如关闭文件、断开连接.

原文笔误: 「un der Ausnahmebehandlung」应为「und」; 注释里「nach normalem, Ende」多了逗号, 应为「nach normalem Ende」.

Beispiel mit finally

多个异常类型
Mehrteilige except-Blöcke

Folie 34

Hinter except darf auch ein Tupel von Fehlerklassen stehen, die dann jeweils mit demselben Code behandelt werden.

Wir können also beispielsweise schreiben:

except (Fehlerklasse1, Fehlerklasse2) as e:

Beispiel:

except (ZeroDivisionError, ValueError) as e:

Wenn ein Fehler auftritt, der auf wenigstens eine der Klassen im Tupel passt (im Beispiel also entweder ein ZeroDivisionError oder ein ValueError), betritt der Python-Interpreter die except-Umgebung und setzt nach dieser die Ausführung am Ende des try-except-Blocks fort.

except 后面可以写一个元组 (第 8 章), 列出多个异常类, 它们用同一段代码处理. 匹配其中任意一个就进入这个 except 块, 之后跳到整个 try-except 语句的后面继续.

Folie 35

Mehrere Ausnahme-Blöcke

Eine try-Anweisung kann mehr als ein except-Block für verschiedene Ausnahmen haben. Diese Schreibweise ermöglicht für jede Fehlerklasse einen eigenen Code zur Fehlerbehandlung zu schreiben:

try:
    # Block für normalen Code
except Exception1:
    # Kommt es zu Exception1, dann führe diesen Block aus
except Exception2:
    # Kommt es zu Exception2, dann führe diesen Block aus

Achtung: Es wird höchstens eine Ausnahmeblock ausgeführt. Dabei wird nur der erste except-Block abgearbeitet, der zur ausgelösten Ausnahme passt.

也可以写多个 except 块, 每种错误各有自己的处理代码. 规则: Python 从上到下依次检查, 只执行第一个匹配的块, 其余的跳过; 所以最多执行一个 except 块.

原文笔误: 「mehr als ein except-Block」应为「einen」(四格); 「höchstens eine Ausnahmeblock」应为「ein」.

Folie 37

Beispiel: Mehrere except-Blöcke

try:
    print(1/0)
except ArithmeticError as e:
    print("Arithmetic Unit Error")
except ZeroDivisionError as e:
    print("Division by Zero.")

# Ausgabe
Arithmetic Unit Error

答案: 1/0 抛出 ZeroDivisionError, 它也是 ArithmeticError (子类). 第一个 except 已经匹配, 所以输出「Arithmetic Unit Error」(实测), 第二个块永远执行不到. 正确的顺序: 具体的子类写在前面, 一般的父类写在后面.

Folie 38

Kombination von try, except und finally

finally und except können zusammen für denselben try-Block verwendet werden, wie im folgenden Python-Beispiel zu sehen ist:

try:
    x = float(input("Deine Zahl: "))
    inverse = 1.0 / x

except ValueError:
    print("Das war wohl kein Zahl!")

except ZeroDivisionError:
    print("Unendlich")

finally:
    print("""Vielleicht ist eine Ausnahme
    aufgetreten oder auch nicht.""")

print("Die inverse Zahl: ", inverse)

两个 except 分别处理「输入不是数」和「输入是 0」, finally 总会执行. 实测三种输入:

  • 4: 打印 finally 的文字, 然后「Die inverse Zahl: 0.25」.
  • abc: 「Das war wohl kein Zahl!」, finally 的文字, 然后 NameError.
  • 0: 「Unendlich」, finally 的文字, 然后 NameError.

幻灯片代码错误: 出现异常时, inverse = 1.0 / x 没有执行完, inverse 从未被赋值. 异常虽然被处理了, 但最后一行 print(..., inverse) 随即报 NameError: name 'inverse' is not defined (实测), 程序还是崩溃. 这正好违反了本章「健壮」的目标. 改法: 把最后的 print 放进 else 块 (Folie 49), 或在 except 块里给 inverse 一个值. 另外「kein Zahl」应为「keine Zahl」. 三引号字符串里第二行的缩进空格会原样输出.

Folie 40

Datei öffnen

Beachte:

  • Die Funktion "open()" benötigt zwei Parameter: Dateiname und Modus.
  • Dateiname ist ein String, der den Namen der Datei enthält, die geöffnet werden soll.
  • Die Datei wird im aktuellen Arbeitsverzeichnis erwartet, d. h. in dem Ordner, von dem aus Python auch gestartet wurde, ansonsten muss der Pfad zur Datei mit der Dateiname mitgegeben werden.
  • Unter Modus verstehen wir, für welche Art Zugriff die Datei geöffnet werden soll. Wollen wir aus der Datei Lesen oder Schreiben? Soll der Zugriff im Text- oder Binärmodus stattfinden? Der Modus wird durch einen String beschrieben.
  • Im Folgenden sehen wir die wichtigsten Modi zum Öffnen einer Datei.

文件是异常的典型来源 (文件可能不存在、没有权限), 所以在这里顺便介绍. 内置函数 open(文件名, 模式) 返回一个文件对象 (handle, 句柄), 之后的读写都通过它的方法进行.

  • 文件名是字符串; 只写文件名时, 在当前工作目录里找, 否则要写路径 (如 "daten/meineDatei.txt").
  • 模式也是字符串: 读还是写、文本还是二进制.

幻灯片说法不准确: open 是函数不是方法 (Folie 39 的注释「mit der Methode open」, 同页最后一句又说 Funktion); 而且 open() 只有文件名是必需的, 模式可以省略, 默认 "r" (即 "rt"), Folie 41 的表也写着 r 是 Standardwert, 和「benötigt zwei Parameter」矛盾. 「mit der Dateiname」应为「dem Dateinamen」.

Teile der Datei Lesen

  • Standardmäßig gibt die Methode read() den gesamten Text zurück.

#Gib die ersten 6 Zeichen der Datei zurück:

  • read(size) verschiebt den “Cursor”, also die aktuelle Leseposition
  • read(): 一次读出整个文件, 得到一个字符串.

Folie 45

Zeilen aus einer Datei lesen (1)

  • Verwandt mit der Methode readline ist die Methode readlines
  • Diese liest die gesamte Datei, zerlegt sie dabei aber bereits an den Zeilenumbrüchen, und packt die Teile der Datei in einer list
  • Beispiel:
# Text/Lesemodus
datei = open("meineDatei.txt", "rt")

lines = datei.readlines()

datei.close() # Methode zum Schließen einer Datei

for line in lines:
    print(line)
  • readline(): 从当前位置读到下一个换行符 (包括换行符 \n), 返回一行. 读到文件末尾时返回空字符串 ''. 参数 size 限制最多读多少个字符.
  • readlines(): 读出所有行, 返回一个列表, 每个元素是一行 (同样带 \n). 实测: ['Hallo! Willkommen bei Python!\n', 'Das ist eine Testdatei.\n', 'Viel Spass!\n'].
  • close(): 关闭文件, 释放资源; 写文件时还保证数据真正写到磁盘.

注意: Folie 45 的循环实际输出时每行之间多一个空行 (实测), 因为 line 自带 \n, print 又加一个. 去掉的办法: print(line, end="") 或 print(line.rstrip("\n")).

更 Python 的逐行读法是直接遍历文件对象: for line in datei:, 一次只读一行进内存, 适合大文件.

Folie 46

Dateien Schreiben

  • Sobald eine Datei in einem Text-Schreibmodus geöffnet wurde (w, x oder a), und solange sie noch nicht wieder geschlossen wurde, können wir mit der Methode write Text in eine Datei schreiben.
  • Syntax: handle.write(text)
  • Beispiel:
# Text/Schreibmodus
datei = open("meineDatei2.txt", "wt")

datei.write("Some text\n")
datei.write("another line" * 2 + "\n")
datei.write(str(datei))

datei.close()

write(text) 把字符串写入文件. write 不会自动换行, 需要自己写 \n. 实测文件内容: 

Some text
another lineanother line
<_io.TextIOWrapper name='meineDatei2.txt' mode='wt' encoding='utf-8'>

第二行: 字符串 * 2 是重复两次 (第 3 章), 中间没有空格. 第三行: str(datei) 是文件对象自身的文本表示, 可以看到文件名、模式和编码 (encoding 随系统而定). write 只接受字符串, 写数字要先 str().

Folie 47

Beispiel mit mehreren Ausnahme-Blöcke

try:
    f = open("integers.txt")
    s = f.readline()
    i = int(s.strip())
except IOError as e:
    errno, strerror = e.args
    print("Zugriff auf Datei nicht moeglich")
    print("I/O error(" + str(errno) + "): " + str(strerror))
    # e can be printed directly without using .args:
    # print(e)
except ValueError:
    print("Keine gueltige ganze Zahl.")
    raise
finally:
    f.close()

读文件第一行并转成整数, 可能出两类错: 文件打不开 (IOError, 即 OSError) 和内容不是整数 (ValueError).

  • OSError 的 e.args 是 (错误号, 错误描述), 文件不存在时为 (2, 'No such file or directory').
  • s.strip() 去掉首尾空白 (包括行末的 \n).
  • ValueError 块里单独的 raise: 打印提示后把同一个异常重新抛出, 交给上层处理.

实测三种情况: 文件内容 "42" → 正常, i = 42; 内容 "abc" → 打印「Keine gueltige ganze Zahl.」后 ValueError 继续往上抛 (这是有意的); 文件不存在 → 见下面红框.

幻灯片代码错误 (Folie 47、48、50、51 同一个问题): open() 本身失败时, 变量 f 从未被赋值. except 块执行完后进入 finally, f.close() 报 NameError: name 'f' is not defined (实测; Folie 51 是 fh). 新异常盖过了刚刚处理好的 IOError, 程序还是崩溃. 正确写法是把 open 放在 try 外面 (或单独一个 try), 只在打开成功后才进入带 finally 的 try; 最简单的是用 with (Folie 52). 另外 IOError 只是 OSError 的旧别名 (实测 IOError is OSError 为 True), 新代码写 OSError 或 FileNotFoundError; 标题「mehreren Ausnahme-Blöcke」应为「Blöcken」.

Folie 48

Beispiel mehrteiliger except-Block

Ein except-Block kann mehr als eine Ausnahme in einem Tupel von Fehlernamen nennen, wie wir im folgenden Beispiel sehen können:

try:
    f = open('integers.txt')
    s = f.readline()
    i = int(s.strip())
except (IOError, ValueError):
    print("Keine gueltige ganze Zahl.")
    raise
finally:
    f.close()

同一个例子, 用元组把两种错误合在一个 except 里 (Folie 34). 缺点: 文件不存在时也打印「Keine gueltige ganze Zahl」, 提示是误导性的 (实测); 而且同样有上面红框的 NameError 问题. 两种错误需要不同的反应时, 应分成两个 except 块.

else 块
Ausnahme mit Else-Block

Folie 49
  • Die try ... except-Anweisung hat einen optionalen else-Block.
  • Ein else-Block muss nach allen except-Blöcken platziert werden.
  • Ein else-Block wird ausgeführt, wenn der try-Block keine Ausnahme auslöst.
try:
    Block fuer normalen Code
except exceptions:
    # Kommt es zu exceptions, dann führe diesen Block aus
else:
    # Gibt es keine Ausnahme, dann führe diesen Block aus.

可选的 else 块写在所有 except 之后 (finally 之前): 只有 try 块没有抛出异常时才执行. 完整顺序: 

try:      # 可能出错的代码
except …: # 出错时 (可多个)
else:     # 没出错时
finally:  # 无论如何

为什么不把 else 的代码直接写在 try 的末尾? 因为那样它出的错也会被 except 接住, 而那些错并不是我们想处理的. try 块里只放真正可能出错的那一两行.

Folie 50

Beispiel Datei Schreiben mit else-Block

try:
    f = open("testdatei", "w") #
    f.write('Test schreibe dies')
except IOError:
    # Dies findet nur statt wenn ein IOError
    #    aufgetreten ist
    print("Error: Konnte die Datei nicht beschreiben oder lesen")
else:
    print("Datei erfolgreich beschrieben")
finally:
    f.close()

写文件: 成功时 else 打印「Datei erfolgreich beschrieben」, 失败时 except 打印错误提示 (「oder lesen」多余, 这里只写不读). finally 关闭文件. 若 open 失败 (例如目录不存在), 同样在 finally 里出现 NameError (实测, 见 Folie 47 的红框).

Folie 51

Beispiel Datei Lesen mit else-Block

Wenn es mit dem Öffnen der Datei klappt, wird die Ausführung mit dem else-Block fortgesetzt. Erfolgt jedoch eine Ausnahme, wird der else-Block übersprungen:

import sys
filename = "4-fibonacci.py"
text = []
try:
    fh = open(filename, 'r')
except IOError:
    print('Datei laesst sich nicht oeffnen', filename)
else:
    text = fh.readlines()
finally:
    fh.close()
if text:
print(text[6])
# Ausgabe
return fib(n-1) + fib(n-2)

读文件: 打开成功 → else 块读出所有行; 失败 → 打印提示, 跳过 else. 最后若列表非空, 打印第 7 行 (下标 6). 文件 4-fibonacci.py 是一个 fib 函数, 第 7 行正是 return fib(n-1) + fib(n-2). try 里只放了 open, 读取放在 else 里, 正是 Folie 49 讲的好习惯.

幻灯片代码错误:

  1. print(text[6]) 没有缩进, 和 if text: 对齐 (PDF 里两行的 x 坐标相同), 照抄运行报 IndentationError: expected an indented block after 'if' statement (实测). 应缩进到 if 下面.
  2. 文件打不开时, finally 里的 fh.close() 报 NameError (实测, 同 Folie 47).
  3. import sys 没有用到.
  4. 实际输出 text[6] 时, 这一行自带缩进和行末的 \n, 所以前面有空格、后面多一个空行 (实测); 幻灯片的「Ausgabe」省略了缩进.

with 语句
with-Anweisung

Folie 52

Anstelle von try-finally-Blöcken verwenden wir die with-Anweisung.

Hier ist ein Beispiel mit einer Datei:

def ausgabeText(filename):
    text = []
    with open(filename, 'r') as fh:
        text = fh.readlines()
    if text:
        print(text[6])

ausgabeText("4-fibonacci.py")

Selbst wenn ausgabeText eine Ausnahme auslöst, wird die Datei sofort ordnungsgemäß geschlossen, wenn der Bereich des with-Blocks beendet wird, unabhängig davon, ob die Ausnahme behandelt wurde oder nicht.

with 语句: with open(...) as fh: 打开文件并绑定到 fh; 离开 with 块时 (不管是正常结束还是因为异常) 文件自动关闭. 它代替了「try … finally: fh.close()」, 而且没有 Folie 47 的 NameError 问题: open 失败时根本不会进入 with 块, 也就没有要关闭的文件. 实测输出和 Folie 51 相同.

注意 with 本身不处理异常: 文件不存在时 FileNotFoundError 照样往上传. 要处理, 就在外面再套 try/except. 读写文件时都应该用 with.

表述不准确: 「Selbst wenn ausgabeText eine Ausnahme auslöst」: 只有在 with 块内部发生的异常才和关闭文件有关; 若异常发生在 with 块之后 (如 text[6] 下标越界), 文件早已关闭.

Folie 53

Kombination aus try, except, else und finally

def int_frage():
    """Funktion zum Erfragen eines Integerwerts."""

    while True:
        try:
            wert = int(input("Bitte gebe eine Zahl ein: "))
        except:
            print("Sieht aus, als ob du keine Zahl eingegeben hast!")
            continue
        else:
            print("Ja, das war eine Zahl!")
            break
        finally:
            print("Aber immerhin wurde ich ausgefuehrt!")
        print(wert)

四个块都用上: 输入不是整数 → except 打印提示, continue 开始下一轮; 是整数 → else 打印确认, break 跳出循环. 不管哪种, finally 都在 continue / break 真正生效之前执行. 实测输入 "abc" 再输入 "7": 

Bitte gebe eine Zahl ein: Sieht aus, als ob du keine Zahl eingegeben hast!
Aber immerhin wurde ich ausgefuehrt!
Bitte gebe eine Zahl ein: Ja, das war eine Zahl!
Aber immerhin wurde ich ausgefuehrt!

幻灯片代码问题:

  1. 最后的 print(wert) (和 try 同一缩进, 在循环内) 永远不会执行: except 分支以 continue 结束, else 分支以 break 结束, 两条路都跳过它 (实测从未打印).
  2. 函数名叫「erfragen 询问整数」, 却没有 return wert, 调用结果是 None (实测). 应把 print(wert) 换成循环后的 return wert.
  3. 裸 except: 接住所有异常, 包括 Ctrl+C (KeyboardInterrupt): 用户想中止程序时只会看到「keine Zahl」并被要求重输, 违反 Folie 25「只捕获预料到的错误」. 应写 except ValueError:.

assert 语句
Assert-Anweisung

Folie 54
  • Die assert-Anweisung ist für Debug-Aufgaben bestimmt
  • Sie kann als abgekürzte Schreibweise für eine bedingte raise-Anweisung angesehen werden, d.h. eine Ausnahme wird nur dann generiert, wenn eine bestimmte Bedingung nicht wahr ist.
  • Ohne die assert-Anweisung: 
    if not <some_test>:
    raise AssertionError(<message>)
  • Semantisch äquivalent mit der assert-anweisung: 
    assert <some_test>, <message>
  • Falls <some test> als False ausgewertet wird, wird eine Ausnahme generiert und <message> wird ausgegeben.
Folie 55

Beispiel mit Assert-Anweisung

Beispiel:

y = sqrt(x)
assert y >= 0, "unexpected result of sqrt"

Richtline:

  • assert sollte in einem korrekten Programm niemals fehlschlagen
  • assert hilft dabei, Programmierfehler frühzeitig zu entdecken

Nutzen Sie assert, um Ihre Erwartungen zu dokumentieren, die ein korrekter Programmcode immer erfüllen sollte

  • Überprüfen von Ergebnissen einer Berechnung
  • Strukturelle Eigenschaften von Datenstrukturen

Beispiel: Indizes in binary search (DEMO)

assert 条件, 信息: 条件为假时抛出 AssertionError(信息), 相当于一个带条件的 raise. 用途是调试: 写下「如果程序正确, 这里一定成立」的假设, 例如计算结果的性质 (平方根不为负)、数据结构的性质 (有序树左小右大)、二分查找里 low ≤ high 之类的下标关系.

与 raise 的分工:

  • raise: 处理外部的、可能真的会发生的错误 (用户输入、文件), 是程序正常逻辑的一部分.
  • assert: 检查内部的、正确程序中绝不应失败的条件. 一旦失败, 说明有 bug (第 11 章 pytest 的测试也用 assert).

用 python -O (优化模式) 运行时, 所有 assert 语句都会被跳过 (实测 assert False 不报错). 所以 assert 不能用来检查用户输入或做必要的错误处理, 那些要用 if + raise. 也因为这一点, 严格说 assert 只在默认 (调试) 模式下和 Folie 54 的 if-raise 等价.

原文笔误: 「assert-anweisung」应大写「Anweisung」; 「<some test>」与上面的 <some_test> 不一致; 「Richtline」应为「Richtlinie」.
