Folie 8

Wir unterscheiden den Zeitbedarf und den Speicherplatzbedarf eines Algorithmus.

Beides hängt ab von

  • den verwendeten Datenstrukturen,
  • den verwendeten algorithmischen Konzepten (z.B. Schleifen),
  • der verwendeten Rechenanlage zur Ausführungszeit (davon abstrahieren wir im Folgenden).
Folie 9

Zeit- und Speicherplatzbedarf

  • Der Zeitbedarf eines Algorithmus errechnet sich aus dem Zeitaufwand für
    • die Auswertung von Ausdrücken, einschl. Durchführung von Operationen,
    • die Ausführung von Anweisungen,
    • organisatorischen Berechnungen (davon abstrahieren wir im Folgenden).
  • Der Speicherplatzbedarf eines Algorithmus errechnet sich aus dem benötigten Speicher für
    • lokale Variable (einschließlich formaler Parameter)
    • Objekte (einschließlich Listen) und deren Attribute,
    • organisatorische Daten (davon abstrahieren wir im Folgenden).

区分Zeitbedarf 时间需求和Speicherplatzbedarf 空间需求. 两者都取决于所用的数据结构、算法结构 (如循环), 以及运行的机器; 机器因素我们忽略 (abstrahieren).

  • 时间 = 求值表达式和执行运算 + 执行语句 (+ 管理性的计算, 忽略). 我们把每个基本操作 (一次比较、一次赋值、一次列表访问……) 都算作1 个单位.
  • 空间 = 局部变量 (含形参) + 对象 (含列表) 及其属性 (+ 管理数据, 忽略). 每个变量、每个列表元素算 1 个单位.

Folie 11

Beispiel: Lineare Suche eines Elements in einer Liste (3)

linSearch(liste, element):
    i=0
    while i < len(liste):
        if liste[i] == element:
            return True
        i +=1
    return False

Sei n = len(liste) und e bereits eine Zahl. Wir schätzen den maximalen Zeitbedarf des Aufrufs linSearch(liste,e) ab

  • 1 für den ersten Schritt i = 0
  • pro Schleifendurchlauf (n mal):
    • Für len(liste): 1 Zugriff + 1 Vergleich
    • Für liste[i] == element: 1 Listenzugriff + 1 Vergleich
    • Für i+=1: 1 Operation (i+1) + 1 Zuweisung i = ...
  • letzter Test i < len(liste): 1 Listenzugriff + 1 Vergleich
  • Aufruf return False: 1 Return

Ergibt: 1 + n · (1 + 1 + 1 + 1 + 1 + 1) + 2 + 1 = 6 · n + 4

改写成 while 循环, 每一步都看得见, 方便数步数. 设列表长度 n, 估计最多要多少步 (元素不存在时):

部分步数
i = 01
每轮循环: 条件 i < len(liste) (取长度 + 比较)2
每轮循环: liste[i] == element (列表访问 + 比较)2
每轮循环: i += 1 (加法 + 赋值)2
最后一次条件判断 (为假, 退出)2
return False1

总计 1 + 6n + 2 + 1 = 6n + 4. 数法的细节 (算 1 还是 2) 不重要, 后面用 O 记号时常数都会被忽略; 重要的是「步数和 n 成正比」.

复杂度分析
Komplexitätsanalyse

Folie 13
  • Der Zeitbedarf und der Speicherplatzbedarf einer Methode hängt i.A. ab von der aktuellen Eingabe.
  • Gegeben sei eine Methode def m(x): body
    Notation: Tm​(e) = Zeitbedarf des Methodenaufrufs m(e)
    Sm​(e) = Speicherplatzbedarf des Methodenaufrufs m(e)
  • Meist ist man am Skalierungsverhalten eines Algorithmus interessiert: Wie hängen Zeit- und Speicherplatzbedarf von der Größe n der Eingabe e ab (z.B. von der Länge einer Listen)?
  • Der Algorithmus zum Suchen eines Elements in einer Liste hat für Listen gleicher Länge unterschiedliche Kosten bzgl. der Zeit.
  • Um solche Unterschiede abschätzen zu können, unterscheidet man die Komplexität im schlechtesten, mittleren und besten Fall (engl. worst case, average case, best case complexity).

记号: Tm​(e) 是调用 m(e) 的时间, Sm​(e) 是空间. 我们关心的是Skalierungsverhalten 伸缩行为: 输入规模 n (如列表长度) 变大时, 时间和空间怎样增长. 同样长度的列表, 查找的时间也可能不同, 所以分最坏、平均、最好三种情况.

Folie 14

Komplexitätsarten

Zeitkomplexität im

  • schlechtesten Fall (worst case): Tm​w(n) = max{Tm(e) | Größe von e ist n}
  • mittleren Fall (average case): Tm​a(n) = Durchschnitt von {Tm(e) | Größe von e ist n}
  • besten Fall (best case): Tm​b(n) = min{Tm(e) | Größe von e ist n}

Speicherplatzkomplexität im

  • schlechtesten Fall (worst case): Sm​w(n) = max{Sm(e) | Größe von e ist n}
  • mittleren Fall (average case): Sm​a(n) = Durchschnitt von {Sm(e) | Größe von e ist n}
  • besten Fall (best case): Sm​b(n) = min{Sm(e) | Größe von e ist n}

在所有规模为 n 的输入中: 最坏情况取最大值, 平均情况取平均值, 最好情况取最小值. 时间和空间各有这三种, 上标 w / a / b 分别表示 worst / average / best.

实践中最常用的是最坏情况: 它给出一个保证 (无论输入怎样都不会更慢). 平均情况要先假设输入的概率分布, 计算更难.

Schlechtester Fall: TwlinSearch(n) = 6n + 4

Bester Fall: TblinSearch(n) = 6

Folie 18

Beispiel: Lineare Suche, Zeitbedarf (2)

(Code wie Folie 11; Schlechtester Fall: 6n + 4, Bester Fall: 6)

Durchschnittlicher Fall:

  • Wir nehmen an, dass das Element nach 1 bis n Schleifendurchläufen gefunden wird, und dass jeder dieser Fälle gleich wahrscheinlich ist.
  • Laufzeit bei j Schleifendurchläufen:
    6 · j (für die Schleifendurchläufe)
    + 2 (für i = 0 und return True)
    − 2 (für letzten Schleifendurchlauf erfolgt keine i+=1)

TalinSearch(n) = (∑j=1n 6 · j) / n = 6 · (n + 1)n / 2 · 1/n = 3n + 3

平均情况: 假设元素一定存在, 在第 1 到第 n 个位置的概率相同. 在第 j 个位置找到时: j 轮循环 6j, 加上 i = 0 和 return True 的 2, 减去最后一轮没有执行的 i += 1 的 2, 正好 6j. 对 j = 1…n 求平均:

(6 + 12 + … + 6n) / n = 6 · n(n+1)/2 / n = 3(n + 1) = 3n + 3

用了求和公式 1 + 2 + … + n = n(n+1)/2 (第 4 章的 5050). 结论: 平均大约要看一半的元素, 仍和 n 成正比. 检查: j = 1 时 6j = 6, 和最好情况一致.

复杂度的数量级: O 记号
Größenordnung der Komplexität: Die O-Notation

Folie 19
  • Eine exakte Beschreibung des Zeit- und Speicherplatzbedarfs wird schnell zu kompliziert, um praktikabel zu sein.
  • Die Komplexität der Funktionen Tw(n),Ta(n),Tb(n),Sw(n),Sa(n) und Sb(n) wird häufig nur bis auf konstante Faktoren untersucht.
  • Sei f:N→N eine Funktion. Wir definieren O(f(n)) als die Klasse aller Funktionen, die nicht wesentlich schneller wachsen als f(n):
Definition (O(f(n)))
Eine Funktion g(n) ist in O(f(n)), falls es Zahlen c > 0 und n0​ gibt, so dass 0≤g(n)≤c⋅f(n) für alle n>n0​.

D.h. die Funktion g(n) wächst höchstens so schnell wie f(n), abgesehen von einer linearen Skalierung von f(n).

精确的步数 (6n + 4) 太繁琐, 而且依赖于怎么数. 所以只看数量级, 忽略常数因子.

定义: g(n)∈O(f(n)) (读作「g 属于大 O f」), 如果存在常数 c > 0 和 n0​, 使得对所有 n>n0​, 都有 0≤g(n)≤c · f(n).

含义: 从某个 n0​ 之后, g 永远不超过 f 的 c 倍. 也就是 g 的增长至多和 f 一样快 (允许乘一个常数). 「足够大的 n 之后」这个条件让我们可以不管小 n 时的情况. O(f) 是一个上界: 6n+4∈O(n), 同时也 ∈ O(n²) (只是不够精确).

Folie 20

O-Notation: Beispiele

  • TwlinSearch(n) ist in O(n), denn TwlinSearch(n) = 6n + 4 und c = 7 und n0​=3 erfüllen die Definition:
    0≤6n+4≤6n+n=7⋅n für alle n > 3
  • SwlinSearch(n) ist in O(1), denn SwlinSearch(n) = 2 und c = 1000 und n0​=10000 erfüllen die Definition:
    0≤2≤1000⋅1 für alle n > 10000

证明 g∈O(f) 就是找出一组 c 和 n0​:

  • 6n+4≤7n 等价于 4≤n, 所以 n > 3 时成立: c=7,n0​=3. 技巧: 把常数项 4 换成 n (n 足够大时 4 ≤ n).
  • 常数 2≤1000⋅1 对所有 n 都成立. 这里故意取了很大的 c 和 n0​, 说明它们只要存在就行, 不必最小 (c = 2、n0​=0 也可以). O(1) 表示「常数, 和 n 无关」.
Folie 21

O-Notation: Beispiele (2)

  • g(n)=n2+10n+20 ist in O(n2), denn mit c = 31 und n0​=1:
    0≤n2+10n+20≤n2+10n2 + 20n2 = 31⋅n2 für alle n > 1
  • g(n)=n3 ist nicht in O(n2):
    Es gibt kein c und n0​, die die Definition erfüllen, denn aus 0≤n3≤c⋅n2 folgt n≤c und es gibt immer ein n, dass das verletzt!
  • 多项式: n≥1 时 n≤n2、1≤n2, 所以每一项都可以放大成 n2 的倍数, 系数相加 1 + 10 + 20 = 31.
  • 反证 n3∈/O(n2): 如果 n3≤c⋅n2 对所有大 n 成立, 两边除以 n2 得 n≤c, 但 n 可以比任何固定的 c 都大 (例如 n = c + 1), 矛盾.

原文笔误: 「es gibt immer ein n, dass das verletzt」应为关系代词「das das verletzt」.

Folie 22

Rechnen mit der O-Notation

  1. Wenn g(n) in O(f(n)) ist, dann gilt für jede Konstante c
    g(n) + c in O(f(n)) und c · g(n) ist in O(f(n))
  2. Wenn g1​(n) und g2​(n) jeweils in O(f(n)) sind, dann gilt auch: g1​(n)+g2​(n) ist in O(f(n))
  3. Sei g1​(n) in O(f1​(n)) und g2​(n) in O(f2​(n)). Dann gilt:
    h(n)=g1​(n)+g2​(n) ist in O(f1​(n)+f2​(n))
    k(n)=g1​(n)⋅g2​(n) ist in O(f1​(n)⋅f2​(n))
  4. Sei f(n) in O(g(n)) und g(n) in O(h(n)). Dann ist f(n) in O(h(n)).
  5. Sei g(n)=pk​⋅nk+pk−1​⋅nk−1+…+p0​ ein Polynom von Grad k. Dann ist g(n) in O(nk)

O 记号的计算规则 (做复杂度分析时直接用):

  1. 加一个常数、乘一个常数, 数量级不变: 6n+4∈O(n).
  2. 同一数量级的两项相加, 仍是这个数量级.
  3. 相加取各自上界之和, 相乘取乘积. 对程序: 两段代码先后执行, 复杂度相加 (实际上取较大者, 因为 O(n + n²) = O(n²)); 循环嵌套, 复杂度相乘: 外层 n 次、内层 n 次 → O(n · n) = O(n2).
  4. 传递性: f∈O(g) 且 g∈O(h), 则 f∈O(h).
  5. k 次多项式属于 O(nk): 只看最高次项, 系数和低次项都不重要 (Folie 21 是 k = 2 的例子).

规则 1 里的「加常数」有个隐含条件: f(n) 从某处起至少是一个正常数 (否则 c 加上去就没法被 c·f(n) 盖住, 例如 f(n) = 0). 本课里 f 总是 1、log n、n 这类函数, 不会出问题. 「乘常数」中的常数应理解为正数.

Exponentielle und polynomielle Komplexität

Folie 26

Problem des „Handelsreisenden“ (Traveling-Salesman-Problem)

Gegeben sei ein Graph mit n Städten und den jeweiligen Entfernungen. Finde eine kürzeste Tour, so dass jede Stadt einmal besucht wird.

Für dieses Problem sind nur Algorithmen mit exponentieller Zeitkomplexität bekannt („alle Möglichkeiten ausprobieren“)

旅行商问题 (TSP): 给定 n 座城市和两两之间的距离, 找一条经过每座城市恰好一次 (并回到起点) 的最短路线. 图里红色的路线 S1–S2–S3–S4–S6–S5–S7–S1 总长 7 + 2 + 5 + 7 + 4 + 2 + 12 = 39.

已知的精确算法本质上都要尝试指数级的可能 (穷举所有排列有 (n−1)!/2 种路线, 比指数还快). n = 7 时还能算, n = 50 就不可能穷举了.

Folie 27

Bemerkungen zu TSP

  • Für das Traveling-Salesman-Problem gibt es einen nichtdeterministischen polynomiellen (NP) Algorithmus („man darf die richtige Lösung raten“)
  • Das Traveling-Salesman-Problem ist NP-vollständig:
    Falls es einen polynomiellen Algorithmus zu seiner Lösung gibt, so hat jeder nichtdeterministisch-polynomielle Algorithmus eine polynomielle Lösung.
  • Die Frage, ob ein NP-vollständiges Problem (und damit alle) in polynomieller Zeit (P) gelöst werden kann, ist eine der bekanntesten ungelösten Fragen der theoretischen Informatik „P = NP“
  • Das „P = NP“ ist eines der sieben sogenannten Millennium-Probleme
  • NP (nichtdeterministisch polynomiell): 如果允许「猜」出正确答案, 就能在多项式时间内验证它. 对 TSP: 给一条路线, 很快就能算出它的长度并检查是否不超过某个界.
  • NP-vollständig NP 完全: NP 中「最难」的问题. 只要有一个 NP 完全问题能在多项式时间内解决, 所有 NP 问题都能.
  • P = NP? 是否每个能快速验证的问题也能快速求解? 至今未解决, 是理论计算机科学最著名的开放问题, 也是七个「千禧年大奖难题」之一 (Clay 研究所悬赏一百万美元).

严格说, NP 完全的是 TSP 的判定版本 (「是否存在长度 ≤ L 的路线?」); 求最短路线的优化版本叫 NP-schwer (NP 难). 这个区别本课不要求.

二分查找
Binäre Suche in einer geordneten Liste

Folie 29

Sei liste ein geordnetes Liste mit den Grenzen j und k, d.h. liste[i] < liste[i+1] für i = j, …, k; also z.B.:

liste:  3   7   13  15  20  25  28  29
        j  j+1  ···                  k

Algorithmus:
Um den Wert e in a zu suchen, teile die Liste in der Mitte und vergleicht e mit dem Element liste[mid] in der Mitte

  • Ist e < liste[mid], dann suche weiter im linken Teil liste[j]...liste[mid-1].
  • Ist e = liste[mid], dann hat man das Element gefunden.
  • Ist e > liste[mid], dann suche weiter im rechten Teil liste[mid+1]...liste[k].

Binäre Suche 二分查找: 前提是列表已排序. 看中间的元素: 要找的值更小, 就只在左半边继续找; 更大就在右半边; 相等就找到了. 每一步把查找范围减半. j 和 k 是当前范围的左右边界.

例: 在 [3, 7, 13, 15, 20, 25, 28, 29] 里找 25: mid = 3 (15), 25 > 15 → 右半 [20, 25, 28, 29]; mid = 5 (25) → 找到, 共 2 步. 找 4 要 3 步才确定不存在.

原文小错: 「liste[i] < liste[i+1] für i = j, …, k」, i = k 时 liste[k+1] 已越界, 应为 i = j, …, k−1. 「um den Wert e in a zu suchen」里的 a 应为 liste (旧版课件用数组 a); 「teile … und vergleicht」应为「vergleiche」; 「ein geordnetes Liste」应为「eine geordnete Liste」.

Folie 30

Binäre Suche in Python

def binarySearch(liste, element):
    j = 0                          # linke Grenze
    k = len(liste) - 1             # rechte Grenze

    # solange element nicht gefunden und liste leer
    while j <= k:
        mid = j + (k-j) //2        # Mitte der Liste bzw. links davon
        if element < liste[mid]:   # element kleiner als das mittlere?
            k = mid -1             # ja, mache mit rechtem Teil weiter.
        elif element > liste[mid]: # element größer als das mittlere?
            j = mid +1             # ja, mache mit rechtem Teil weiter.
        else:
            return True            # sonst: gefunden
    return False

# Beispiel
  • mid = j + (k-j)//2: 范围中点 (元素个数为偶数时取中间偏左的那个). 等价于 (j+k)//2.
  • 更小 → k = mid - 1, 右边界左移, 继续在左半找; 更大 → j = mid + 1, 继续在右半找. mid 本身已经比较过, 所以 ±1 把它排除.
  • while j <= k: 范围非空就继续; j > k 时范围为空, 说明不存在.

实际运行: 在上面的列表里找 25 → True (2 轮), 找 4 → False (3 轮), 找 3 → True (3 轮).

幻灯片小错 (注释): 「solange element nicht gefunden und liste leer」应为「… und der Bereich nicht leer」(循环条件 j≤k 正是「范围非空」). k = mid -1 后面的注释写的是「mache mit rechtem Teil weiter」, 实际是继续查左半部分 (右边界左移), 应为「linkem Teil」.

Folie 32

Wie oft wird die while-Schleife maximal durchlaufen?

Beispiel: In einer Liste der Größe 16 braucht man maximal 5 Durchläufe.

  • Eine Liste der Länge n mit 2i≤n<2i+1 benötigt man im schlechtesten Fall i + 1 Schleifendurchläufe
  • Sei log2(n) der ganzzahlige Anteil des Logarithmus zur Basis 2
  • Es gilt 2log2(n) ≤ n < 2log2(n)+1
  • Daher braucht man im schlechtesten Fall log2(n) + 1 Durchläufe.

每轮循环范围至少减半: 16 → 8 → 4 → 2 → 1, 最多 5 轮. 一般地, 长度 n 满足 2i≤n<2i+1 时, 最坏要 i + 1 轮, 即 ⌊log2 n⌋ + 1 轮. 用脚本对 n = 1, 2, 3, 15, 16, 17, 1000 实际数过最坏轮数, 全部吻合 (例如 n = 1000 时 10 轮).

直观: 1000 个元素最多 10 次比较, 一百万个元素最多 20 次. 而线性查找要一百万次.

Worst-Case-Komplexitäten der Suchalgorithmen

Laufzeitkomplexitäten

  • TwbinarySearch(n) ist in O(log(n)) — logarithmisch
  • TwlinSearch(n) ist in O(n) — linear

Speicherplatzkomplexitäten

  • SwbinarySearch(n) ist in O(1) — konstant
  • SwlinSearch(n) ist in O(1) — konstant

Beachte: Bei der Speicherplatzkomplexität zählen wir die Größe der Eingabe nicht mit.

二分查找最坏 O(log n), 线性查找最坏 O(n); 两者额外空间都是 O(1) (只有几个变量 j、k、mid). 代价: 二分查找要求列表先排好序, 而排序本身至少要 O(n log n). 所以只查一次时, 直接线性查找更划算; 要在同一份数据上查很多次时, 先排序再二分才值得.

冒泡排序
Sortieren einer Liste durch Vertauschen (Bubble Sort)

Folie 34

Idee:
Vertausche benachbarte Elemente, wenn sie nicht wie gewünscht geordnet sind. In jedem Durchlauf des Feldes steigt das relativ größte Element wie eine Blase (bubble) im Wasser auf.

Algorithmus:

  • Sei „outer“ ein Zeiger auf das letzte Element der Liste.
  • Solange „outer“ nicht auf das erste Element zeigt:
    • Sei „inner“ ein Zeiger auf das erste Element der Liste.
    • Solange „inner < outer“:
      • Vertausche Elemente an den Positionen „inner“ und „inner+1“, wenn sie in falscher Reihenfolge stehen.
      • Rücke mit „inner“ eine Position vorwärts.
    • Rücke mit „outer“ eine Position rückwärts.

Bubble Sort 冒泡排序: 反复比较相邻的两个元素, 顺序反了就交换. 每扫一遍, 当前最大的元素就像气泡一样「浮」到末尾.

两个指针: outer 指向「未排序部分的末尾」, 从最后一个往前移; inner 在 0 到 outer 之间扫描, 每次比较 inner 和 inner+1. 每扫完一遍, outer 处就放好了一个最大值, outer 前移一位.

5   12  8   1   13  33     Nach dem zweiten Durchlauf sind die beiden größten Elemente an der richtigen Stelle

每一行是一遍扫描后的状态 (用脚本逐遍打印核对过). 第一遍 33 一路被换到最后; 第二遍 13 到倒数第二; …… 第五遍后全部有序. 第 k 遍之后, 最后 k 个元素就位.

Bubble Sort in Python

def bubbleSort(liste):
    for i in range(len(liste)):
        for j in range(0, len(liste) - i -1):

            if liste[j] > liste[j+1]:

                temp = liste[j]
                liste[j] = liste[j+1]
                liste[j+1] = temp

beispiel = [-2, 45, 0, 11]
bubbleSort(beispiel)
print(beispiel)

外层 i 是已经排好的个数; 内层 j 从 0 到 n−i−2, 比较 liste[j] 和 liste[j+1], 反了就用 temp 交换. len(liste) - i - 1: 最后 i 个已就位, 不用再比. 函数直接修改列表 (in-place). 实际输出 [-2, 0, 11, 45].

Folie 37

Komplexitäten des Bubble Sort

Sei n die Länge der Liste

Zeitkomplexität:

  • Die äußere for-Schleife wird in jedem Fall n + 1 mal durchlaufen.
  • Im i-ten Schritt wird die innere for-Schleife n−i mal durchlaufen, was durch n nach oben abschätzt werden kann.
  • Folglich ist die Zeitkomplexität des Bubble Sort in jedem Fall quadratisch, also in O(n2).
  • Beachte: Das ist auch die best-case Laufzeit von Bubble Sort!

Platzbedarf:

  • Neben der Eingabe werden 3 zusätzliche Speicherplätze für die lokalen Variablen gebraucht.
  • Daher ist die Speicherplatzkomplexität in der Eingabe n, konstant, d.h. in O(1).

时间: 外层 n 次, 内层每次最多 n 次 → 嵌套相乘 O(n · n) = O(n2). 精确地说内层总共 (n−1) + (n−2) + … + 0 = n(n−1)/2 次比较, 也是 O(n2). 这个版本不管输入怎样都做满所有比较, 所以已排好的输入也要 O(n2) (最好情况也是平方).

空间: 除了输入只用 i、j、temp 三个变量 → O(1).

幻灯片错误: 「Die äußere for-Schleife wird in jedem Fall n + 1 mal durchlaufen」: for i in range(len(liste)) 正好执行 n 次. 结论 O(n2) 不受影响. 「nach oben abschätzt」应为「abgeschätzt」.

Folie 38

Bubble Sort, optimiert

Wenn in einem Durchlauf keine Vertauschungen mehr passieren, dann ist das Feld bereits sortiert, und wir können aufhören:

def bubbleSortOpt(liste):
    for i in range(len(liste)):
        notSwapped = True
        for j in range(0, len(liste) - i -1):
            if liste[j] > liste[j+1]:
                temp = liste[j]
                liste[j] = liste[j+1]
                liste[j+1] = temp
                notSwapped = False

        if notSwapped:
            return

beispiel = [-2, 45, 0, 11]
bubbleSortOpt(beispiel)
print(beispiel)

Bubble Sort, optimiert (2)

(Code wie Folie 38)

Beachte: Die Best-Case-Laufzeit verbessert sich dadurch von O(n2) auf O(n), die Wort-Case-Laufzeit bleibt bei O(n2).

优化: 用标志 notSwapped 记录这一遍有没有交换过. 一遍扫下来一次都没换, 说明已经有序, 直接 return 结束.

  • 最好情况 (已排序): 第一遍就没有交换, 只扫一遍 n−1 次比较 → O(n). 实际运行: 对 [1, 2, 3, 4, 5] 只走了 1 遍外层循环.
  • 最坏情况 (倒序): 每遍都有交换, 仍要 n 遍 → 仍是 O(n2).

时间复杂度改善了吗? 最坏情况没有, 最好情况有. 例子 [-2, 45, 0, 11] 第 2 遍就没有交换了, 提前结束, 输出 [-2, 0, 11, 45].

注意 if notSwapped: 和内层 for 对齐, 在内层循环结束之后检查; 如果缩进到 if 里面, 就永远不会提前结束.

Selection Sort in Python

def selectionSort(liste):
    for i in range(len(liste)):
        minIndex = selectMinIndex(liste, i)
        tmp = liste[i]
        liste[i] = liste[minIndex]
        liste[minIndex] = tmp

def selectMinIndex(liste, ab):
    minIndex = ab
    for i in range(ab + 1, len(liste)):
        if liste[i] < liste[minIndex]:
            minIndex = i
    return minIndex

beispiel = [-2, 45, 0, 11, -9]
selectionSort(beispiel)
print(beispiel)

selectMinIndex 就是第 8 章的 find_min_index, 只是从下标 ab 开始找. selectionSort 每轮找最小值的下标, 再和位置 i 交换. 实际输出 [-9, -2, 0, 11, 45].

selectMinIndex 定义在 selectionSort 后面没关系: Python 在调用时才查找函数名, 那时两个 def 都已经执行过了.

Folie 44

Komplexität des Selection Sort

Sei n die Länge der Liste

Zeitkomplexität:

  • Es wird in jedem Fall n mal das Minimum gesucht und an die richtige Stelle getauscht.
  • Für jede Minimumsuche in der j-ten Runde wird ein Array der Größe n − j durchsucht. Die Laufzeit hierfür kann mit n nach oben abgeschätzt werden.
  • Folglich ist die Zeitkomplexität des Selection Sort in jedem Fall quadratisch, also in O(n2).
  • Beachte: Das ist auch die Best-Case Laufzeit!

Platzbedarf:

  • Neben der Eingabe werden nur konstant viele Speicherplätze benötigt. Daher ist die Speicherplatzkomplexität in der Eingabe n, konstant, d.h. in O(1).

n 轮, 每轮在最多 n 个元素里找最小值 → O(n2). 找最小值必须看完未排序部分的每一个元素 (不看完不知道是不是最小), 所以已排序的输入也一样慢: 最好情况也是 O(n2). 空间 O(1). 优点: 交换次数最多 n 次 (每轮一次), 比冒泡少.

插入排序
Sortieren einer Liste durch Einfügen (Insertion Sort)

Folie 45

Sei liste das zu sortierende Liste.

Idee: Für alle i ab 1 bis zum Ende der Liste:

  • Seien die Elemente in liste[0], ..., liste[i-1] schon sortiert
  • Nehme das Element liste[i] an i-ter Position und füge es an der richtigen Stelle ein, sodass die Folge liste[0], ..., liste[i] sortiert ist.

Beachte: Für das Einfügen an der richtigen Stelle, muss Platz geschaffen werden:
Verschiebe die Elemente dafür nach rechts.

Insertion Sort 插入排序: 像打牌时整理手里的牌. 左边 liste[0..i−1] 已经有序; 拿起第 i 个元素, 在左边找到它该在的位置插进去. 插入前要把比它大的元素逐个右移腾出空位.

Insertion Sort in Python

def insertionSort(liste):
    for i in range(1, len(liste)): # einzufügendes Element
        toInsert = liste[i]
        j = i

        while (j > 0 and liste[j-1] > toInsert): # schiebe liste[j-1] um 1 nach rehts
            liste[j] = liste[j-1]
            j -= 1
        liste[j] = toInsert # Einfügeposition gefunden

l = [5, 33, 12, 13, 8, 1]
insertionSort(l)
print(l)

toInsert 存要插入的值; j 是当前空位. while: 空位左边还有元素 (j > 0) 且那个元素比 toInsert 大, 就把它右移进空位, 空位左移一格. 结束后把 toInsert 放进空位. 实际输出 [1, 5, 8, 12, 13, 33].

j > 0 and … 的顺序很重要: 短路求值 (第 3 章) 保证 j = 0 时不会去访问 liste[-1].

Folie 50

Komplexitäten des Insertion Sort

Sei n die Länge der Liste

Zeitkomplexität:

  • Die äußere for-Schleife wird in jedem Fall n − 1 mal durchlaufen.
  • Im i-ten Schritt wird die while-Schleife höchstens i mal durchlaufen, was durch n nach oben abschätzt werden kann.
  • Folglich ist die Zeitkomplexität des Insertion Sort in jedem Fall quadratisch, also in O(n2).

Platzbedarf:

  • Neben der Eingabe werden 3 zusätzliche Speicherplätze für die lokalen Variablen gebraucht.
  • Daher ist die Speicherplatzkomplexität in der Eingabe n, konstant, d.h. in O(1).

外层 n−1 次, 内层 while 最多 i 次 → 最坏 O(n2). 空间: i、j、toInsert 三个变量 → O(1).

幻灯片前后不一致: 这里说 Insertion Sort「in jedem Fall quadratisch 任何情况下都是平方」, 但两张之后的 Folie 52 和 Folie 53 的表格都说最好情况是 O(n). 后者是对的 (while 循环可能一次都不执行). 准确的说法是: 最坏情况 O(n2), 所以「in jedem Fall in O(n2)」只在「O 是上界」的意义上成立, 不是「每种情况都是平方级」.

Folie 52

Insertion Sort: Best- und Worst-Case

  • Der beste Fall tritt ein, wenn die Eingabe bereits sortiert ist:
    • Die while-Schleife wird in diesem Fall nie durchlaufen
    • Die best-case Laufzeit von Insertion Sort ist in O(n)
  • Der schlechteste Fall tritt ein, wenn die Eingabe absteigend sortiert ist:
    • Dann muss die while-Schleife jeweils i mal durchlaufen werden.
    • Wie schon festgestellt, ist die worst-case Laufzeit in O(n2)
  • 最好情况 (已经升序): 每个元素都不比左边的小, while 条件第一次就为假, 每轮只做常数次操作 → O(n).
  • 最坏情况 (降序): 每个元素都要移到最前面, 第 i 轮 while 走 i 次 → 1 + 2 + … + (n−1) = n(n−1)/2 → O(n2).

插入排序对「几乎有序」的数据特别快, 所以实际的排序库 (如 Python 的 Timsort) 在小段上会用它.

总结: 三种简单排序最坏都是 O(n2), 额外空间都是 O(1). 优化的冒泡和插入排序最好情况 O(n). 基于比较的排序在最坏情况下不可能比 O(n log n) 更快 (这是一个定理); 达到 O(n log n) 的算法如归并排序、堆排序, 以及平均情况下的快速排序 (下一章).

「实践中常数因子也重要」: 两个 O(n2) 的算法, 实际速度可能差好几倍 (例如插入排序通常比冒泡快); 小规模数据时, 一个 O(n2) 的简单算法甚至可能比 O(n log n) 的复杂算法快.

表格最后一行的「Best-Case O(n·log n)」容易误解: 已经有插入排序做到最好情况 O(n), 所以「最好情况的最佳可能」其实是 O(n) (至少要把每个元素看一遍). 这一行的本意是「最坏情况下能达到的最佳复杂度是 O(n log n)」, 并且堆排序能在 O(1) 额外空间内做到这一点.
