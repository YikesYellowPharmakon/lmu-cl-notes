Part 1 · Python 概况
Python

Slide 21

Python is an interpreted language (in contrast to e.g. Java or C++, which are compiled).

  • Widely used, especially in Data Science, ML, Computational Linguistics/NLP
  • Developed in the 90s, Guido van Rossum in Amsterdam
  • Variables
    • Dynamically typed: types are determined automatically at runtime
    • The type of a variable can change
    • You can check the type of variables with type(var)
  • Space matters: typesetting (tabs or spaces have a meaning), in contrast to other programming languages

1. 解释型语言. Python 程序由解释器一边读一边执行, 不需要先整体翻译成机器码. Java、C++ 是编译型: 先由编译器把整个程序翻译好, 再运行翻译结果. 解释型的好处是写完立刻能跑、能在交互环境里逐行试; 代价是运行速度一般慢一些.

2. 应用领域与历史. 广泛用于数据科学、机器学习、计算语言学/NLP. 1990 年代由 Guido van Rossum 在阿姆斯特丹开发.

3. 动态类型.

  • 类型在运行时自动确定: 不用像 Java 那样写 int x, Python 看赋给它的值是什么, 就知道是什么类型.
  • 同一个变量的类型可以改变: x = 5 之后可以 x = "hi".
  • 用 type(x) 查看当前类型: type(5) → <class 'int'>.

4. 空白有意义. Python 用缩进 (空格或 Tab) 表示代码块, 即哪些语句属于 if、for、函数等. Java/C 用花括号 { } 表示代码块, 缩进只是为了好看; Python 里缩进错了, 程序结构就变了, 甚至报 IndentationError.

缩进的惯例是每层 4 个空格, 并且不要混用 Tab 和空格: 两者在编辑器里看起来可能一样宽, Python 却认为不同, 会报 TabError. PyCharm 默认把 Tab 键转换为 4 个空格.

交互式解释器 REPL
The Python REPL

Slide 22

The REPL (Read-Eval-Print Loop) is Python’s interactive language shell. You can invoke it on the shell like this:

$ python
>>> x = 'world'
>>> print('hello', x)
hello world
>>> x = 3 - 3 * 6 + 2
>>> x
-13
>>> x = 'a' * 10
>>> x
'aaaaaaaaaa'
>>> quit()

REPL = Read (读入你输入的一行) → Eval (求值/执行) → Print (打印结果) → Loop (回到开头等下一行). 在终端输入 python (macOS 上通常是 python3) 进入, 提示符是 >>>; quit() 退出.

逐行解释:

  • print('hello', x): print 接收多个参数时, 用空格隔开输出, 所以是 hello world.
  • 3 - 3 * 6 + 2: 先乘后加减, 3×6=18, 再从左到右 3−18+2 = −13.
  • 只输入 x 回车: REPL 会自动显示表达式的值 (这是 REPL 独有的; 写在 .py 文件里则必须用 print).
  • 'a' * 10: 字符串 × 整数 = 重复, 得到 10 个 a.
  • 注意显示格式: REPL 显示字符串值时带引号 ('aaaaaaaaaa'), 而 print 输出不带引号.
  • 同一个 x 先后是字符串、整数、字符串, 这就是上一页说的「类型可以改变」.

变量
Variables

Slide 23
  • Storage units
  • Content can be changed (i.e, is variable)
  • Variables consist of: a data type, a variable name and a variable value
  • Assignment of value to variable: var_name = value, e.g., num = 17, automatically determines the variable type (here: int)
# Python:
num = 17

# Java:
int num = 17;

变量是存储单元, 内容可以改变 (所以叫「变」量). 一个变量有三个要素: 数据类型、变量名、变量值.

赋值写作 变量名 = 值. num = 17 让名字 num 指向值 17, Python 根据 17 自动确定类型为 int.

对比 Java: Java 必须在变量名前写出类型 int, 行尾要分号; 这是静态类型, 类型在编译时就固定, 之后不能把字符串存进 num. Python 不写类型、不写分号.

注意: = 是赋值, 不是数学上的「相等」; 判断相等用 ==.

字符串
String data types

Slide 26
  • Textual data in Python is handled with str objects, or strings.
  • Immutable sequence of single characters
s1="first line\nsecond line"          # double quotes
s2=r"first line\nstill first line"    # raw string
s3="""first line
second line""".                       # triple quotes (may span multiple lines)
s4='using different quotes'           # single quotes
# Single quotes: 'allows embedded "double" quotes'
  • What does the r in front of the opening quote in example s2 do (raw string)?
  • See for more info: https://docs.python.org/3/library/stdtypes.html#text-sequence-type-str

字符串是由单个字符组成的不可变序列:

  • 序列: 字符有顺序, 可以按位置 (下标) 取;
  • 不可变: 建好后不能修改其中某个字符. s = 'the'; s[0] = 'T' 会报 TypeError; 要「改」只能造一个新字符串, 如 s = 'T' + s[1:].

四种写法:

  • s1 双引号: \n 是转义序列, 表示换行. print(s1) 输出两行.
  • s2 原始字符串: 回答幻灯片的问题: 前缀 r 让反斜杠不再起转义作用, \n 就是反斜杠和字母 n 两个字符. 所以 print(s2) 输出一行: first line\nstill first line. 常用于正则表达式和 Windows 路径 (如 r"C:\new").
  • s3 三引号: """…""" 可以跨多行, 引号内的换行就是字符串里的换行. 也用于函数的文档字符串 (后面 doctest 会用到).
  • s4 单引号: 和双引号等价. 好处是单引号里可以直接放双引号: 'allows embedded "double" quotes', 反之亦然.

幻灯片错误: s3 那一行 second line""". 的三引号后面多了一个句点, 照抄会报 SyntaxError: invalid syntax. 应写成 second line""".

Unicode 字符串
Unicode strings

Slide 27

Strings are Unicode UTF-8 by default in Python3:

>>> x = 'B\u00e4ume'
>>> print(x)
Bäume

\u00e4 是一个转义序列: \u 后跟 4 位十六进制数, 表示一个 Unicode 字符. 十六进制 00E4 = 十进制 228, 对应字母 ä. 所以 'B\u00e4ume' 就是 'Bäume' (德语「树」的复数), 长度是 5 个字符.

Python 3 的字符串天生支持所有 Unicode 字符 (中文、德语变音、表情符号都可以). 幻灯片的「Unicode UTF-8」这个说法不够精确, 下一页会把两者分开: Unicode 给字符编号, UTF-8 把编号变成字节.

核心问题: 计算机只能存字节 (8 个比特), 不能直接存「字母」. 所以需要一套规则把字符变成字节, 这就是字符编码. 这件事分两步:

  1. 字符 → 编号: 由 Unicode 负责. Unicode 试图给人类所有文字里的每个字符分配一个唯一编号, 叫码位. 幻灯片写: 截至 18.0 版 (2026-09-16 发布) 共 172 808 个字符.
  2. 编号 → 字节: 由 UTF-8 / UTF-16 等编码方式负责 (见下一页).

在 Python 里, 字符串就是一串 Unicode 码位. ord("A") 返回 A 的码位 65; 反过来 chr(65) 返回 'A'.

看表要注意:

  • 大写和小写是不同字符: A=65, a=97, 相差 32.
  • 空格也是字符, 编号 32.
  • 0–127 的字符就是老的 ASCII (英文字母、数字、标点). α、β、©、€、🌍 都在 ASCII 之外, 编号更大.

UTF (Universal Character Set Transformation Format) 是把 Unicode 编号转换成字节的格式, 有多个版本:

  • UTF-8: 每个字符用 1、2、3 或 4 个字节, 变长.
  • UTF-16: 每个字符用 2 或 4 个字节.

为什么多数情况下 UTF-8 更省空间? 看表:

  • 空格和 A 在 UTF-8 里只占 1 字节 (8 位); 在 UTF-16 里占 2 字节, 前面多了一整个 00000000.
  • 🌍 两边都是 4 字节.

英文文本、代码、HTML 绝大多数字符都是 ASCII, 用 UTF-8 每个只需 1 字节, 比 UTF-16 省一半. 所以 UTF-8 是今天网页和文件最常用的编码.

UTF-8 的字节长度规律 (看第一个字节的开头几位就知道这个字符占几个字节):

码位范围字节数格式例子

2048–6553531110xxxx 10xxxxxx 10xxxxxx€, 汉字

表中 🌍 的 UTF-8 第一个字节是 11110000, 开头 11110 说明它占 4 个字节; 后三个字节都以 10 开头, 表示「接续字节」. 中文汉字在 UTF-8 里占 3 字节, 在 UTF-16 里占 2 字节, 所以对纯中文文本 UTF-16 反而更省. 这就是幻灯片说「in most cases」的原因.

字典
Dictionaries

Slide 39
  • Dictionaries are mappings, not sequences
  • They represent a collection of key:value pairs
  • Example: d = {'food':'Spam', 'quantity':4, 'color':'pink'}
  • Efficient access (∼ constant time): what is the value associated with a key?
  • They are mutable like lists: Key-value pairs can be added, changed, and removed
  • Keys need to be unique and immutable – why?
  • 映射, 不是序列: 字典不按位置 0、1、2 取值, 而是按键取值. d[0] 不是「第一项」, 而是「键为 0 的值」.
  • 由键值对组成: 'food' 是键, 'Spam' 是值. 就像真正的词典: 查「词条」 (键) 得到「释义」 (值).
  • 查找很快, 约为常数时间: 无论字典有 10 项还是 1000 万项, 按键查值所需时间大致相同. 对比列表: 要在列表里找某个值, 最坏要从头到尾逐个比较.
  • 可变: 可以增加、修改、删除键值对.

幻灯片的问题: 为什么键必须唯一且不可变?

  • 唯一: 一个键只能对应一个值, 否则 d['food'] 就不知道返回哪个. 对已有的键再赋值, 是覆盖旧值.
  • 不可变: 字典查找快, 是因为它根据键算出一个哈希值, 直接定位到存储位置. 如果键能被修改, 哈希值就变了, 原来存的位置就找不回来了. 所以字符串、数字、元组可以做键, 列表、字典、集合不能做键 ({[1,2]: 'x'} 会报 TypeError: unhashable type: 'list').

NLP 中最典型的用法: 词频统计, 键是单词, 值是出现次数.

  • 'element' in s1 → True: 'element' 是作为一个整体加入的元素.
  • 'spam' in s1 → False: s1 里有的是 's'、'p'、'a'、'm' 四个单独字母, 没有 'spam' 这个整串.
  • s2 = set('ham') → {'h', 'a', 'm'}.
  • 交集 intersection (两边都有的): a、m → {'m', 'a'}.
  • 并集 union (至少一边有的, 重复只算一次): s、p、a、m、element、h.

幻灯片强调: 交集、并集返回新集合, 原来的 s1、s2 不变.

幻灯片留的问题: 差集 difference 有方向.

  • s1.difference(s2) = s1 有而 s2 没有 → {'s', 'p', 'element'}
  • s2.difference(s1) = s2 有而 s1 没有 → {'h'}

两者结果不同. 交集和并集与顺序无关, 差集与顺序有关.

运算符简写: s1 & s2 交集, s1 | s2 并集, s1 - s2 差集.

Slide 55

The for loop is a generic iterator in Python: it can step through the items in any ordered sequence or other iterable objects (strings, lists, tuples, and other built-in iterables, as well as new user-defined iterables).

Python 的 for 是通用迭代器: 它能逐个取出任何可迭代对象里的元素, 包括字符串 (逐个字符)、列表、元组、字典 (逐个键)、集合、文件 (逐行), 以及以后自定义的可迭代对象. 它和 C/Java 的「计数式」for 不同, 直接遍历元素.

for i in range(0, len(l))0 1 2 3取下标: len(l)=4, range(0,4) 是 0–3

函数把一组语句打包起来, 起个名字, 以便在程序中多次运行.

为什么用函数:

函数也是对象
Function objects

Slide 61

Functions are normal python objects – they can be bound to other variables, be put into lists or dictionaries and even be used as parameter for other functions.

>>> def add(x, y):
...   return x + y
>>> def mul(x, y):
...   return x * y
>>> def do(x, y, f):
...   return f(x, y)
>>> f = mul # Bind the variable f to the function mul.
>>> f(3, 5)
15
>>> f = add # Bind the variable f to the function add.
>>> do(8, 4, f)
12

在 Python 里函数是普通对象, 和数字、字符串一样可以: 赋给其他变量、放进列表或字典、作为参数传给别的函数.

  • f = mul: 让变量 f 指向函数 mul. 注意没有括号: mul 是函数本身, mul(3, 5) 才是调用它. 之后 f(3, 5) 等于 mul(3, 5) = 15.
  • f = add: f 改为指向 add.
  • do(8, 4, f): 把函数 add 当参数传进 do. do 内部执行 f(x, y), 即 add(8, 4) = 12.

意义: do 不关心具体做什么运算, 具体运算由调用者传进来. 这叫高阶函数, 是函数式编程的思想. 实际例子: sorted(words, key=len) 把函数 len 传给 sorted, 按单词长度排序.

    return x * x

doctest 的原理: 它在模块的文档部分里寻找「看起来像 REPL 交互会话」的文本, 即以 >>> 开头的行; 把这些行当代码运行, 再把结果和下一行写的期望输出逐字比较.

本例: docstring 第一行是说明「返回 x 的平方」; 下面两组测试:

  • >>> square(2), 期望 4;
  • >>> square(-2), 期望 4 (负数的平方是正数, 这是一个边界情况).

格式要求: >>> 后要有一个空格; 期望输出紧接在下一行; 比较是按文本逐字进行的, 所以期望写 4.0 而实际是 4 也算失败.

优点: 测试就是文档, 读函数说明的人同时看到了用法示例, 示例还保证是对的.

测试驱动开发
Test-Driven Development (TDD)

Slide 73
  • Write tests first (implement functionality later)
  • Add to each test an empty implementation of the function (use the pass-statement)
  • The tests initially all fail
  • Then implement, one by one, the desired functionality
  • Advantages:
    • Define in advance what the expected input and outputs are
    • Also think about important boundary cases (e.g. empty strings, empty sets, float(inf), 0, unexpected inputs, negative numbers)
    • Gives you a measure of progress (“65% of the functionality is implemented”) – this can be very motivating and useful!

测试驱动开发 (TDD) 把通常的顺序倒过来: 先写测试, 后写实现.

  1. 先写好测试 (期望的输入和输出);
  2. 函数体先只写 pass (空语句, 什么也不做, 只是占位让语法合法);
  3. 这时运行测试, 全部失败, 这是预期中的;
  4. 然后一个一个实现功能, 看着失败的测试逐个变绿.

好处:

  • 事先明确输入和输出应该是什么, 避免写到一半才发现没想清楚需求;
  • 逼你考虑边界情况: 空字符串、空集合、float('inf') (无穷大)、0、意外的输入、负数. 很多 bug 恰恰出在这些地方. 例如一个「求平均词长」的函数, 输入空文本时会除以 0;
  • 提供进度度量: 「65% 的测试已通过」= 65% 的功能已实现, 既有用又能激励自己.

unittest 模块
The unittest module

Slide 77
  • Similar to Java’s JUnit framework.
  • Most obvious difference to doctest: test cases are not defined inside of the module which has to be tested, but in a separate module just for testing.
  • In that module …
    • import unittest
    • import the functionality you want to test
    • define a class that inherits from unittest.TestCase
      • This class can be arbitrarily named, but XyzTest is standard, where Xyz is the name of the module to test.
      • In XyzTest, write member functions that start with the prefix test...
      • These member functions are automatically detected by the framework as tests.
      • The tests functions contain assert-statements
      • Use the assert-functions that are inherited from unittest.TestCase (do not use the Python built-in assert here)

unittest 类似 Java 的 JUnit 框架. 和 doctest 最明显的区别: 测试不写在被测模块里, 而是写在一个单独的测试模块 (单独的 .py 文件) 里. 这样被测代码保持干净, 测试也可以写得更复杂.

测试模块的写法 (按顺序):

  1. import unittest;
  2. 导入要测试的功能, 如 from example_module import square;
  3. 定义一个类, 继承 unittest.TestCase (继承 = 自动获得 TestCase 的全部功能, 下周讲类时细说):
    • 类名可以随便取, 但惯例是 XyzTest, Xyz 是被测模块/功能的名字 (如 SquareTest);
    • 在类里写以 test 开头的方法. 只有以 test 开头的方法才会被框架自动识别为测试, 名字不对就不会运行;
    • 测试方法里写断言;
    • 用从 TestCase 继承来的断言方法 (self.assertEqual 等), 不要用 Python 内置的 assert 语句. 原因: TestCase 的断言方法失败时会给出清楚的报告 (如 None != 0), 而且能被框架统计.

每个断言方法检查一个条件, 不满足就判这条测试失败. 「New in」列是该方法从哪个 Python 版本开始提供 (3.1、3.2 都很老了, 现在都能用).

  • assertEqual / assertNotEqual: 值相等 / 不等. 最常用.
  • assertTrue(x) / assertFalse(x): x 的真值为真 / 假. 注意是 bool(x): assertTrue([]) 会失败, 因为空列表为假.
  • assertIs / assertIsNot: 是不是同一个对象.
  • assertIsNone / assertIsNotNone: 是否为 None.
  • assertIn(a, b) / assertNotIn: a 是否在 b 里 (b 可以是列表、字符串、字典的键……).
  • assertIsInstance(a, b): a 是否是类型 b 的实例, 如 assertIsInstance(result, list).

幻灯片的问题: a == b 和 a is b 有什么区别?

  • == 比较值 (内容): 两边看起来一样就为真.
  • is 比较身份: 两边是否是内存中的同一个对象. 
a = [1, 2]
b = [1, 2]
c = a
a == b    # True ：内容相同
a is b    # False：是分别创建的两个列表
a is c    # True ：c 和 a 指向同一个列表

「同一个对象」意味着通过一个名字修改, 另一个也会变 (见前面「可变与不可变」). 判断 None 时惯用 x is None, 因为 None 在整个程序里只有一个. 比较数字、字符串的值应该用 ==, 不要用 is.

Slide 83 · Example using setUp and tearDown 
class SquareTest(unittest.TestCase):
    def setUp(self):
        self.inputs_outputs = [(0,0),(-1,1),(2,4)]

    def testCalculation(self):
        for i,o in self.inputs_outputs:
            self.assertEqual(square(i),o)

    def tearDown(self):
        # Just as an example.
        self.inputs_outputs = None

如果测试类里写了这两个特殊名字的方法, 框架会自动识别并调用:

  • setUp: 在每个测试方法运行之前执行. 用来建立多个测试共用的前提条件, 例如准备输入输出数据、建立网络连接、从文件读入数据.
  • tearDown: 在每个测试方法运行之后执行 (用得较少). 用来做收尾清理, 例如关闭网络连接、删除临时文件.

执行顺序 (每个 test 方法都重复一遍): setUp → testXxx → tearDown.

例子解读:

  • setUp 把测试数据——三个 (输入, 期望输出) 元组——存在 self.inputs_outputs 上. 用 self. 存, 测试方法才能访问到.
  • testCalculation 用 for 循环逐对检查. for i, o in … 是元组解包: 每个元组 (0, 0) 被拆成 i=0、o=0. 效果等同于前面三条 assertEqual, 但测试数据和测试逻辑分开了, 加新的测试数据只需改 setUp 里的列表.
  • tearDown 把数据设为 None. 注释写明 Just as an example: 这里其实不需要清理, 只是演示 tearDown 会在测试后执行.

Slide 86 · Unicode strings

Strings are Unicode UTF-8 by default in Python3:

>>> x = 'B\u00e4ume'
>>> print(x)
Bäume

Let’s convert from UTF-8 to binary:

>>> y = x.encode('utf-8') # same as x.encode()
>>> print(y)
b'B\xc3\xa4ume'
  • \x tells Python to interpret the next two characters as hex values.
  • Python displays the first 127 characters (ASCII) in their plain form ('B', 'u', 'm', 'e'). However, their internal binary representations are '\x42', '\x75', '\x6d' and '\x65'.
  • x.encode('utf-8'): 把字符串编码成字节 (bytes 类型). 不写参数时默认就是 UTF-8.
  • 结果 b'B\xc3\xa4ume': 前缀 b 表示这是字节串, 不是普通字符串.
  • \x 后面跟两位十六进制数, 表示一个字节的值. ä 在 UTF-8 中占两个字节: \xc3\xa4.
  • B、u、m、e 是 ASCII 字符, Python 显示字节串时直接显示成可读字母, 但它们实际也是字节: B = \x42 (十进制 66, 对照前面 Unicode 表), u = \x75, m = \x6d, e = \x65.

长度对比: len('Bäume') 是 5 (5 个字符), len('Bäume'.encode()) 是 6 (6 个字节, 因为 ä 占 2 字节). 字符数和字节数不一定相等.

幻灯片小错: 「first 127 characters (ASCII)」应为 128 个 (编号 0–127).

Slide 88 · UTF-8 Encoding

Example continued…

# Decode binary back to string:
>>> str(b"\x42\xc3\xa4\x75\x6d\x65", "utf-8")
'Bäume'

How does conversion from unicode to binary work?

  • Naive approach:
    • Use lookup table that maps characters (i.e. their unicode code points) to a binary code that can be stored on disk.
    • E.g., we could directly store the letter A by the binary code of it’s code point ord('A')=65, which is 1000001 (8 bits).
    • Disadvantage: Fix code lengths are space in-efficient. Remember: storing the symbol 🌍 requires 32 bits.
  • UTF-8 encoding is a method that translates unicode code points into variable-length binary codes (https://www.utf8-chartable.de/).

解码: str(字节串, "utf-8") 把字节按 UTF-8 规则还原成字符串, 等价于 b"…".decode("utf-8"). 编码与解码是一对: 

'Bäume'  ──encode('utf-8')──▶  b'B\xc3\xa4ume'
         ◀──decode('utf-8')──

用错编码解码就会出现乱码, 例如把 UTF-8 字节按 Latin-1 解码, ä 会变成 Ã¤.

为什么要用变长编码?

  • 朴素方法: 每个字符的码位直接用固定长度的二进制存储. A 的码位 65 = 二进制 1000001.
  • 缺点: 固定长度必须照顾最大的码位. 🌍 需要 32 位, 于是每个字符都得占 32 位 (4 字节), 连 A 也是, 大部分位都是 0, 浪费空间.
  • UTF-8 的办法: 变长编码, 常用字符用短编码 (ASCII 只要 1 字节), 少见字符用长编码 (最多 4 字节). 码表可查 utf8-chartable.de.

幻灯片小错: 1000001 只有 7 位; 作为一个 8 位字节存储时写作 01000001 (见 Slide 29 的表).
