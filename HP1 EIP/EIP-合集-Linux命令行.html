⑤ 每次练习的固定流程
Routine

ssh 你的CIP用户名@remote.cip.ifi.lmu.de   # 1. 登录
mkdir -p ~/uebung                         # 2. 只有第一次需要：建练习目录
cd ~/uebung                               # 3. 进入练习目录
...                                       # 4. 照着书练习
exit                                      # 5. 退出，回到自己电脑的终端

~ 是你在服务器上的家目录 (第 2 章、第 7 章细讲), 不是你笔记本上的家目录. mkdir -p 的 -p 表示「需要时连上级目录一起建, 目录已存在也不报错」, 所以这一行重复执行也无害. # 后面是注释, 不用输入.

退出也可以按 Ctrl-D (第 1 章).

⑥ 出现 Permission denied 时
Fehlersuche

按顺序检查:

  1. 用户名: @ 前面是 CIP 用户名, 不是校园账号.
  2. 远程登录: 第 ② 步做了吗? 做完后等了几分钟吗?
  3. 密码: 大小写、Caps Lock、键盘布局 (德语键盘 y/z 互换)、中文输入法要关掉.
  4. 生效时间: 确认邮件里写的生效时间已经过了吗?

都没问题还是失败: 在 CipConf 里重设密码, 或用 CipConf 的 Message to RBG 联系机房管理员 (RBG = Rechnerbetriebsgruppe).

⑦ 使用规则
Regeln

  • 入口服务器只适合运行短命令. 长时间、高资源的计算会被不加通知地终止 (第 10 章会讲进程怎样被终止).
  • 服务器每周重启一次. 不要指望登录会话一直存在; 文件要及时保存.
  • 在学院的 CIP 机房里, 可以直接用 CIP 账号登录电脑, 不需要 ssh.

冒号后面是服务器上的路径; 最后的 . 表示「当前目录」 (第 2 章).

第 1 章 · Shell 是什么
1 What Is the Shell?

S. 3

“The shell is a program that takes keyboard commands and passes them to the operating system to carry out. Almost all Linux distributions supply a shell program from the GNU Project called bash. The name is an acronym for bourne-again shell …”

shell 是一个程序: 接收键盘输入的命令, 交给操作系统执行. 几乎所有 Linux 发行版都带 GNU 项目的 shell bash, 名字是 bourne-again shell 的缩写, 意思是它增强并取代了 Steve Bourne 写的原始 Unix shell sh (名字里有个双关: born again「重生」).

理解要点: 「命令行」指的其实就是 shell. shell 本身只是一个普通程序, 它的工作是读一行文字 → 解释 → 让系统去执行. 第 7 章会讲「解释」这一步到底做了什么.

终端模拟器
Terminal Emulators

S. 3–4

“When using a graphical user interface (GUI), we need another program called a terminal emulator to interact with the shell.” KDE uses konsole, GNOME uses gnome-terminal.

在图形界面下, 要通过终端模拟器这个窗口程序才能和 shell 打交道. 终端只负责显示文字、接收按键; 真正解释命令的是窗口里运行的 shell. macOS 的「终端」、Windows 的 PowerShell 窗口也是终端模拟器.

macOS 的终端默认运行 zsh, 不是 bash. zsh 和 bash 大部分相同, 但有些行为不同 (例如通配符找不到匹配时, zsh 报错 no matches found, bash 会把模式原样传下去, 见第 7 章). 书里的例子以 bash 为准, 所以建议在 CIP 上练习. 用 echo $SHELL 看自己的登录 shell; 如果不是 bash, 输入 bash 就能进入一个 bash.

第一次敲键盘: 提示符
Making Your First Keystrokes

S. 4 
[me@linuxbox ~]$
[me@linuxbox ~]$ kaekfjaeifj
bash: kaekfjaeifj: command not found

“This is called a shell prompt … it will typically include your username@machinename, followed by the current working directory … and a dollar sign.” “If the last character of the prompt is a hash mark (#) rather than a dollar sign, the terminal session has superuser privileges.”

提示符表示 shell 已准备好接收输入. 结构是 用户名@主机名 当前目录, 最后一个字符是 $ (普通用户) 或 # (超级用户 root, 权限最大, 要格外小心).

输入一串乱码, bash 回答 command not found, 然后给你下一次机会. 在 shell 里出错不可怕, 读懂报错信息是第一个要养成的习惯: bash: 说明是谁在报错, kaekfjaeifj: 是出问题的那个词, 最后是原因.

鼠标、复制粘贴与焦点
A Few Words About Mice and Focus

S. 5

X Window System: highlight text with the left mouse button (or double-click a word) to copy it; press the middle mouse button to paste.

“Don’t be tempted to use ctrl-C and ctrl-V to perform copy and paste inside a terminal window. They don’t work. These control codes have different meanings to the shell …”

Linux 图形界面 (X) 里, 选中即复制, 鼠标中键粘贴. 在终端里 Ctrl-C 不是复制: 它的意思是「中断正在运行的程序」 (第 10 章). 书里还提到「焦点跟随鼠标」这种窗口设置, 属于桌面偏好, 不影响命令行学习.

macOS 终端里用 ⌘-C / ⌘-V 复制粘贴, Ctrl-C 仍然是中断. Windows Terminal 和新版 PowerShell 窗口通常支持 Ctrl-Shift-C / Ctrl-Shift-V (新版也允许 Ctrl-V 粘贴), 右键也常常就是粘贴. 通过 ssh 连到 CIP 时, 复制粘贴由你自己电脑上的终端完成, 服务器感觉不到.

文件系统树
Understanding the File System Tree

S. 7–8

Linux organizes its files in a hierarchical directory structure … “The first directory in the file system is called the root directory.”

“… unlike Windows, which has a separate file system tree for each storage device, Unix-like systems such as Linux always have a single file system tree … Storage devices are attached (or more correctly, mounted) at various points on the tree …”

层级目录结构: 目录 (别的系统叫文件夹) 里装文件和子目录, 像一棵倒过来的树, 最顶端是根目录 /.

和 Windows 的关键区别: Windows 每个盘一棵树 (C:\、D:\); Linux 永远只有一棵树, U 盘、第二块硬盘被挂载 (mount) 到树上的某个目录 (第 1 章 df 的 Mounted on 列就是挂载点).

当前工作目录
The Current Working Directory

S. 8 
[me@linuxbox ~]$ pwd
/home/me

“At any given time, we are inside a single directory … The directory we are standing in is called the current working directory.” When we log in, it is set to our home directory — “the only place a regular user is allowed to write files.”

把文件系统想成一座迷宫: 任何时刻你都「站在」某一个目录里, 这就是当前工作目录. pwd (print working directory) 告诉你站在哪. 登录后你站在自己的家目录, 它是普通用户唯一可以随意写文件的地方 (第 9 章解释原因). 在 CIP 上, ~/uebung 就建在家目录里.

绝对路径
Absolute Pathnames

S. 9

“An absolute pathname begins with the root directory and follows the tree branch by branch until the path to the desired directory or file is completed.”

[me@linuxbox ~]$ cd /usr/bin
[me@linuxbox bin]$ pwd
/usr/bin

路径名就是在树上走的路线. 绝对路径以 / 开头, 从根出发: /usr/bin = 根目录下的 usr 里的 bin. 不管你站在哪, 绝对路径指向的都是同一个地方. 注意提示符里的目录名从 ~ 变成了 bin.

小心两种 /: 开头的 / 表示根目录, 中间的 / 只是分隔符.

相对路径
Relative Pathnames

S. 9–10

“… a relative pathname starts from the working directory.” “The . notation refers to the working directory, and the .. notation refers to the working directory’s parent directory.”

[me@linuxbox bin]$ cd ..
[me@linuxbox usr]$ pwd
/usr
[me@linuxbox usr]$ cd ./bin
[me@linuxbox bin]$ pwd
/usr/bin

“In almost all cases, we can omit the ./ part because it is implied.” — cd bin does the same thing.

相对路径不以 / 开头, 从当前目录出发. . = 当前目录, .. = 上一级 (父目录). cd .. 和 cd /usr 结果一样; 作者的建议是: 哪种打字少用哪种.

./ 一般可以省略: 没写路径时默认就是当前目录. 例外留到以后: 运行当前目录里的程序或脚本时必须写 ./脚本名 (第 2 部分会讲 PATH).

文件名的重要事实
Important Facts About Filenames

S. 11
  • Filenames that begin with a period character are hidden … ls will not list them unless you say ls -a.
  • Filenames and commands in Linux … are case sensitive. File1 and file1 refer to different files.
  • … limit the punctuation characters in the names of files you create to period, dash, and underscore. Most important, do not embed spaces in filenames.
  • Linux has no concept of a “file extension” … The contents or purpose of a file is determined by other means.
  1. 以点开头的文件是隐藏文件, 只是 ls 默认不显示, ls -a 才显示; 家目录里的配置文件 (如 .bashrc) 大多是这种.
  2. 区分大小写: File1 和 file1 是两个文件. (macOS 默认不区分大小写, CIP 上区分, 从 Mac 拷文件过去时要留意.)
  3. 文件名不要带空格, 只用字母、数字、. - _. 空格会让 shell 把一个名字拆成两个参数 (第 7 章「引号」会看到后果).
  4. 没有「扩展名」概念: .txt 只是名字的一部分, 系统不靠它判断内容; 但很多应用程序会看扩展名. 判断内容用 file (第 3 章).

选项与参数
Options and Arguments

S. 14–15 
command -options arguments

“Most commands use options, which consist of a single character preceded by a dash, for example, -l. Many commands, however, including those from the GNU Project, also support long options, consisting of a word preceded by two dashes. Also, many commands allow multiple short options to be strung together.”

[me@linuxbox ~]$ ls -lt
[me@linuxbox ~]$ ls -lt --reverse

Note: Command options, like filenames in Linux, are case sensitive.

这是理解所有命令的通用格式: 命令 + 选项 + 参数.

  • 选项 (option) 改变命令的行为: 短选项一个横线一个字母 -l; 长选项两个横线一个单词 --reverse.
  • 多个短选项可以合写: ls -lt = ls -l -t (长格式 + 按修改时间排序).
  • 参数 (argument) 是命令作用的对象, 例如目录名、文件名.
  • 选项区分大小写: -a 和 -A 是两个选项 (见下表).

Files are made up of two parts: the data part and the name part. “The system assigns a chain of disk blocks to what is called an inode, which is then associated with the name part.”

建了 3 个硬链接后, 第 2 列的链接数是 4 (原名 + 3 个新名字). 怎么证明它们是同一个文件? ls -i 在最前面显示 inode 号: fun 和 fun-hard 的 inode 号相同, 说明它们是同一份数据的两个名字.

模型: 文件 = 数据部分 (inode 管理的磁盘块) + 名字部分 (目录项). 硬链接 = 再加一个名字部分, 指向同一个 inode. (已在本机实测: 两个硬链接的 inode 号相同, 链接数为 2.)

“… when we create a symbolic link, we are creating a text description of where the target file is relative to the symbolic link.” “… the length of the symbolic link file is 6, the number of characters in the string ../fun …” Relative pathnames are usually preferable: the tree can be renamed or moved “without breaking the links.”

最容易错的一点: 符号链接里存的相对路径, 是相对于链接所在的位置, 不是相对于你执行命令时所在的位置. dir1/fun-sym 在 dir1 里, 从那里看 fun 在上一级, 所以要写 ../fun.

符号链接的「大小」是路径字符串的长度: ../fun 是 6 个字符, 所以显示 6; fun 是 3 (已实测).

可以用绝对路径 (ln -s /home/me/playground/fun …), 但整棵目录搬家后链接会断; 相对路径跟着一起搬, 不会断. 符号链接也能指向目录 (dir1-sym -> dir1), 硬链接不能.

标准输入、输出、错误
Standard Input, Output, and Error

S. 50

“… programs such as ls actually send their results to a special file called standard output (often expressed as stdout) and their status messages to another file called standard error (stderr). By default, both standard output and standard error are linked to the screen … many programs take input from a facility called standard input (stdin), which is, by default, attached to the keyboard.”

每个程序启动时都有三条现成的「管道」:

名称文件描述符默认连到放什么
标准输入 stdin0键盘程序读的数据
标准输出 stdout1屏幕程序的结果
标准错误 stderr2屏幕状态和错误信息

结果和错误默认都显示在屏幕上, 所以看起来像一回事, 其实是两条不同的通道. I/O 重定向就是改变这些通道连接的地方. (文件描述符 0/1/2 在 S. 52 才出现, 这里提前列出便于对照.)

重定向标准输出: > 与 >>
Redirecting Standard Output

S. 50–51 
[me@linuxbox ~]$ ls -l /usr/bin > ls-output.txt
[me@linuxbox ~]$ ls -l /bin/usr > ls-output.txt
ls: cannot access /bin/usr: No such file or directory
[me@linuxbox ~]$ ls -l ls-output.txt
-rw-rw-r-- 1 me   me   0 2018-02-01 15:08 ls-output.txt
[me@linuxbox ~]$ > ls-output.txt
[me@linuxbox ~]$ ls -l /usr/bin >> ls-output.txt

“… when we redirect output with the > redirection operator, the destination file is always rewritten from the beginning.” “Using the >> operator will result in the output being appended to the file.”

  • 命令 > 文件: 把标准输出写进文件, 文件从头重写 (原内容清空).
  • 第二个例子目录不存在: 错误信息仍然出现在屏幕上, 因为它走的是 stderr, 而 > 只改了 stdout.
  • 同时文件变成了 0 字节: shell 在命令运行之前就已经打开并清空了文件, 命令却什么结果都没输出.
  • 所以单独一个 > 文件 就能清空文件, 或建一个空文件 (已实测).
  • >> 追加到文件末尾; 文件不存在时和 > 一样新建. 书里追加三次, 文件大小是原来的三倍.

重定向标准错误
Redirecting Standard Error

S. 52–53 
[me@linuxbox ~]$ ls -l /bin/usr 2> ls-error.txt
[me@linuxbox ~]$ ls -l /bin/usr > ls-output.txt 2>&1
[me@linuxbox ~]$ ls -l /bin/usr &> ls-output.txt
[me@linuxbox ~]$ ls -l /bin/usr &>> ls-output.txt
[me@linuxbox ~]$ ls -l /bin/usr 2> /dev/null

“… the shell references them internally as file descriptors 0, 1, and 2, respectively.”

The order of the redirections is significant. “The redirection of standard error must always occur after redirecting standard output or it doesn’t work.”

>ls-output.txt 2>&1    # stderr goes to ls-output.txt
2>&1 >ls-output.txt    # stderr goes to the screen
  • 2> 文件: 在 > 前面写上文件描述符 2, 重定向的就是 stderr. (> 其实是 1> 的简写.)
  • > 文件 2>&1: 先把 1 接到文件, 再让 2「接到 1 现在接的地方」. &1 的 & 表示「这是描述符 1」, 不是名叫 1 的文件.
  • 为什么顺序重要: 重定向从左到右执行. 写成 2>&1 >文件 时, 2 复制的是 1 当时的去向 (屏幕), 之后 1 才改到文件, 所以错误仍然出现在屏幕上.
  • &> 文件: bash 的简写, 一次把 stdout 和 stderr 都写进文件; &>> 是追加版.
  • /dev/null: 「位桶」, 写进去的东西直接消失. 2> /dev/null 用来扔掉不想看的错误信息. 「把你的意见发到 /dev/null」是 Unix 圈子里的玩笑话.

&>> 需要 bash 4 及以上; macOS 自带的 bash 3.2 遇到它直接报语法错误 syntax error near unexpected token `>' (本机实测). CIP 上的 bash 版本没问题. 写脚本要兼容旧环境时, 用传统写法 >> 文件 2>&1.

重定向标准输入: cat 与 <
Redirecting Standard Input · cat

S. 53–55 
cat filename

[me@linuxbox ~]$ cat

The quick brown fox jumped over the lazy dog.
[me@linuxbox ~]$ cat > lazy_dog.txt
The quick brown fox jumped over the lazy dog.
[me@linuxbox ~]$ cat < lazy_dog.txt

“Because wildcards always expand in sorted order, the arguments will be arranged in the correct order.” “If cat is not given any arguments, it reads from standard input …” Type ctrl-D to signal end of file (EOF).

  • cat 文件...: 把一个或多个文件依次输出到 stdout, 不分页; 多个文件就是「拼接」 (concatenate). 拼接分块文件时可以放心用通配符, 因为通配符展开结果是排好序的, .001 在 .002 前面.
  • 不给参数时, cat 读 stdin (键盘), 所以看起来「卡住了」——它在等你输入. 按 Ctrl-D 表示输入结束 (EOF).
  • cat > 文件: 键盘输入直接写进文件, 「世界上最简陋的文字处理器」.
  • < 文件: 把 stdin 从键盘改成文件. cat < f 和 cat f 结果一样, 但原理不同: 前者是 shell 打开文件交给 cat, 后者是 cat 自己打开.

Pipelines

> 和 | 的区别
The Difference Between > and |

S. 56 
command1 > file1
command1 | command2
# cd /usr/bin
# ls > less

“… the redirection operator connects a command with a file, while the pipeline operator connects the output of one command with the input of a second command.” “… the redirection operator silently creates or overwrites files …”

命令作用要点
sort按行排序两个目录的两份有序列表合成一份
uniq去掉相邻的重复行输入必须先排序; -d 只显示重复的行

wc ls-output.txt 的 503634 字节, 正好是前面追加三次后 ls -l 显示的大小, 前后一致.

管道的思路: 每个工具只做一件小事, 用 | 串起来解决大问题. 「两个目录里有多少个不重复的程序」= 列出 → 排序 → 去重 → 数行.

EIP 的 Python 部分也会用到这三条通道: print() 写 stdout, 错误信息写 stderr, input() 和 sys.stdin 读 stdin. 所以 python3 prog.py < eingabe.txt > ausgabe.txt 不改代码就能让程序读写文件.

第 7 章 · 以 shell 的眼光看世界: 展开与引号
7 Seeing the World as the Shell Sees It

S. 61–62

“Each time we type a command and press the enter key, bash performs several substitutions upon the text before it carries out our command … The process that makes this happen is called expansion.”

[me@linuxbox ~]$ echo this is a test
this is a test
[me@linuxbox ~]$ echo *
Desktop Documents ls-output.txt Music Pictures Public Templates Videos

“… the echo command never saw the *, only its expanded result.”

本章是第 1 部分的核心. 按下回车后、命令真正运行之前, bash 先把这一行文字改写一遍, 这叫展开 (expansion). echo 只是把收到的参数原样打印出来, 所以它是观察展开结果的最好工具.

echo * 没有打印星号: shell 先把 * 换成了当前目录的文件名列表, echo 收到的是这些文件名, 根本没见过 *. 第 4 章的通配符原来是 shell 的功能.

路径名展开
Pathname Expansion

S. 62–63 
[me@linuxbox ~]$ echo D*
Desktop Documents
[me@linuxbox ~]$ echo *s
Documents Pictures Templates Videos
[me@linuxbox ~]$ echo [[:upper:]]*
Desktop Documents Music Pictures Public Templates Videos
[me@linuxbox ~]$ echo /usr/*/share
/usr/kerberos/share /usr/local/share

Hidden files: echo * does not reveal hidden files; echo .* also includes . and ... Better: echo .[!.]* (still misses names with multiple leading periods). ls -A provides a correct listing.

  • 通配符的工作机制叫路径名展开. 模式可以出现在路径的任何一段: /usr/*/share 匹配「/usr 下任意一个子目录里的 share」.
  • * 不匹配以点开头的隐藏文件. .* 会把 . 和 .. 也带上 (对 rm -r .* 这种命令很危险). .[!.]* = 「一个点 + 一个非点字符 + 任意」, 排除了 . 和 ...

没有匹配时会怎样: bash 把模式原样传给命令 (本机实测 echo zzznomatch* 打印 zzznomatch*), zsh 则直接报错 no matches found, 命令不执行. 这是 Mac 终端和 CIP 上结果不同的常见原因之一.

算术展开
Arithmetic Expansion

S. 64–65 
$((expression))

[me@linuxbox ~]$ echo $(($((5**2)) * 3))
75
[me@linuxbox ~]$ echo $(((5**2) * 3))

[me@linuxbox ~]$ echo Five divided by two equals $((5/2))

Operators: + - * / (integer division) % (modulo, “remainder”) ** (exponentiation). “Arithmetic expansion supports only integers.” “Spaces are not significant in arithmetic expressions, and expressions may be nested.”

$((…)) 里做整数运算: 5/2 得 2 (小数部分直接丢掉), 5%2 得余数 1, 5**2 是 5 的平方. 可以嵌套, 也可以用单层括号分组, 两种写法都得 75 (全部已实测). 括号里的空格无所谓.

对照 Python: bash 的 / 相当于 Python 的 // (对正数而言), ** 和 % 写法相同.

花括号展开
Brace Expansion

S. 65–66 
[me@linuxbox ~]$ echo Front-{A,B,C}-Back
Front-A-Back Front-B-Back Front-C-Back
[me@linuxbox ~]$ echo Number_{1..5}
Number_1 Number_2 Number_3 Number_4 Number_5
[me@linuxbox ~]$ echo {01..15}
01 02 03 04 05 06 07 08 09 10 11 12 13 14 15
[me@linuxbox ~]$ echo {Z..A}
Z Y X W V U T S R Q P O N M L K J I H G F E D C B A
[me@linuxbox ~]$ echo a{A{1,2},B{3,4}}b
aA1b aA2b aB3b aB4b
[me@linuxbox Photos]$ mkdir {2007..2009}-{01..12}

A pattern may have a leading preamble and a trailing postscript; the brace expression contains a comma-separated list or a range of integers or single characters. “The pattern may not contain unquoted whitespace.” Zero-padding requires bash 4.0 or newer.

  • 花括号展开按模式生成字符串: 前缀 (preamble) + 括号里的每一项 + 后缀 (postscript).
  • 括号里可以是逗号列表 {A,B,C}, 也可以是范围 {1..5}、{Z..A} (可以倒序), 还可以嵌套.
  • 括号里不能有未加引号的空格, 否则不展开.
  • 典型用途: 批量建目录. {2007..2009}-{01..12} 两组相乘, 生成 3 × 12 = 36 个 年-月 目录, 按名字排序正好是时间顺序 (已实测 36 个).

和路径名展开的区别: 通配符只匹配已经存在的文件; 花括号不管文件存不存在, 只是生成文字, 所以能用来「造」新名字.

补零写法 {01..15} 需要 bash 4+. macOS 自带的 bash 3.2 会输出 1 2 3 … (本机实测), zsh 和 CIP 上的 bash 会补零.

[me@linuxbox ~]$ printenv | less

[me@linuxbox ~]$

“… if you misspell the name of a variable, the expansion will still take place but will result in an empty string.”

易错点: 变量名拼错 ($SUER) 不会报错, 只会变成空字符串. 其他展开写错时会原样留下, 便于发现; 参数展开写错却悄无声息, 是脚本 bug 的常见来源.

$(命令) 先运行里面的命令, 再用它的输出替换这一段. ls -l $(which cp): 先问出 cp 的完整路径, 再对这个路径 ls -l, 不用自己记路径. 里面可以是一整条管道.

引号: 控制展开
Quoting

S. 67–68 
[me@linuxbox ~]$ echo this is a     test
this is a test
[me@linuxbox ~]$ echo The total is $100.00
The total is 00.00

“In the first example, word splitting by the shell removed extra whitespace … In the second example, parameter expansion substituted an empty string for the value of $1 because it was an undefined variable.”

展开有时会帮倒忙:

  • 多个空格被压成一个: shell 先按空白把一行切成一个个「词」 (分词, word splitting), 空白只是分隔符, echo 收到 4 个参数, 再用单个空格连起来打印.
  • $100.00 里的 $1 被当成变量 (第 1 个位置参数), 它是空的, 所以只剩 00.00 (已实测).

引号 (quoting) 就是用来有选择地关掉展开的.

双引号

“If we place text inside double quotes, all the special characters used by the shell lose their special meaning … The exceptions are $ (dollar sign), \ (backslash), and ` (backtick). This means that word splitting, pathname expansion, tilde expansion, and brace expansion are suppressed; however, parameter expansion, arithmetic expansion, and command substitution are still carried out.”

[me@linuxbox ~]$ ls -l two words.txt

umask 是一张「要去掉哪些位」的掩码, 不是「要给哪些位」. 新建普通文件的起点是 rw-rw-rw- (666), 掩码里为 1 的位被清掉:

  • 0002: 去掉「其他人的写」→ rw-rw-r-- (664);
  • 0022: 去掉「属组和其他人的写」→ rw-r--r-- (644), 这是另一种常见默认值;

这就是为什么 umask 写成四位: 最前面一位管特殊权限.

  • sticky (1000, 其他人的 x 位显示成 t): 设在目录上时, 人人可写, 但只能删自己的文件. /tmp 就是这样 (用 ls -ld /tmp 看).

这个例子把整章串了起来. 目标: bill 和 karen 共用一个音乐目录, 互相能改对方建的文件和子目录.

  1. 建组 music, 把两人加进去 (书里用图形工具).
  2. sudo mkdir: /usr/local/share 在家目录之外, 普通用户没有写权限, 需要超级用户. 新目录属于 root, 权限 755.
  3. chown :music 只改属组; chmod 775 让组成员也能写. 现在两人都能在里面建文件, 其他人只能看.
  4. 还剩两个问题: (a) umask 是 0022, 新文件 rw-r--r--, 组员改不了别人的文件 → 两人都改用 umask 0002; (b) 新文件的属组是创建者的主组 bill, 不是 music → 给目录加 setgid (g+s), 之后新建的东西自动属于 music.
  5. 结果: test_file 是 -rw-rw-r-- bill music, test_dir 是 drwxrwsr-x bill music, 子目录也继承了 setgid.

umask 的设置只在当前会话有效, 要永久生效需要写进启动文件 (第 11 章).

Modern operating systems “create the illusion of doing more than one thing at once by rapidly switching from one executing program to another. The kernel manages this through the use of processes.”

多任务是一种错觉: CPU 在各个程序之间飞快切换. 内核用进程来组织这些「排队等 CPU 的程序」. 程序是磁盘上的文件, 进程是这个程序正在运行的一次: 同一个程序运行两次就是两个进程.

进程如何工作
How a Process Works

S. 100

At startup the kernel launches a program called init, which runs init scripts that start the system services, many implemented as daemon programs — “programs that just sit in the background and do their thing without having any user interface.” A program can launch other programs: a parent process produces a child process. Each process has a process ID (PID); “init always getting PID 1.” Processes also have owners and user IDs.

  • 开机时内核启动 init (PID 1), init 再启动各种系统服务, 它们多是没有界面、在后台运行的守护进程 (daemon).
  • 进程启动进程: 父进程产生子进程. 你在 shell 里运行 ls, bash 就是 ls 的父进程.
  • 每个进程有编号 PID, 按递增顺序分配; 和文件一样, 进程也有属主 (第 9 章).

今天大多数发行版的 PID 1 是 systemd, 它取代了传统 init 和 init 脚本 (服务用 systemctl 管理). 「PID 1 是第一个用户态进程、所有进程的祖先」这一点不变. 在 CIP 上可以用 ps -p 1 看看.

ctrl-C interrupts a program — “we are politely asking the program to terminate.” Follow a command with & to place it in the background; the shell reports the job number and PID (job control). “A process in the background is immune from terminal keyboard input, including any attempt to interrupt it with ctrl-C.” fg %1: return to the foreground (%1 = jobspec; optional with only one job). ctrl-Z stops a foreground process; bg resumes it in the background.

  • 普通地运行一个程序, 它在前台: shell 等它结束才给你新的提示符. Ctrl-C 中断它.

信号是操作系统和进程之间的一种通信方式. kill 的名字有误导性: 它发送信号, 多数信号的默认效果才是结束进程.

  • 信号可以写编号、名字或带 SIG 前缀的名字: kill -1 = kill -HUP = kill -SIGHUP. 目标可以写 PID, 也可以写作业号 %1.
  • 先礼后兵: 先用默认的 TERM (15), 程序有机会保存工作、清理现场; 只有它不理睬时才用 KILL (9), 那是内核直接强制结束.
  • INT = Ctrl-C, TSTP = Ctrl-Z; STOP 和 KILL 都不能被程序忽略. fg、bg 让暂停的进程继续, 靠的是 CONT.
  • 只能给自己的进程发信号 (root 除外) ——第 9 章的权限思想同样适用于进程.

本机核对: 被 TERM 结束的进程退出状态是 143 = 128 + 15, 正好是「被 15 号信号结束」.

信号编号因系统而异, 名字是通用的. 书里的编号是 Linux (x86) 上的; macOS 上 kill -l 显示 STOP = 17、TSTP = 18、CONT = 19 (本机实测). 所以写命令时用名字 (kill -TERM、kill -KILL) 最稳妥; 1、2、9、15 这几个常用的在各系统上相同.
