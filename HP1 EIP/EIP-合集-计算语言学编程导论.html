汇编与机器语言
Assembler & Maschinensprache

S. 6

Programm in Maschinensprache

  • Zahlenfolge im Speicher B8 05 00 00 00 83 C0 03 (hexadezimal)
  • kann direkt vom Prozessor ausgeführt werden
  • Jede Prozessorenfamilie verwendet ihre eigene Maschinensprache.
  • Beispielsprachen: 32 Bit: Intel x86, ARMv7 · 64 Bit: AMD x86-64, ARMv8

Assembler-Programm

  • Folge von Befehlen mit Argumenten MOV EAX, 5 ADD EAX, 3
  • Assembler-Code ist viel lesbarer als Maschinencode und wird 1:1 in Maschinencode übersetzt: B8 05 00 00 00 83 C0 03

机器语言程序就是内存中的一串数字 (这里用十六进制写), 处理器可以直接执行. 每个处理器家族有自己的机器语言: Intel/AMD 的 x86 和手机常用的 ARM 互不相通.

汇编程序是「指令 + 参数」的序列, 和机器码一一对应翻译:

汇编机器码意思
MOV EAX, 5B8 05 00 00 00把 5 放进寄存器 EAX (B8 = 「MOV 到 EAX」, 后 4 字节是数 5, 低位在前)
ADD EAX, 383 C0 03EAX 加 3, 结果 8

寄存器是 CPU 内部极快的小存储单元. 汇编比机器码好读得多, 但每条指令仍然只做极小的一步.

编译型语言
Compilersprachen

S. 7
  • verwenden komplexe Befehle wie printf("Hello world\n")
  • Der Code wird von einem Compiler in Maschinencode übersetzt.
  • keine 1:1-Übersetzung
  • Beispielsprachen: C, C++, C#, Rust

Vor- und Nachteile

  • + Die Verarbeitung ist sehr schnell.
  • + Syntaxfehler werden bereits beim Kompilieren erkannt.
  • + Der Quellcode des Programmes muss nicht an Anwender weitergegeben werden.
  • − Der kompilierte Code läuft nur auf Rechnern mit bestimmten Prozessoren und Betriebssystemen.
  • − Programmfehler führen zu unkontrollierten Programmabstürzen.
  • − Die Fehlersuche ist schwieriger.

解释型语言
Interpreter-Sprachen

S. 8
  • Der Programmcode wird nicht in Maschinencode kompiliert sondern direkt von einem Interpreter-Programm verarbeitet.
  • Beispielsprachen: Python, Java, PHP, Ruby
  • Der Interpreter simuliert einen Computer, der bspw. Python ausführen kann.

Vor- und Nachteile (komplementär zu Compilersprachen)

  • + Plattform-Unabhängigkeit: Der Code läuft auf allen Rechnern, auf denen ein Interpreter installiert ist.
  • + Programmfehler werden vom Interpreter abgefangen, der eine informative Fehlermeldung ausgibt.
  • − Der Interpreter braucht viel Speicherplatz.
  • − Die Verarbeitung ist langsamer.
  • − Syntaxfehler werden nicht sofort erkannt.
  • − Anwender erhalten den Quellcode des Programmes und können ihn einfach modifizieren.

两类语言的优缺点正好互补, 对照着记:

编译型 (C, C++, C#, Rust) 解释型 (Python, Java, PHP, Ruby)
如何执行编译器先把整个程序翻成机器码 (不是 1:1, 一条 printf 会变成很多条机器指令) 解释器程序直接处理源码, 相当于「模拟一台会执行 Python 的计算机」
速度+ 很快− 较慢
语法错误+ 编译时就发现− 运行到那里才发现
源码+ 只发可执行文件, 不必给源码− 用户拿到源码, 可以随意修改
平台− 只能在特定处理器 + 操作系统上运行+ 装了解释器的机器都能跑
出错时− 程序不受控地崩溃, 难调试+ 解释器拦住错误, 给出有信息量的报错
内存− 解释器本身占很多内存

原文笔误: 「Platform-Unabhängigkeit」德语应拼作 Plattform-Unabhängigkeit.

Python 实际怎么运行
Python

S. 9
  • Der Python-Interpreter übersetzt Programme zunächst in Bytecode.
  • Der Bytecode wird dann von der Python Virtual Machine ausgeführt.
  • Python ist also sowohl eine Compilersprache als auch eine Interpretersprache.
  • Um den Bytecode nicht bei jedem Start neu kompilieren zu müssen, wird er in einer Datei mit der Endung .pyc gespeichert.

Python 是两步走:

  1. 先把 .py 源码编译成字节码: 一种介于源码和机器码之间的、与平台无关的中间指令;
  2. 再由 Python 虚拟机 (PVM) 逐条解释执行字节码.

所以 Python 同时是编译型和解释型. 为了不用每次启动都重新编译, 字节码会缓存在 .pyc 文件中 (通常在 __pycache__/ 文件夹里, 被 import 的模块才会生成).

想看字节码长什么样: import dis; dis.dis(lambda x: x + 1) 会列出 LOAD_FAST、BINARY_OP 等指令. Java 也是同样的结构 (.class 字节码 + JVM), 所以幻灯片把 Java 放在解释型一边.

面向对象
Objektorientierung

S. 10
  • Python ist eine strikt objektorientierte Programmiersprache.
  • Alle Python-Daten sind Objekte.
  • Ein Objekt fasst Daten (Attribute) und zugehörige Funktionen (Methoden) zu einer Einheit zusammen.
  • Das Innere von Objekten wird gegenüber dem übrigen Programm abgekapselt, wodurch Programme übersichtlicher werden.

Python 是严格的面向对象语言: 所有数据都是对象, 连 3、'abc'、函数本身都是. 一个对象把数据 (属性 Attribute) 和操作这些数据的函数 (方法 Methode) 打包成一个整体. 例如列表对象既存着元素, 又带着 append、sort 等方法.

对象内部对程序其他部分是封装的: 外部只通过方法使用它, 不必关心内部怎么实现, 程序因此更清晰.

位、数制与编码
Bits und Bytes · Zahlensysteme · Zeichenkodierung

S. 11
  • Computer repräsentieren alle Informationen als Bitfolgen.
  • Ein Bit hat die möglichen Werte True (1) und False (0)
  • 8 Bits werden zu einem Byte zusammengefasst.
  • Ein 64-Bit-Computer fasst 4 Bytes (=64 Bits) zu einem Maschinenwort zusammen.
  • Computer lesen, schreiben und verarbeiten Maschinenwörter immer als Einheit.
  • Ältere Prozessoren verarbeiteten 32 Bit (Intel 80386), 16 Bit (Intel 8086) oder auch nur 8 Bit (Intel 8008) auf einmal.
  • 计算机把所有信息表示为比特序列. 一个比特只有两个值: True(1) / False(0).
  • 8 比特 = 1 字节.
  • 64 位计算机把 64 比特合成一个机器字, 读写和运算都以机器字为单位.
  • 早期处理器一次只处理 32 位 (Intel 80386)、16 位 (8086) 甚至 8 位 (8008).

幻灯片错误: 「Ein 64-Bit-Computer fasst 4 Bytes (=64 Bits)」: 64 比特 = 8 字节 (64 ÷ 8 = 8). 4 字节是 32 位机器字.

Python 中的数
Python-Zahlen · Fließkommazahlen

S. 19

Python kennt folgende Zahlentypen:

  • bool mit den Werten True und False (bzw. 1 und 0)
  • int für ganze Zahlen beliebiger Länge
  • float für Fließkommazahlen mit 64-Bit nach dem IEEE 754-Standard
    Wertebereich: ca. ± 1.79 × 10³⁰⁸ (±1.79e308) · kleinste Zahl größer 0: ca. 5 × 10⁻³²⁴ (5e-324)
  • Underflow: Der Python-Ausdruck 5e-324 / 2 liefert den Wert 0.0
  • Overflow: Der Python-Ausdruck 1e+308 * 2 liefert den Wert inf
S. 20

Beispiel: 1.7976931348623157e+308 = Mantisse 1.7976931348623157 · Exponent e+308

Nach dem IEEE-Standard 754 gilt für 64-Bit-Float:

  • Mantisse 52 Bit (eigentliche Zahl)
  • Exponent 11 Bit (Position des Dezimalpunktes)
  • Vorzeichen 1 Bit
  • bool: True/False, 在算术里等于 1/0 (True + True == 2).
  • int: 整数, 长度不限, 2**1000 也能精确算出 (不同于 C/Java 的 32/64 位整数).
  • float: 浮点数, 64 位, IEEE 754 标准. 范围约 ±1.79 × 10³⁰⁸, 最小正数约 5 × 10⁻³²⁴.
    • 下溢: 比最小正数还小 → 变成 0.0;
    • 上溢: 超过最大值 → 变成 inf.

浮点数的结构 (科学计数法): 尾数 × 基数指数. 64 位分成 1 位符号 + 11 位指数 + 52 位尾数. 尾数决定精度 (约 15–16 位十进制有效数字), 指数决定小数点的位置 (所以叫「浮动的点」).

浮点数内部是二进制, 所以「指数」其实决定的是二进制小数点的位置; 很多十进制小数无法精确表示: 

>>> 0.1 + 0.2
0.30000000000000004
>>> 0.1 + 0.2 == 0.3
False
>>> import math; math.isclose(0.1 + 0.2, 0.3)
True

因此比较浮点数不要用 ==, 用 math.isclose 或判断差的绝对值足够小.

Wie wird der String „Abba“ kodiert? 65 98 98 97

Python 内部把每个字符存成一个数字 (Unicode 码位). 表里可以看出几条规律:

  • 大写字母 A–Z 是 65–90, 小写 a–z 是 97–122, 大小写相差 32;
  • 数字字符 '0'–'9' 是 48–57: 字符 '9' 不等于数 9;
  • ä 是 228, 表情 🙂 是 128578, 都超出了老的 ASCII (0–127) 范围;
  • 还有不可见的控制字符: 空字符 0、制表符 9.

「Abba」: A=65, b=98, b=98, a=97 → 65 98 98 97. 注意 b 是小写, 所以是 98 不是 66. 用 Python 验证: [ord(c) for c in 'Abba'].

下面按 Herdr 和 Neovim 的默认键. Ctrl 在德语键盘上是 STRG.

写、保存、运行、看报错都留在同一个窗口里. 程序就是一份纯文本. Neovim 里保存之后, 左边的 python 跑到的才是新的一版. 交出去的也是这份 .py.

三样先装好. Ghostty 从 ghostty.org 安装, Herdr 从 herdr.dev 安装. Neovim 装好之后, 终端里输入 nvim 能打开即可. 打开 Ghostty, 输入 herdr 再回车. 已经在 Herdr 里, 就不用再输入一次.

练习目录只建一次. mkdir -p ~/eip 建出目录, cd ~/eip 进去, python3 -m venv .venv 造出这个目录自己的 Python, 再 source .venv/bin/activate. 行首出现 (.venv) 再往下做. 换一个新项目时, 为那个目录再单独建一次 .venv.

每天打开 Ghostty, 进入 Herdr, cd ~/eip, 再 source .venv/bin/activate. 每个新开的终端都要 source 一次. .venv 不用重建.

按 Ctrl+B, 松开, 再按 V, 右边多出一块. 左边留着运行. Ctrl+B 然后 H 移到左边, L 移到右边. 新的一块如果还在家目录, 先 cd ~/eip, 再输入 nvim hello.py.

Neovim 打开后处于普通状态, 按字母不会把字写进文件. 先按 i 才能打字. 写完按 Esc, 输入 :w 再回车. 回到左边, 输入 python hello.py. 没按 :w, 跑出来的还是磁盘上的旧文件.

报错从 Traceback 往下看. 最后一行是错误种类, 它上面一行是文件名和行号. 回到 Neovim, 在普通状态输入 :行号 跳到那一行, 改完再 :w, 再运行. :q 退出 Neovim. 关掉 Ghostty 窗口后, 已经 :w 保存过的文件还在, 下次打开继续改.

⇒ Objekte werden bei der Zuweisung zu einer Variablen nicht kopiert!

这是本章最重要、最容易出错的一页. 逐段看:

  1. 列表可修改: liste[0] = liste[0] / 2 把第 0 个元素换成 0.5 (/ 得 float). liste[0:2] = [1,2] 给切片赋值, 一次替换多个元素.
  2. liste2 = liste 不复制列表, 只是让 liste2 也指向同一个列表对象 (两个名字, 一个对象, 叫「别名」). 所以 liste2[1] = 7 之后, 通过 liste 看到的也是 7; 反过来 liste[0] = 5 后 liste2 也变了.
  3. 要真正复制: liste2 = liste[:] (全切片) 或 liste2 = list(liste) (或 liste.copy()). 复制后两者独立: 改 liste 不影响 liste2, 反之亦然.
  4. liste[::2] = [0,0,0]: 给带步长的切片赋值, 下标 0、2、4 被替换. 此时右边元素个数必须与切片长度完全相等 (这里都是 3), 否则 ValueError. 
liste2 = liste          liste2 = liste[:]
liste ──┐               liste  ──▶ [1, 2, 4, 8, 16]
        ├─▶ [1,2,4,8,16]
liste2 ─┘               liste2 ──▶ [1, 2, 4, 8, 16]   （另一个对象）

用 liste2 is liste 可以检查两个名字是否指向同一对象.

幻灯片排版问题: 原页第一行 liste = [1,2,4,8,16] 下面紧跟着印了 [1, 7, 4, 8, 16], 这是动画叠加留下的后面步骤的输出, 不是这一句的结果 (赋值语句本身不输出任何东西). 上面已按正确顺序整理.

幻灯片错误: liste2 = list(liste) 复制得到 [1, 2, 4, 8, 16], liste2[0] = 9 改的是下标 0, 所以结果是 [[1, 2, 4, 8, 16], [9, 2, 4, 8, 16]]. 幻灯片印成 [1, 9, 4, 8, 16] (像是改了下标 1). 上面已按实际运行结果改正.

[:]、list()、copy() 都是浅拷贝: 只复制最外层. 若元素本身是列表, 内层列表仍被共享: a = [[1], [2]]; b = a[:]; b[0].append(9) 之后 a 也变成 [[1, 9], [2]]. 需要完全独立时用 import copy; copy.deepcopy(a).

Globale Variablen sollten vermieden werden. Sie machen den Code unübersichtlicher.

核心规则: 在函数里给某个变量赋值, 它就是局部变量, 只在函数内部存在; 只读取而不赋值, 就使用全局变量.

  1. 例 1: 函数里 z = x + y 是赋值 → 这个 z 是局部的, 和外面的 z 是两个不同的变量. add(3, 3) 返回 6, 外面的 z 仍是 3 → 输出 6 3.
  2. 例 2: plus_z 里只读 z, 没赋值 → 用全局 z. 注意函数定义时 z 还不存在也没关系, 调用时 (z = 3 之后) 能找到就行 → 2 + 3 = 5.
  3. 例 3: global z 声明函数里的 z 就是全局 z, 于是赋值会修改外面的 z → 输出 6 6.

建议避免全局变量: 函数应当通过参数拿数据、通过 return 交回结果, 这样每个函数可以单独理解和测试.

一个经典陷阱: 函数里先读后赋值同一个名字会报错. def f(): print(z); z = 1 调用时报 UnboundLocalError, 因为 z 在函数里被赋值了, 整个函数里它都算局部变量, 读取时还没有值.

贪婪 vs. 非贪婪:

  • ^ 默认只表示整个字符串的开头 → 只有 'C'. re.M (MULTILINE) 让 ^ 和 $ 匹配每一行的开头和结尾 → C、L、D.

>>> re.match(r'(?:.+)(def)', 'abcdef').groups()

Lookbehind

>>> re.match(r'(.+)(?<=bc)(.+)', 'abcdef').group(0,1,2)

>>> re.match(r'(...+?)(?<!bc)(.+)', 'abcdef').group(0,1,2)

Lookahead

>>> re.match(r'(.+?)(?=de)(.+)', 'abcdef').group(0,1,2)

>>> re.match(r'(.+?)(?!de)(...+)', 'abcdef').group(0,1,2)

写法名称含义
(?:…)非捕获组只用于分组 (如配合 +), 不产生编号的组
(?=…)正向先行断言当前位置后面必须是 …
(?!…)负向先行断言当前位置后面不能是 …
(?<=…)正向后行断言当前位置前面必须是 …
(?<!…)负向后行断言当前位置前面不能是 …

断言 (lookaround) 只检查条件, 不消耗字符 (宽度为 0), 所以检查过的字符仍可以被后面的部分匹配.

  • (.+)(?<=bc)(.+): 在「前面是 bc」的位置切开, 即 abc | def.
  • (...+?)(?<!bc)(.+): 第 1 组至少 3 个字符且尽量少; 位置 3 前面是 'bc' 被排除, 于是延到位置 4 → abcd | ef.
  • (.+?)(?=de)(.+): 在「后面是 de」的位置切开 → abc | def.
  • (.+?)(?!de)(...+): 第 1 组尽量少, 位置 1 后面是 'bc' 不是 'de', 立刻满足 → a | bcdef.

Ein Decorator ändert das Verhalten einer Funktion, ohne den Code zu verändern.

# test.py
def changecase(func):
   ''' schreibt den Ausgabetext von func in Großbuchstaben '''
   def newfunc(*args, **kwargs):
      result = func(*args, **kwargs)
      return result.upper()
   return newfunc

@changecase
def myfunction():
   return 'Hello World!'

print(myfunction())
> python test.py
HELLO WORLD!

装饰器: 一个「接收函数、返回新函数」的函数, 用来在不改动原函数代码的情况下改变它的行为.

  • @changecase 写在 def 上方, 等价于定义之后执行 myfunction = changecase(myfunction).
  • changecase 内部定义了新函数 newfunc: 先调用原函数 func, 再把结果转成大写. 返回的是 newfunc, 于是之后调用 myfunction() 实际执行的是 newfunc.
  • *args 收集任意多个位置参数成元组; **kwargs 收集任意多个关键字参数成字典. 调用时 func(*args, **kwargs) 再把它们解包原样传下去, 因此 newfunc 能包装任何参数形式的函数.

# Messwerte mit Rauschen erzeugen

完整流程: 造数据 → 拟合 → 画图:

  1. np.linspace(-5, 5, 20): −5 到 5 之间等距的 20 个点.
  2. 用真实参数 a=0.5、b=−2、c=5 算出 y, 再加上正态分布噪声 np.random.normal(-1, 1, size=20) (均值 −1、标准差 1).
